# 提示词链 — 需求分析

- **Feature ID:** prompt-chaining
- **Version:** 1.0
- **Status:** Proposed（待架构评审）
- **Author:** ui-ux-agent
- **Date:** 2026-10-12

## 1. 竞品调研总结

| 平台 | 链式 / 组合做法 | 关键启示 |
|---|---|---|
| **FlowGPT "Flows"** | 多步提示词链：一个提示词的输出喂给下一个；可视化步骤列表；在 UI 中顺序运行 | 顺序管道是核心心智模型；v1 用可视化步骤列表（而非画布）即可 |
| **AIPRM "Prompt Chains"** | 预定义工作流链（如 调研 → 大纲 → 草稿）；每步是带变量的模板；运行产生合并记录 | 把链打包为可分享的制品（类似模板）创造了第二层可复用内容 |
| **Snack Prompt** | 无链式；带变量的单提示词 | 单提示词平台证明了链所填补的多步工作流空白 |
| **PromptBase** | 无链式；单提示词市场 | 证实链是工作流特性而非市场特性 |
| **Zapier / n8n** | 带映射的节点图；复杂但强大 | 节点图强大但笨重 —— 线性链加可选分支覆盖大多数真实工作流且更易上手 |
| **LangChain（库）** | 代码式链：prompt → parser → prompt；输出变量按名传递 | 按名的输出→输入映射是开发者熟悉的契约；我们以可视化方式镜像它 |
| **ChatGPT "GPTs"（自定义指令）** | 单系统提示词 + 文件；无链式 | 最大的平台也把组合排除在产品外 —— 这是机会，而非要照抄的模式 |

**综合结论：** v1 的制胜模式是**线性链**：链是命名的有序步骤列表，每一步引用一个现有模板（按版本/别名），声明它消费哪些变量，并把前一步的*输出*映射到自己的某个变量。输出由用户声明：每一步把一个变量标记为它的"输出槽"（用户为该变量填写的值即该步的结果）。在类 playground 的运行器中运行链：填第 1 步的输入，产生输出，自动填充第 2 步中被映射的变量，依此类推；用户复制每一步的结果。链是一等内容：默认私有，可像模板和集合一样发布、可 fork，并复用相同的详情页模式。**LLM 执行明确不在范围内** —— 链的运行逐步解析并组装提示词文本；绝不调用模型。这使链式成为现有模板基础设施之上的纯组合层。

## 2. 问题陈述

1. **真实工作流是多步的。** "总结这篇文章 → 提取行动项 → 起草回复"今天是三个模板。用户必须手动把一个生成器的输出复制进下一个生成器的变量 —— 易错且繁琐。
2. **组合知识无处安放。** 发现模板 A 的输出可以接模板 B 的输入的用户，无法保存或分享这个配方。每次会话都从记忆开始。
3. **产品单元太小。** 模板是单条提示词；用户从提示词平台获得的价值越来越多来自*序列*。集合把模板分组但不连接它们。
4. **没有结构化交接。** 变量名是模板间的天然契约（`$$article_text$$` → `$$input_text$$`），但产品中没有任何东西表达"这个输出接到那里"。

## 3. 目标用户

- **高级用户 / 工作流构建者（主要）：** 有重复性多步文本工作流的用户，希望一次编码、永久复用。
- **创作者：** 互补模板的作者，希望发布的不只是模板，还有组合它们的*配方*（自己的和他人的）。
- **普通用户：** 运行已发布链的消费者，无需理解接线即可获得多步结果。
- **管理员：** 在管理控制台把链作为内容进行审核（与模板相同的模式：可见性、下架）—— v1 无链专属管理工具。

## 4. 用户故事

- **US-H1:** 作为高级用户，我希望逐步选择模板来创建链，以便多步工作流被一次编码。
- **US-H2:** 作为高级用户，我希望把每一步的一个变量标记为输出，以便下游步骤知道消费什么。
- **US-H3:** 作为高级用户，我希望把前一步的输出映射到后一步的变量，以便运行链时数据自动流动。
- **US-H4:** 作为高级用户，我希望运行链时只填*未映射*的变量，以便每次运行只需我的原始输入。
- **US-H5:** 作为高级用户，我希望看到每一步解析后的提示词并复制它，以便在自己的工具中使用中间结果。
- **US-H6:** 作为创作者，我希望用稳定 URL 发布链，以便他人运行我的配方。
- **US-H7:** 作为普通用户，我希望不经编辑就能运行已发布的链，以便不理解组合也能受益。
- **US-H8:** 作为用户，我希望 fork 已发布的链为自己的可编辑副本，以便按需改造配方。
- **US-H9:** 作为管理员，我希望链出现在模板审核中并有相同的可见性控制，以便不当链可被取消发布。

## 5. 功能需求

### 5.1 数据模型

- **FR-1:** 新表 `prompt_chains`：`id UUID PK`、`owner_id TEXT NOT NULL`（外键 users）、`name VARCHAR(120) NOT NULL`、`description TEXT`（0–1000 字符）、`visibility VARCHAR(10) NOT NULL DEFAULT 'private' CHECK (visibility IN ('private','public'))`、`created_at`、`updated_at`。索引 `(owner_id)`、`(visibility, updated_at DESC)`。
- **FR-2:** 新表 `prompt_chain_steps`：`id UUID PK`、`chain_id UUID NOT NULL REFERENCES prompt_chains(id) ON DELETE CASCADE`、`position INT NOT NULL`、`template_id UUID NOT NULL REFERENCES templates(id)`、`version_id INT`（可空；空 = 运行时取最新）、`output_variable VARCHAR(50)`（可空；该步声明的输出槽）、`created_at`。唯一 `(chain_id, position)`。删除被引用模板不删除步骤（见 FR-16）。
- **FR-3:** 新表 `prompt_chain_mappings`：`id UUID PK`、`step_id UUID NOT NULL REFERENCES prompt_chain_steps(id) ON DELETE CASCADE`、`variable_name VARCHAR(50) NOT NULL`、`source_step_position INT NOT NULL`（引用同链更早的步骤），唯一 `(step_id, variable_name)`。映射的含义：该步的 `variable_name` 由 `source_step_position` 步骤的输出填充。
- **FR-4:** 限额：每用户最多 20 条链；每链 2–10 步；每步最多 5 个映射。服务端强制执行并返回友好错误。

### 5.2 链构建（普通用户界面）

- **FR-5:** 已登录用户在 `/chains/new`（或创建弹窗）创建链：名称、描述，然后是步骤编辑器。步骤按顺序添加；每步选择模板（可搜索选择器，自己的 + 公开模板），可选固定版本（默认：最新），可选标记输出变量（该模板变量的下拉）。
- **FR-6:** 构建器为每步列出模板的变量；每个变量用户可选择：留作*运行时输入*，或*从前一步输出映射*（已声明输出变量的更早步骤的下拉）。
- **FR-7:** 校验（构建器，客户端 + 服务端）：至少 2 步；位置唯一；映射只引用更早步骤；被映射变量必须存在于该步模板中；步骤的输出变量必须存在于其模板中；循环引用因"仅更早"规则在构造上不可能。
- **FR-8:** 链隐式保存为草稿（私有），可从链详情页发布（可见性公开）—— 与集合相同的模型。

### 5.3 链详情与运行

- **FR-9:** 链详情页 `/chains/{id}` 展示：头部（名称、所有者、可见性徽标、统计）、步骤列表（按序卡片：模板标题、版本/别名、带输入/映射徽标的变量、输出变量徽标）、描述，以及**运行面板**。
- **FR-10:** 运行面板收集运行时输入：仅任何步骤中都未被映射的变量（链的"根输入"）。每个根输入渲染一个 textarea（与生成器相同样式）。一个"运行链"按钮。
- **FR-11:** 运行链在客户端按序解析步骤：对每步，拉取模板版本内容（现有 API），将被映射变量替换为前序步骤输出、根输入替换为用户值，渲染解析后的提示词，并作为该步结果展示且带复制按钮。该步声明的输出变量的*用户可见值*是用户在结果面板中为该变量槽输入/粘贴的文本（见 FR-12）。
- **FR-12:** **输出捕获：** 每步解析后的提示词展示后，运行面板显示该步输出变量名与空 textarea：用户粘贴/输入自己获得的结果（来自其在产品外的模型使用），随后喂给下游被映射的变量。"跳过"选项将输出留空（下游被映射变量收到空字符串）。这使产品保持无 LLM，同时让数据流动具体化。
- **FR-13:** 运行状态仅客户端（v1 不持久化运行）；运行可重置；跳过/空输出之后的步骤仍以空值运行（与生成器的空字符串行为一致）。
- **FR-14:** Fork：任何用户可 fork 公开链（或自己的）为私有副本（新 id、所有者 = fork 者、描述中注明"Forked from {chain}"）。链详情页一键 fork。

### 5.4 发现

- **FR-15:** 公开链出现在 "Chains" 区：`/chains` 浏览页（链卡片网格：名称、步骤数、所有者、更新时间），支持按名称/描述搜索与按最新/最多 fork 排序。链卡片出现在所有者主页（follow-creators 的未来创作者页）—— v1 仅链接。

### 5.5 删除与完整性

- **FR-16:** 删除被链步骤引用的模板不删除该步骤；步骤在构建器与详情页渲染"模板不可用"状态，链在所有者替换或移除该步骤前无法运行。这使链免受模板变动影响。
- **FR-17:** 删除链为软删除（仅所有者，确认弹窗）；fork 副本不受影响。管理员取消发布将可见性设为私有（非删除）。

### 5.6 管理端界面

- **FR-18:** 链作为内容类型筛选（`type=chain`）出现在管理控制台模板审核列表：列 名称、所有者、步骤数、可见性、更新时间；操作：查看（只读详情）、取消发布（可见性 → 私有，原因记入审计日志，与模板审核相同的弹窗）。管理员不编辑链。
- **FR-19:** 管理 API 扩展现有审核端点：`GET /api/v1/admin/chains?query=&visibility=&page=`、`GET /api/v1/admin/chains/{id}`、`POST /api/v1/admin/chains/{id}/unpublish`（body: reason）。审计日志条目使用动作 `chain.unpublish`。

### 5.7 API（普通用户）

- **FR-20:** `POST /api/v1/chains`（创建含步骤+映射）、`GET /api/v1/chains?owner=me|public&query=&sort=&page=`、`GET /api/v1/chains/{id}`（详情含模板摘要的步骤）、`PUT /api/v1/chains/{id}`（整体更新名称/描述/可见性/步骤/映射）、`DELETE /api/v1/chains/{id}`、`POST /api/v1/chains/{id}/fork`。适用处均限定所有者；已发布链可公开读取。

### 5.8 通知集成

- **FR-21:** 若 notifications 功能已上线，有人 fork 公开链时向链所有者发送 `chain_fork` 通知事件（操作者、链名、链接）。若 notifications 未上线，该 FR 延后且不阻塞本功能。

## 6. 非功能需求

- **NFR-1（性能）：** 10 步链的详情 + 运行面板加载 < 1 秒（并行拉取模板版本）；步骤解析在客户端且即时。
- **NFR-2（完整性）：** 所有 FR-7 校验在创建/更新时由服务端强制执行（客户端仅为体验）；引用缺失变量的映射被拒绝并返回字段级错误。
- **NFR-3（限额）：** 服务端强制的限额（FR-4）返回 400 与清晰消息；构建器实时显示限额计数。
- **NFR-4（国际化）：** 所有文案通过 i18next 提供 EN/ZH（`chains.*` 命名空间）；变量名与模板标题是用户内容，绝不翻译。
- **NFR-5（无障碍）：** 步骤列表与运行面板全键盘可操作；步骤顺序与数据流以文字传达（编号步骤、"第 2 步的输出 → 第 3 步的变量 X"），绝不只靠颜色。
- **NFR-6（一致性）：** 链的可见性、发布、fork 与审核完全复用模板与集合的模式（相同徽标、弹窗、审计原因）。

## 7. 验收标准

- **AC-1:** 用户创建 3 步链（每步是带变量的模板），把第 1 步的 `summary` 标记为输出，把第 2 步的 `input_text` ← 第 1 步输出映射，保存；链以私有状态出现在 My Chains。
- **AC-2:** 发布链后其他用户可在 `/chains/{id}` 浏览；浏览页列出它。
- **AC-3:** 运行链只显示根输入（未映射变量）；填完第 1 步输入后，其解析后的提示词带复制按钮渲染，并出现 `summary` 的输出捕获框。
- **AC-4:** 向第 1 步输出框粘贴文本后，第 2 步 `input_text` 的显示自动填充；第 2 步解析后的提示词包含粘贴的文本。
- **AC-5:** 含指向不存在变量的映射的链在保存时被拒绝（400，字段级错误）。
- **AC-6:** 引用已删除模板的链在步骤上显示"模板不可用"且无法运行，直到修复。
- **AC-7:** fork 公开链在 fork 者名下创建私有副本；原件不受影响；副本描述中出现 fork 注记。
- **AC-8:** 管理员可按链筛选审核、查看、并带原因取消发布；动作以 `chain.unpublish` 出现在审计日志；链变为私有。
- **AC-9:** 限额生效：11 步的链被拒绝；第 21 条链被拒绝；均为友好错误。
- **AC-10:** 所有文案 EN/ZH 已翻译；无硬编码文案。
- **AC-11:** 功能中没有任何变现相关内容；功能中没有任何 LLM 执行。

## 8. 不做范围

- **LLM 执行：** 链只解析并组装提示词文本；产品绝不调用模型厂商。输出捕获为手动粘贴（FR-12）。
- 分支/条件逻辑、并行步骤、循环、节点图画布（v1 严格线性）。
- 服务端持久化运行、运行历史、定时运行、分享运行结果。
- 链版本化（链是可变的；模板版本固定已覆盖可复现性）。
- 协同链编辑；整链的嵌入/API 执行（单模板 API 仍是 API 面）。
- 任何形式的变现（支付、定价、购买、收益）—— 本产品永久不做。

## 9. 依赖与假设

- **D-1:** 模板、版本与别名（现有 + template-versioning 功能）提供步骤内容；链按 id 与可选 version id 引用模板。
- **D-2:** collections 功能的可见性/发布模型与 follow-creators 功能的所有者身份块是要镜像的模式（徽标、发布动作、主页链接）。
- **D-3:** 模板详情页的生成器（变量输入、`$$var$$` 替换、复制）被复用为运行面板的步骤渲染器。
- **D-4:** 管理控制台的审核列表 + 原因弹窗 + 审计日志（admin-user-management 功能）自然扩展到链（FR-18/19）。
- **D-5:** notifications 功能的事件机制（若上线）承载 `chain_fork`（FR-21）。
- **D-6:** api-playground 功能的模式（客户端 fetch + 解析）指导运行面板的实现，但不是依赖。

## 10. 给架构师的开放问题

1. **步骤内容快照：** 步骤应默认固定 `version_id`（链可复现，但固定版本被删时链断）还是默认最新（始终当前，但链会静默变化）？推荐：默认最新、允许显式固定 —— 请确认。
2. **映射语义：** "仅更早步骤"（FR-7）作为 v1 数据流规则（无同步或前向引用）是否可接受，使模型保持为无 DAG 的线性管道？
3. **模板删除：** FR-16 保留带悬空模板引用的步骤。后端是否还应阻止对被公开链引用模板的*硬*删除（改为软删除），还是"步骤不可用"状态已足够？
4. **Fork 计数：** `prompt_chains` 是否应携带反规范化的 `fork_count`（类似 `like_count`）以支持最多 fork 排序，还是 v1 规模下 COUNT 查询即可？
5. **API 形态：** 一个 `PUT /chains/{id}` 整体替换步骤+映射（更简单，符合 FR-20）还是细粒度步骤端点 —— 请确认整体替换可接受。
6. **通知：** 确认 `chain_fork` 作为 like/favorite/fork/comment/follow 之外的新事件类型，还是延后到 notifications 事件枚举的 v2。
