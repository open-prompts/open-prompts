# SEO 与落地页改进 — 需求分析

- **功能 ID：** seo-landing
- **版本：** 1.0
- **状态：** 已提案（待架构评审）
- **作者：** ui-ux-agent
- **日期：** 2026-10-12

## 1. 竞品调研总结

| 平台 | SEO / 落地方式 | 关键启示 |
|---|---|---|
| **PromptHero** | SEO 优先：公开提示词页完全服务端渲染，丰富标题（"提示词 + 模型 + 风格"），图片搜索流量 | 公开内容页就是整个获客引擎；标题模式很重要 |
| **FlowGPT** | 公开模板页被索引；分类枢纽页（"Best ChatGPT prompts for X"）瞄准头部关键词 | 瞄准"某用途最佳提示词"的枢纽页是流量最大的模式 |
| **Snack Prompt** | 干净的公开 URL、社交预览卡、趋势页 | Open Graph 卡驱动社交分享点击 |
| **AIPRM** | 带功能分区的落地页 + 独立索引路径上的社区提示词库 | 产品落地和内容库是分开的界面，各有目标 |
| **PromptBase** | 市场落地页带精选提示词；技术 SEO 极少 | 即使市场领导者技术 SEO 也很弱 —— 门槛容易跨越 |
| **Notion（营销站）** | 静态营销页 + 独立应用；按语言区域的落地路径 | 营销页必须静态/快速；应用本身留在认证之后 |

**综合分析：** 产品的公开模板目录是其天然 SEO 资产，但今天它是不可见的：SPA 只输出一个裸的 `<title>Open Prompts</title>`，没有 meta 描述、没有 Open Graph/Twitter 卡、没有按路由的标题、没有结构化数据，也没有可抓取的内容（仅客户端渲染）。v1 策略有三：(1) **按路由的文档头管理**（标题、描述、canonical、OG/Twitter 卡），通过一个轻量 head 管理工具 —— 每个公开模板、分类、标签页都有唯一的、含关键词的标题；(2) **面向爬虫的公开内容页服务端渲染** —— 后端为搜索引擎 UA 返回完整 HTML（或轻量预渲染/SSG 层），认证后的应用路由保持客户端渲染；(3) **正经的落地体验** —— 未登录主页变成营销落地页（英雄区、精选公开模板、分类展示、工作原理），而非空应用外壳。结构化数据（模板页的 `ProfilePage`/`Article` JSON-LD、分类页的 `BreadcrumbList`）补齐技术基线。

## 2. 问题陈述

1. **公开目录对搜索引擎不可见。** 所有页面都是客户端渲染且只有一个静态标题；爬虫看到空外壳，任何模板都无法获得排名。
2. **社交分享看起来是坏的。** 没有 Open Graph/Twitter meta：在聊天/社交中分享的链接只显示裸 URL 或通用标题 —— 浪费传播。
3. **未登录访客走进死胡同。** 匿名用户的主页是一个要求登录上下文的应用外壳，而非展示产品；跳出率高且没有任何叙事（这是什么、为什么加入）。
4. **没有落地叙事。** 产品内部没有任何地方解释产品价值（管理、版本化、分享、使用提示词；API 访问）。

## 3. 目标用户

- **来自搜索/社交的匿名访客：** 落在模板页或落地页；需要即时上下文和进入路径。
- **搜索引擎/社交爬虫：** 需要可抓取、描述良好的公开页面。
- **评估产品的新用户：** 落地页是他们的第一印象。
- **分享链接的既有用户：** 他们的分享应渲染出有吸引力的预览卡。

## 4. 用户故事

- **US-S1：** 作为来自搜索引擎的匿名访客，我落在公开模板页上并立即看到完整内容（服务端渲染），无需下载应用/登录墙即可获得价值。
- **US-S2：** 作为访客，页面标题和描述告诉我这个模板是什么（"Support Reply Prompt — Open Prompts"），一眼就知道自己在哪里。
- **US-S3：** 作为在聊天/社交中分享模板链接的用户，链接展开为带模板名、描述和站点品牌的卡片，让我的分享显得可信。
- **US-S4：** 作为未登录主页的首次访客，我看到解释产品并展示真实精选模板的落地页，在注册之前理解价值。
- **US-S5：** 作为浏览分类的访客，分类和标签页有可抓取的枢纽页（"客服支持提示词"），无需账号即可浏览。
- **US-S6：** 作为多语言访客，公开页面尊重 `?lang=` / Accept-Language 提示来决定渲染语言，让落地页读起来自然。
- **US-S7：** 作为站点所有者/运营者，我获得覆盖公开页面的 `robots.txt` 和 `sitemap.xml`，索引完整且私有页面被排除。
- **US-S8：** 作为屏幕阅读器用户，改进的标题和标题层级（与提供给爬虫的内容相同）也给我更好的页面上下文。

## 5. 功能需求

### 5.1 文档头管理（SPA）

- **FR-1：** 一个 head 管理工具在每个客户端渲染路由（公开和认证）上设置按路由的 `<title>`、`<meta name="description">`、canonical URL 和 Open Graph/Twitter 卡标签：模板详情（"{模板名} — Open Prompts"）、分类、标签、合集、链、团队（公开）、个人资料（公开）、管理端（noindex）、功能页（"API Keys — Open Prompts"）。
- **FR-2：** 仅认证页面（资料设置、API 密钥、通知、管理端）带 `noindex` meta；公开页面可索引。私有/未发布内容绝不出现在任何 meta 标签中。

### 5.2 面向爬虫的服务端渲染

- **FR-3：** 公开模板页（模板为 public 的 `/templates/{id}`）为搜索引擎 UA 动态渲染：后端（或预渲染层）返回完整 HTML —— 标题、meta、JSON-LD、可见内容（名称、描述、分类、标签、提示词预览、点赞数）—— 并带醒目的"在 Open Prompts 中打开"CTA 指向应用路由。
- **FR-4：** 分类和标签枢纽页为爬虫服务端渲染公开模板列表（名称 + 链接 + 描述片段），分页，每页最多 50 个链接。
- **FR-5：** 未登录落地页（`/`）服务端渲染（静态或动态），英雄文案和精选模板可被抓取。
- **FR-6：** 动态渲染对用户和爬虫提供相同 URL（无 cloaking）：爬虫 HTML 是公开数据的忠实渲染；普通浏览器照旧获得 SPA（允许渐进交接）。

### 5.3 落地页（未登录主页）

- **FR-7：** 匿名访客的 `/` 渲染落地页：英雄区（主标题、副标题、主 CTA"开始使用"、次 CTA"浏览提示词"）、精选公开模板网格（6 张卡片，真实数据）、分类展示（前 6 个分类及计数）、"工作原理"（3 步：创建 → 版本/分享 → 通过网页或 API 使用）、带产品链接的页脚。登录用户看到的现有主页仪表盘不变。
- **FR-8：** 落地页完全响应式，遵循 Aurora 设计系统，通过既有 i18n 运行时支持 EN/ZH，并尊重明暗主题。
- **FR-9：** 落地 CTA 深度链接合理："浏览提示词" → 公开模板浏览（匿名的现有主页浏览），"开始使用" → `/register`。

### 5.4 结构化数据与抓取基础设施

- **FR-10：** 服务端渲染模板页上的 JSON-LD：类 `Article` 模式（name、description、datePublished/dateModified、author）和 `BreadcrumbList`（主页 → 分类 → 模板）。分类页带 `BreadcrumbList` 和 `ItemList`。
- **FR-11：** `robots.txt`（允许公开路径；禁止 `/admin`、`/api`、`/profile`、`/api-keys`、`/notifications` 及所有认证路由）和 `sitemap.xml`（公开模板、分类、落地页；≤ 10,000 URL，每日或按需刷新；需要时分页 sitemap 索引）。
- **FR-12：** `og:image` 默认使用站点 logo/品牌卡；模板页使用生成的品牌卡（品牌背景上的模板名）—— v1 不做每模板 AI 图片。

### 5.5 API

- **FR-13：** SPA 无新增公开 API 端点。服务端渲染路径直接消费内部服务（或既有内部端点）。sitemap 生成器通过定时或按需任务读取数据库（公开模板/分类）。

### 5.6 管理端

- **FR-14：** v1 无管理 UI。（sitemap 生成和 SEO 健康是运维事务；审计日志记录的取消发布操作会在下次 sitemap 刷新时移除 URL —— 既有行为。）

## 6. 非功能需求

- **NFR-1（性能）：** 服务端渲染爬虫页响应 < 500 毫秒（p95）且可缓存（短 TTL）；匿名用户的 SPA 落地页加载 < 2 秒（LCP），精选网格从既有公开 API 流式加载。
- **NFR-2（正确性）：** meta 标签始终描述实际可见的公开内容；私有数据绝不出现在提供给爬虫的 HTML 中；未发布模板在 SSR 路径返回 404/410。
- **NFR-3（一致性）：** 爬虫 HTML 和 SPA 渲染相同的公开事实（名称、描述、分类、标签、计数）；不一致即缺陷。
- **NFR-4（国际化）：** 落地和 SSR 页面基于 `?lang=` 优先于 Accept-Language 渲染 EN/ZH；SSR 页面输出 `hreflang` 备选；SPA head 管理工具按 i18n-completeness 设计设置 `<html>` 的 `lang`。
- **NFR-5（无障碍）：** 落地页是普通的可访问页面（landmark、标题层级、焦点顺序）；SSR 页面共享相同的标记语义。
- **NFR-6（构建）：** head 管理工具轻量（无新的重依赖）；SSR/动态渲染与既有 Go 网关（Go 模板渲染）或构建时预渲染集成 —— 由架构师选择（见开放问题）。

## 7. 验收标准

- **AC-1：** 每个 SPA 路由设置唯一标题和描述；导航时更新；管理/认证页带 noindex。
- **AC-2：** 用搜索引擎 UA 抓取公开模板 URL 返回完整 HTML，含标题、描述、OG/Twitter 标签、JSON-LD 和可见模板内容。
- **AC-3：** 以爬虫身份抓取私有/未发布模板 URL 返回 404；meta 和正文不泄露其内容。
- **AC-4：** 在社交/聊天客户端中分享公开模板链接展开为带名称、描述和品牌图片的卡片。
- **AC-5：** 匿名 `/` 显示落地页（英雄区、6 个精选模板、分类、工作原理）；登录 `/` 不变。
- **AC-6：** 分类枢纽页渲染可抓取的公开模板列表并分页（≤ 50 链接/页）。
- **AC-7：** `/robots.txt` 禁止认证/管理路径；`/sitemap.xml` 列出公开模板、分类和落地页；未发布模板在下次刷新后从 sitemap 消失。
- **AC-8：** SSR 页面输出 EN/ZH 的 `hreflang` 备选并尊重 `?lang=`。
- **AC-9：** 落地页在 EN 和 ZH、明暗主题、桌面和移动宽度下正确渲染。
- **AC-10：** 落地页和示例模板页（爬虫视图）的 Lighthouse SEO 类别 ≥ 95。
- **AC-11：** 所有新文案通过 i18next（`landing.*`、`seo.*` 命名空间）EN/ZH 翻译。
- **AC-12：** 任何地方都没有变现内容（无定价区块、无套餐对比、无升级 CTA）。

## 8. 范围之外

- 博客/内容营销系统。
- 落地页变体的 A/B 测试。
- 按语言的 URL 路径（`/zh/...`）—— v1 使用 `?lang=` + hreflang（基于路径的语言区域是未来的 i18n 决策）。
- AI 生成的每模板预览图。
- 管理控制台中的分析/SEO 仪表盘。
- 链接建设、广告或任何增长营销运营。
- 任何形式的变现（定价页、套餐层级、升级流程）—— 本产品永久排除。

## 9. 依赖与假设

- **D-1：** 匿名用户的公开模板浏览已存在（或可轻易启用）—— 落地页的"浏览提示词"和精选网格依赖公开模板读取。
- **D-2：** Go 网关可以为 SSR 路径渲染 HTML 模板（标准 `html/template`），无需新的运行时依赖。
- **D-3：** i18n-completeness 设计的 `<html lang>` 同步适用；本功能在 SSR 页面上增加 `hreflang`。
- **D-4：** 模板分类和标签是稳定的标识符，可用于枢纽 URL（`/categories/{slug}` 样式或既有路由）。
- **D-5：** 既有的点赞/收藏计数和模板元数据可通过内部服务调用供 SSR 层使用。
- **D-6：** 存在定时任务机制（或带缓存 TTL 的按需生成）用于 sitemap 刷新；取消发布/审计操作已存在。

## 10. 给架构师的开放问题

1. **动态渲染 vs 预渲染服务 vs Go SSR：** 建议：网关中用 Go `html/template` 为爬虫 UA 做 SSR（无新服务、完全可控、可缓存）。备选：prerender.io 式服务（新依赖）或构建时 SSG（对每模板页会过期）。哪个最适合部署？
2. **爬虫检测：** UA 嗅探（Googlebot/Bingbot 列表）vs 独立的 `?_escaped_fragment_=` 约定 vs 公开页对所有首跳都 SSR？建议：维护列表的 UA 嗅探，同 URL（内容一致故无 cloaking 风险）。
3. **公开模板页是否对所有首次访问（含用户）SSR 并水合**，让 SPA 成为渐进增强？改动更大；Core Web Vitals 更好；建议：v1 仅爬虫。
4. **sitemap 生成：** 定时任务（Go 服务器内 cron？外部？）vs 带缓存 TTL 的按需生成；放在哪里（网关路由 `/sitemap.xml` 直接读库）？
5. **分类枢纽 URL：** 新的干净路由（`/c/{category-slug}`）vs 复用现有主页过滤查询参数（查询参数对 SEO 很弱）—— 建议：为分类和标签新增干净路由。
6. **og:image 生成：** 静态品牌卡 vs 每模板动态图片（请求时在品牌背景上渲染模板名，缓存）—— 建议：v1 静态品牌卡，后续再做动态。
7. **落地精选模板：** 人工精选（管理员挑选，需要小型管理机制）vs 自动（按点赞数取顶，周窗口）—— 建议：v1 自动按点赞取顶，无管理 UI。
