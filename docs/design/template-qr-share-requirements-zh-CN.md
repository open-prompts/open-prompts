# 模板二维码分享（Template QR Share）— 需求分析

- **Feature ID:** template-qr-share
- **Version:** 1.0
- **Status:** Proposed（待架构评审）
- **Author:** ui-ux-agent
- **Date:** 2026-10-12

## 1. 竞品研究摘要

| 平台 | 二维码/分享模式 | 关键启示 |
|---|---|---|
| **GitHub（仓库分享）** | 分享下拉："分享到 X/LinkedIn/Reddit" 链接 + "复制链接" clone URL；无二维码 | 复制链接是普适基线；社交目标只是深链 —— 无需任何 API |
| **YouTube（分享面板）** | 分享弹窗：社交按钮 + "复制" + **二维码标签页**（客户端生成，可下载 PNG）；时间戳复选框 | 二维码是*分享弹窗内的一个标签页*，而非独立界面；下载为 PNG 是预期操作；二维码打通"我在桌面 → 朋友在手机" |
| **Spotify（分享）** | 每个实体（曲目/专辑/歌单）在移动端都有 分享 → 二维码 选项；二维码编码规范的短 URL | 二维码在移动优先的消费场景中价值最大；编码*规范的短 URL* 让二维码密度保持低位（高密度二维码扫描效果差） |
| **微信 / 小红书** | 二维码是主要的跨设备分享机制（长按识别）；每个个人主页/内容页都暴露二维码 | 在中国市场，二维码不是增强功能 —— 它*就是*分享渠道；ZH 优先的产品把二维码视为基本盘 |
| **Notion（分享菜单）** | 一个弹出层里 复制链接 + "发布到 web" 开关；无二维码 | 在没有二维码的情况下，复制链接 + 移动端原生 Web Share API 覆盖了大多数场景 |
| **Stripe（文档/面板链接）** | 到处都是"复制"按钮，带自愈式 tooltip；Stripe 移动端对支付链接提供二维码 | 复制交互必须是一键完成且有清晰反馈；二维码只出现在"手机接力"是真实任务的场景 |

**综合结论：** Open Prompts 目前**完全没有分享交互** —— 模板详情页的"Share"按钮实际上是*可见性开关*（它通过 `UpdateTemplate` 把模板设为公开），既没有复制链接、没有社交分享，也没有任何二维码。获胜的 v1 模式是 **YouTube/Spotify 分享弹窗**：模板详情页上统一的**分享弹窗**，包含 (1) **复制链接**（一键、自愈式 tooltip、公开模板可用），(2) **二维码标签页** —— **客户端**生成（无后端），编码规范模板 URL，可下载 PNG、可复制到剪贴板，(3) **社交分享目标**（X、Reddit、LinkedIn、Telegram —— 纯深链，无 SDK），(4) 移动端在可用时调用**原生 Web Share API**（`navigator.share`）。二维码是 ZH 市场（微信扫码）与桌面→手机接力的核心。私有模板的弹窗显示"链接仅对你有效"状态（复制/二维码仍可用 —— 该 URL 是所有者的私有链接；无权限的查看者会命中既有的 403 页）。

## 2. 问题陈述

1. **无法分享模板链接。** 模板详情页的"Share"按钮改变可见性（公开/私有）—— 它不分享。想把模板发给同事的用户只能手动复制浏览器地址栏 URL；没有复制链接按钮、没有分享面板、没有社交目标。
2. **跨设备接力不可能。** 在桌面浏览、想在自己手机（真正用 AI 应用的地方）打开模板的用户没有任何机制。二维码是标准桥梁，对 ZH 市场（微信扫码文化）更是基本盘。
3. **发现闭环动力不足。** 模板靠口口相传传播；每一个没有发生的分享都是一个流失的访客。社交分享目标零成本（深链）却不存在。
4. **"Share"一词名不副实。** 标着"Share"的按钮把模板变成公开 —— 一个带暴露性质的破坏性动作伪装成分发动作。用户很可能点了它 expecting 拿到链接，结果却改变了模板的可见性。

## 3. 目标用户

- **创作者（主要）：** 想分发自己模板 —— 给同事、社区、社交信息流 —— 并扩大受众的用户。
- **桌面浏览者（主要）：** 在桌面找到模板、想在自己手机（AI 应用所在）继续使用的用户；二维码是最快的桥梁。
- **ZH 市场用户（主要）：** 微信扫码是默认分享机制的用户。
- **所有用户（次要）：** 任何曾经只想复制一条干净模板链接的人。

## 4. 用户故事

- **US-Q1:** 作为创作者，我希望 Share 按钮给我模板的链接，让我分发模板而不改变其可见性。
- **US-Q2:** 作为桌面用户，我希望有模板 URL 的二维码，让我用手机一扫即可在手机上打开模板。
- **US-Q3:** 作为用户，我希望把二维码下载为 PNG，让我能放进幻灯片、文档或打印。
- **US-Q4:** 作为用户，我希望把二维码图片本身复制到剪贴板，让我直接粘贴到聊天里。
- **US-Q5:** 作为用户，我希望一键复制模板链接，让文字分享毫不费力。
- **US-Q6:** 作为用户，我希望一键分享到 X/Reddit/LinkedIn/Telegram，让模板无需手动粘贴 URL 就能触达社区。
- **US-Q7:** 作为移动端用户，我希望点分享时出现原生分享面板，让手机上的分享体验是原生的。
- **US-Q8:** 作为私有模板的创作者，我希望复制/二维码我的私有链接，让我在自己的设备间流转 —— 同时明白别人打不开它。
- **US-Q9:** 作为用户，我希望二维码保持可扫描（低密度），让它第一次就能被可靠扫出。
- **US-Q10:** 作为 ZH 用户，我希望二维码与分享 UI 完全本地化，让流程在中文里读起来自然。
- **US-Q11:** 作为用户，我希望分享弹窗展示模板标题与预览，让我确信分享的是对的东西。
- **US-Q12:** 作为屏幕阅读器用户，我希望二维码有文本替代（URL），让分享弹窗对我不至于走投无路。

## 5. 功能需求

- **FR-1:** **分享弹窗。** 模板详情页头部（Like/Favorite/Fork 旁）新增"分享"图标按钮，点击打开分享弹窗。展示：模板标题（截断）、可见性徽章、规范 URL、复制按钮、二维码标签页与社交目标。既有的可见性开关按钮**改名**为"设为公开"/"设为私有"（它的真实动作）—— 不再标为"Share"。
- **FR-2:** **规范 URL。** 分享的 URL 是 `{origin}/templates/{template_id}`（既有路由）。v1 不做短链服务；URL 即二维码编码的内容。若模板有公开别名，弹窗额外提供别名解析 URL 作为次要复制选项（`{origin}/t/{alias}` 风格，按别名系统 —— 具体路径见 §10 待架构师确认）。
- **FR-3:** **复制链接。** 一键复制规范 URL，用 `navigator.clipboard.writeText` 并为旧浏览器提供回退（execCommand）；反馈是自愈式"已复制" tooltip/toast；不发生导航。
- **FR-4:** **二维码。** 二维码标签页（桌面默认；移动端若无 Web Share 则为唯一标签页）渲染编码规范 URL 的二维码。**客户端**生成（打包 `qrcode` 等 npm 库）；纠错等级 M；静区 4 模块；512×512 尺寸、256px 显示。无后端参与。
- **FR-5:** **二维码操作。** "下载 PNG"（canvas → blob → `a[download]`，文件名 `openprompts-{标题slug}.png`）与"复制图片"（支持处的 ClipboardItem PNG；不支持处隐藏）。均有成功反馈。
- **FR-6:** **社交目标。** X（`https://twitter.com/intent/tweet?url={url}&text={title}`）、Reddit（`https://reddit.com/submit?url={url}&title={title}`）、LinkedIn（`https://www.linkedin.com/sharing/share-offsite/?url={url}`）、Telegram（`https://t.me/share/url?url={url}&text={title}`）按钮。纯链接新标签打开（`rel="noopener noreferrer"`）；无 SDK、无分享计数。
- **FR-7:** **Web Share API。** 在移动端（或任何存在 `navigator.share` 的设备）上，分享按钮直接调用 `navigator.share({title, text, url})`；API 缺失或分享被取消/中止时回退到弹窗。`navigator.canShare` 把二维码 PNG 的文件分享挡在 v1 之外（v1：仅 URL 分享；二维码文件分享作为延伸记于 §10）。
- **FR-8:** **私有模板。** 弹窗在私有模板上可用，带内联提示："此模板为私有 —— 链接仅对你有效。"复制/二维码均可用（所有者可能想分享到自己的设备或未来设为公开后给查看者）；私有模板隐藏社交目标（给粉丝分享一个 403 是恶意的）。
- **FR-9:** **Embed 交叉链接。** 弹窗包含文字链接"嵌入此模板"，打开既有的嵌入弹窗（template-embedding-widget 设计）—— 一个分发界面从另一个可被发现。
- **FR-10:** **分析（可选）。** 若 analytics 上线：`share_modal_opened`、`link_copied`、`qr_downloaded`、`qr_copied`、`social_share_clicked {target}`。v1 不做服务端分享追踪（无重定向计数）。
- **FR-11:** **可用性。** 分享按钮在每个模板详情页对每个查看者可用（含匿名 —— 分享公开内容不设门槛）。匿名用户获得同样的弹窗（复制/二维码/社交）；无登录墙。
- **FR-12:** **本地化。** 所有弹窗文案、二维码替代文本、下载文件名前缀与改名的可见性按钮 EN/ZH 同日就绪。

## 6. 非功能需求

- **NFR-1:** **零后端改动。** 整个特性纯前端（客户端二维码生成、剪贴板、深链）。无新端点、表或服务。
- **NFR-2:** **性能。** 二维码生成为同步操作，对该长度 URL < 50 ms；库（gzip 后约 30 KB）在首次打开二维码标签页时才懒加载。弹窗即时打开（URL 已知；无请求）。
- **NFR-3:** **隐私。** 不加载任何第三方脚本（社交目标是纯链接；没有回传数据的分享计数组件）。二维码本地生成；URL 绝不离开浏览器，除非用户显式分享。
- **NFR-4:** **无障碍。** 弹窗遵循应用的对话框模式（焦点锁定、Escape、焦点返回）。二维码图片的 `alt` 文本包含 URL；二维码标签页可键盘到达；所有按钮有可辨识文本；颜色对比度 ≥ 4.5:1。
- **NFR-5:** **国际化。** EN/ZH 完整；社交目标名称为专有名词（X、Reddit、LinkedIn、Telegram）不翻译；弹窗布局容纳 ZH 文案长度。
- **NFR-6:** **一致性。** 弹窗复用应用既有 Modal 组件与设计 token；"已复制"反馈与既有复制到剪贴板模式一致（APIKeyManager、SDK 代码片段复制）。

## 7. 验收标准

- **AC-1:** 模板详情页显示分享图标按钮（所有查看者、所有模板）；点击打开含模板标题、可见性徽章与规范 URL 的分享弹窗；旧的"Share"可见性按钮现标为"设为公开"/"设为私有"。
- **AC-2:** 点击复制将 URL 复制到剪贴板并显示"已复制"反馈；粘贴到别处得到精确的 `{origin}/templates/{id}`。
- **AC-3:** 二维码标签页渲染的二维码被手机扫描后打开模板页；二维码有 4 模块静区与纠错等级 M。
- **AC-4:** "下载 PNG"保存 512×512 的 PNG，名为 `openprompts-{slug}.png`；"复制图片"在存在 ClipboardItem API 处把 PNG 复制到剪贴板，不支持处隐藏。
- **AC-5:** 每个社交按钮在新标签打开正确的 intent URL 并预填模板 URL 与标题；存在 `rel="noopener noreferrer"`。
- **AC-6:** 在有 `navigator.share` 的设备上，分享按钮调用带标题+URL 的原生面板；取消不做任何事（无错误）；没有该 API 的设备打开弹窗。
- **AC-7:** 在私有模板上，弹窗显示私有提示、隐藏社交按钮，仍允许复制 + 二维码。
- **AC-8:** "嵌入此模板"链接打开嵌入弹窗（当嵌入特性存在时）。
- **AC-9:** 匿名用户在公开模板上看到并能使用完整分享弹窗，不被提示登录。
- **AC-10:** 二维码库不在主包中（首次打开二维码标签页时懒加载）；弹窗本身打开时零网络请求。
- **AC-11:** 所有文案 EN/ZH 齐备；二维码的替代文本包含 URL；弹窗完全可键盘导航，Escape 关闭且焦点返回分享按钮。
- **AC-12:** 特性在最新 Chrome、Firefox、Safari、Edge（桌面）与 Chrome/Safari（移动）上可用；旧浏览器启用剪贴板回退。

## 8. 不做范围（v1）

- 服务端分享追踪 / 重定向计数（bit.ly 式分析）。
- 短链服务（使用规范 URL；UUID 长度的二维码密度可接受 —— 见 §10）。
- 自定义二维码品牌化（logo 叠加、颜色）—— v2 美化。
- 非模板实体的二维码（个人主页、合集、分类）。
- 分享计数 / 社交证明组件。
- 微信 JS-SDK 分享卡片（需要微信公众号集成）。
- 邮件分享（除验证码外无邮件基础设施）。
- 定时/临时分享链接（template-scheduler-sharing 负责）。
- "复制为 Markdown/HTML" 链接格式（export-formats 负责格式多样性）。

## 9. 依赖与假设

- **D-1:** 模板详情页（frontend/src/pages/TemplateDetails.js）存在 Like/Favorite/Fork 操作与代码库中的 Modal 组件；分享按钮插入既有操作行。
- **D-2:** 规范路由 `/templates/:id`（App.js:52）存在；`window.location.origin + /templates/{id}` 可在客户端构造，无需 API 调用。
- **D-3:** template-embedding-widget（设计）在同页定义了嵌入弹窗；本特性交叉链接到它，并假设其弹窗可被程序化打开（共享的 open-modal 处理器或事件）。
- **D-4:** 客户端二维码库（`qrcode` 或等价物，MIT 许可）可作为新的前端依赖；通过动态 import 懒加载。
- **D-5:** 既有的复制到剪贴板模式（APIKeyManager `copyToClipboard`、TemplateDetails.js:1009 的 SDK 代码片段复制）是要复用的反馈惯例。
- **D-6:** 假设架构师在实现次要复制选项前确认别名 URL 形状（FR-2）—— 是 `/t/{alias}` 还是其他路径；主规范 URL 没有歧义。

## 10. 给架构师的开放问题

1. **弹窗中的别名 URL：** 同时提供规范 `/templates/{id}` 与别名解析 URL 两个复制选项，还是 v1 只做规范 URL？（别名 URL 更漂亮但解释成本高；二维码应编码对分享而言规范的那个。）
2. **二维码密度：** 模板 id 是 UUID（约 36 字符）→ URL 约 60 字符 → 二维码版本 4-5，扫描无压力。若未来出现短 id，二维码自动变小。确认 v1 不需要短链服务。
3. **Web Share 文件分享：** `navigator.canShare({files})` 可以直接从原生面板分享二维码 PNG —— v1 纳入还是推迟？（设计推迟；记为延伸。）
4. **按钮位置：** 分享图标按钮放操作行（Like/Favorite/Fork 旁）还是标题旁的头部？设计假设操作行以保持一致。
5. **可见性按钮改名：** "设为公开"/"设为私有" —— 确认 i18n 键变更（`template_details.share_public` → `template_details.make_public`）且没有其他界面引用旧标签。
6. **PWA 集成：** pwa-offline（设计）让应用可安装；分享弹窗是否应出现在应用 manifest 的 share_target 条目中（接收来自其他应用的分享）？已推迟，但标记。
