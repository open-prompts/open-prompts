# 模板对比视图 — 需求分析

- **功能 ID：** template-compare
- **版本：** 1.0
- **状态：** 已提案（待架构评审）
- **作者：** ui-ux-agent
- **日期：** 2026-10-13

## 1. 竞品调研总结

| 平台 | 对比方式 | 关键启示 |
|---|---|---|
| **电商（Amazon、Best Buy）** | 卡片上的"加入对比"复选框；浮动对比托盘；带属性行的专用对比页；2–4 项上限 | 卡片复选框 + 浮动托盘是主流入口模式；硬上限保持表格可读 |
| **GitHub** | 跨 ref 对比视图；带词级高亮的统一/并排 diff | 词级（而非行级）高亮对散文很重要 —— 提示词正是散文 |
| **IDE diff 工具（VS Code）** | 并排窗格、内联词高亮、同步滚动 | 同步滚动是长内容的基本要求 |
| **PromptBase** | 无对比；用户开多个标签页 | 即使市场领导者也缺这个 —— 廉价且显眼的产品胜利 |
| **FlowGPT / Snack Prompt** | 无对比；呈现相似提示词但不可 diff | 所有提示词平台都有同样的缺口 |
| **SaaS 对比站（G2、vs 图表生成器）** | 带勾/叉标记的结构化属性表；"赢家"徽章 | 当条目共享 schema 时属性表有效 —— 模板正是如此（分类、标签、变量、统计） |

**综合分析：** 没有提示词平台提供对比，而所有相邻领域（电商、开发工具）都收敛到同一形态：**从列表卡片选择 → 浮动托盘 → 专用对比页**，包含 (1) 元数据的结构化属性表，(2) 带词级 diff 高亮和同步滚动的并排内容窗格，(3) 2–3 项上限。模板共享 schema（分类、标签、语言、变量、统计），属性表模式直接适用。diff 引擎在某种意义上已存在：template-versioning 为同一模板的两个版本提供 DiffModal —— 本功能将该界面泛化到 N 个不同模板。

## 2. 问题陈述

评估相似模板（三个"代码评审"提示词、两个"冷邮件"变体）的用户今天必须打开多个浏览器标签页，并在脑中拼凑标题、标签、变量和内容：

1. **没有并排界面。** 唯一的 diff 工具（template-versioning 的 DiffModal）比较同一模板的两个版本。比较两个*不同*模板在产品内不可能。
2. **变量是决定因素但在使用前不可见。** 哪个模板需要更少输入、哪个需要 `tone` 变量 —— 今天只能通过阅读全文或打开生成器发现。
3. **元数据分散。** 分类、标签、语言、版本数、更新时间和参与度统计位于不同的详情页；没有对齐视图。
4. **Fork 评估是盲目的。** template-remix-forks-tree 展示树，但在 fork 和源（或兄弟 fork 之间）做选择意味着来回切标签。

## 3. 目标用户

- **浏览/评估者（主要）：** 在收藏或使用前在相似公开模板间做选择的用户。
- **Fork 用户：** 在源模板和其 fork 之间做决定的用户（template-remix-forks-tree 提供入口）。
- **创作者：** 将自己的模板与热门相似模板对比以定位作品的用户。
- **管理员：** v1 无管理员界面（§8）；对比页是普通用户界面。

## 4. 用户故事

### 4.1 选择要对比的模板

- **US-C1：** 作为用户，我可以从任何列表（网格、搜索结果、横栏）的卡片上将模板加入对比选择，以便在浏览时收集候选。
- **US-C2：** 作为用户，我看到一个浮动对比托盘，显示所选模板和"对比"按钮，选择始终可见且可达。
- **US-C3：** 作为用户，我最多选 3 个模板；添加第 4 个会提示先移除一个，对比保持可读。
- **US-C4：** 作为用户，我可以从托盘移除模板或清空整个选择，从而控制对比集。
- **US-C5：** 作为用户，我的对比选择在浏览器会话中持久化（localStorage），页面间导航不会丢失。
- **US-C6：** 作为用户，我可以直接通过 URL（`/compare?ids=1,2,3`）打开对比页，对比可分享、可收藏。

### 4.2 阅读对比

- **US-C7：** 作为用户，我看到对齐的属性表（标题、作者、分类、标签、语言、可见性、版本数、更新日期、点赞、收藏、浏览、使用），元数据差异一目了然。
- **US-C8：** 作为用户，我看到每个模板从 `$$var$$` 占位符提取的变量列表（名称、数量），无需阅读全文即可判断输入成本。
- **US-C9：** 作为用户，我看到并排窗格中的内容，相对所选基准有词级差异高亮，文本分歧立即可见。
- **US-C10：** 作为用户，我可以切换 diff 基准（任一被对比模板或"无高亮"），从而控制参考点。
- **US-C11：** 作为用户，内容窗格同步滚动，长模板保持对齐。
- **US-C12：** 作为用户，我可以从任一列跳转到该模板的详情页，深入评估一键可达。

### 4.3 系统故事

- **US-C13：** 作为系统，我只允许对比请求者可见的模板，私有模板绝不泄漏到分享的对比 URL 中。
- **US-C14：** 作为系统，我在客户端计算词级 diff，没有 diff 负载跨越网络。

## 5. 功能需求

### 5.1 选择与托盘

- **FR-1：** 列表（主页网格、搜索结果、相关横栏、合集视图）中的每个模板卡片应提供"加入对比"切换操作（图标按钮，悬停/聚焦可见，始终在 Tab 序列中）。
- **FR-2：** 选中 ≥1 个模板时，视口底部应渲染浮动对比托盘，显示缩略图/名称 chips、每个 chip 的移除 ✕、"清空"操作和"对比"按钮（≥2 时启用）。
- **FR-3：** 选择上限为 3 个模板。添加第 4 个在托盘中显示内联消息（"最多对比 3 个 —— 请先移除一个"）；添加操作无效果。
- **FR-4：** 选择应按浏览器（而非用户账户）为键持久化在 localStorage 中；它在导航和重载后保留，不同步到服务端。
- **FR-5：** 托盘应可收起（折叠为带计数的角落药丸）；点击重新展开，绝不遮挡最后一行内容（页面底部内边距自适应）。

### 5.2 对比页

- **FR-6：** 对比页应存在于 `/compare?ids=<id1>,<id2>[,<id3>]`（需 ≥2 个 id；1 个或 0 个 → 带引导的空态）。
- **FR-7：** 页面应为每个模板渲染一列：头部（标题、作者链接、"打开"链接）、属性表、变量列表和内容窗格 —— 每行垂直对齐。
- **FR-8：** 属性表应显示：标题、作者、分类、标签、语言、可见性、版本数、最后更新、点赞、收藏、浏览、使用。浏览/使用仅在可用时渲染（prompt-analytics 依赖，D-4）；否则省略该行。
- **FR-9：** 变量列表应使用现有 `$$var$$` 正则（advanced-editor D-1 契约）在客户端从最新版本内容提取，去重、按字母排序，带计数徽章。
- **FR-10：** 内容窗格应显示最新版本内容，相对所选基准（默认最左列）有词级 diff 高亮，在客户端计算。
- **FR-11：** 基准选择器应允许选择任一被对比模板为基准或"无"（纯内容，无高亮）。
- **FR-12：** 内容窗格应同步滚动（垂直；水平独立），带同步开关。
- **FR-13：** URL 中无效或不可访问的 id（不存在、私有、作者被封禁）应被丢弃并显示通知（"1 个模板已被移除：对你不可见"）；若剩余 ≥2 则渲染其余，否则空态。
- **FR-14：** URL 中的重复 id 应去重。

### 5.3 卡片之外的入口

- **FR-15：** 模板详情页的操作行应提供"加入对比"，用户可以从已喜欢的模板发起对比。
- **FR-16：** forks 树（template-remix-forks-tree）在该功能的 UI 交付后应在 fork 节点上提供"与源对比"；在此之前，卡片选择覆盖该流程。

### 5.4 普通用户与管理员分离

- **FR-17：** 所有界面均为普通用户界面（`/compare`、卡片操作、详情操作）。无管理员控制台页面；无 `/api/v1/admin` 端点。

### 5.5 API

- **FR-18：** v1 不需要新端点：页面并行通过现有 `getTemplate`（返回元数据 + 最新内容）获取每个模板。若架构师偏好批量端点（`GET /api/v1/templates/batch?ids=1,2,3`），那是优化而非需求（OQ-1）。
- **FR-19：** 可见性执行依赖现有 `getTemplate` 授权（私有模板对非所有者 404/403）；客户端按 FR-13 将其视为"已丢弃"。

## 6. 非功能需求

- **NFR-1（性能）：** 3 个模板的对比页可交互 < 1.5s（3 个并行 `getTemplate` 调用）；≤64KB 内容的客户端 diff < 200ms 完成。
- **NFR-2（兼容性）：** 不改变现有端点或页面；卡片操作是附加的。没有该操作的列表（如第三方嵌入）不受影响。
- **NFR-3（无障碍）：** 托盘、卡片切换、属性表和 diff 窗格完全可键盘操作；diff 高亮有文本替代（UI/UX 文档 §9）。
- **NFR-4（国际化）：** 所有新 UI 字符串以 EN 和 ZH 提供且键集一致；包含 diff 高亮图例。
- **NFR-5（隐私）：** 对比 URL 仅含模板 id；选择保留在客户端（localStorage）；无服务端选择存储或历史。
- **NFR-6（确定性）：** 相同 URL 始终渲染相同对比（获取时的最新版本）；无个性化。
- **NFR-7（内容限制）：** diff 在现有内容长度限制内运行；超过客户端 diff 预算（64KB）的模板渲染纯内容并显示通知，而非高亮。

## 7. 验收标准

- **AC-1：** 从主页网格添加两个模板显示托盘；点击对比打开 `/compare?ids=…`，两列对齐。
- **AC-2：** 添加第 4 个模板显示上限消息且不改变选择。
- **AC-3：** 属性表跨列对齐所有行；不同的值被视觉强调（如标签、分类）。
- **AC-4：** 变量列表显示去重、按字母排序的名称及计数；含 `$$tone$$` 和 `$$language$$` 的模板恰好列出这些。
- **AC-5：** 基准为最左列时，仅存在于右侧模板的词被高亮为新增，反之亦然；切换基准重新高亮；"无"移除高亮。
- **AC-6：** 同步开启时滚动一个内容窗格会滚动其他窗格；关闭同步后停止。
- **AC-7：** 包含他人私有模板 id 的对比 URL 丢弃该列并显示通知，渲染其余部分。
- **AC-8：** 重载页面从 URL 恢复相同对比；托盘选择在导航后保留（localStorage）。
- **AC-9：** 所有卡片切换按钮可通过 Tab 触达并被屏幕阅读器播报（"加入对比，模板 X"）。
- **AC-10：** 所有新 UI 字符串以 EN 和 ZH 存在于翻译文件中且键集一致。

## 8. 范围之外（v1）

- 对比特定版本（v1 仅对比最新版本；版本对 diff 保留在 template-versioning）。
- 对比超过 3 个模板。
- 服务端 diff 计算或 diff 持久化（无保存的对比）。
- 语义相似度评分（"87% 相似"）。
- 对比非模板实体（合集、链、用户）。
- 管理员对比界面。
- 导出/打印对比报告。
- 任何形式的变现 —— 本产品永久超出范围。

## 9. 依赖与假设

- **D-1：** `getTemplate` 对请求者可见的任何模板返回完整元数据和最新版本内容（已在 `services/api.js` 验证，与 import-export D-1 相同假设）。
- **D-2：** `$$variable$$` 提取正则与 advanced-editor（其 D-1）共享 —— 一个客户端工具，两个消费者。
- **D-3：** 需要客户端词级 diff 工具；template-versioning 的 DiffModal 已为两个版本实现行/词 diff —— 本功能复用或提取该引擎（OQ-2）。
- **D-4：** 属性表中的浏览/使用依赖 prompt-analytics 计数器（模板上的 `view_count`/`use_count`）；若未交付则省略这些行（FR-8）。
- **D-5：** TemplateCard 支持对比切换的操作插槽或包装而不破坏现有点击行为（accessibility 设计使卡片可键盘操作）。
- **D-6：** React Router v6 支持添加 `/compare` 路由；通过 `useSearchParams` 解析查询参数（与 template-search-filtering D-4 相同）。
- **D-7：** 点赞/收藏/版本数/updated_at 是 `getTemplate` 返回的现有模板字段。

## 10. 给架构师的开放问题

1. **批量端点：** v1 接受 3 个并行 `getTemplate` 调用，还是现在就交付 `GET /api/v1/templates/batch?ids=` 端点（更少往返、单次可见性检查）？设计假设并行调用；批量是优化。
2. **Diff 引擎复用：** 将 template-versioning 的 DiffModal diff 逻辑提取到共享 `diff.js` 工具（词级、基准参数化）—— 确认当前实现是词级还是需要小升级。
3. **localStorage 键共享：** 对比选择应在同一浏览器的标签页间共享（storage 事件同步）还是每标签页独立？设计假设共享（简单 localStorage 语义）。
