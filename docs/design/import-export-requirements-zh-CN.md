# 模板导入/导出 — 需求分析

| | |
|---|---|
| **Feature ID** | FE-010 |
| **Version** | 1.0 |
| **Status** | Proposed（待架构评审） |
| **Author** | ui-ux-agent |
| **Date** | 2026-10-10 |

## 1. 竞品研究

| 产品 | 导入/导出方式 | 优点 | 缺点 |
|---|---|---|---|
| AIPRM | 提示词模板的完整 JSON 导出/导入，用于团队共享；包含分类、语气、主题元数据 | 跨账号可移植；团队迁移方便 | 格式不透明；导出不含版本历史 |
| PromptBase | 封闭市场；无面向用户的导出——内容锁定在平台内 | 保护市场内容 | 用户无法备份自己的作品 |
| FlowGPT | 仅通过公开 URL 分享；无文件导出 | 分享简单 | 无离线可移植性，无备份 |
| ChatGPT（自定义指令） | 仅复制到剪贴板 | 零摩擦 | 无结构、无元数据，需手动重新录入 |
| GitHub Gist | 完整文件下载；任意文本格式 | 通用、有版本 | 无提示词专用结构 |
| Cursor（rules 文件） | 仓库中共享 `.mdc` 文件；放置文件即导入 | 生态可移植 | 无校验，无元数据模式 |

**结论：** 没有竞品提供结构化、带版本历史的提示词导出。AIPRM 的 JSON 方案最接近，但缺少版本历史。定义一个开放的、带版本历史的 JSON 格式是 open-prompts 的差异化机会：用户拥有并可以迁移自己的作品。

## 2. 问题陈述

用户在编写和迭代提示词模板上投入了大量精力，但作品被锁定在 open-prompts 内部：

1. **无法备份。** 模板被误删（或账号出问题）意味着作品丢失。无法将副本带离平台。
2. **无法迁移。** 用户在账号之间迁移（个人 → 团队，或迁移实例）时必须重新录入每个模板，且丢失版本历史。
3. **无法离线分享。** 私有模板无法交给同事，除非设为公开或重新粘贴原始文本——这会丢失所有元数据（分类、标签、语言）和历史。
4. **无法批量入驻。** 已有提示词文件或其他工具存量提示词的用户，没有结构化的方式带入平台，只能逐字段手动创建。

## 3. 目标用户

- **提示词作者**：希望备份模板和版本历史。
- **迁移用户**：在账号或自托管实例之间迁移作品。
- **团队/同事**：不公开模板的前提下共享私有模板。
- **新用户**：带着存量提示词文件入驻。

## 4. 用户故事

- **US-1**：作为模板所有者，我希望将我的某个模板（含完整版本历史）导出为 JSON 文件，以便拥有平台外的备份。
- **US-2**：作为用户，我希望导入之前导出的模板文件，以便在另一个账号中恢复或迁移我的作品。
- **US-3**：作为用户，我希望在导入提交前审查并编辑模板字段，以便解决冲突（如标题重复）并选择可见性。
- **US-4**：作为用户，当导入文件格式错误、被截断或不是 open-prompts 导出文件时，我希望看到清晰的校验错误，以便理解问题所在。
- **US-5**：作为收到共享导出文件的同事，我希望导入的模板默认为私有，以便未经我同意不会公开暴露。
- **US-6**：作为导入多版本导出文件的用户，我希望版本历史被保留（按顺序生成各版本），以便迭代脉络不丢失。
- **US-7**：作为用户，我希望导出文件是可读的 JSON，以便检查、脚本化处理或存入 git。
- **US-8**：作为管理员，我希望从管理控制台导出任意模板（用于支持/调试），以便在不冒充用户的情况下检查其模板。

## 5. 功能需求

### 5.1 导出

- **FR-1**：模板所有者可在模板详情页通过"导出"操作导出自己拥有的任意模板，下载单个 `.json` 文件。
- **FR-2**：导出文件必须包含：格式标识（`open-prompts-template`）、格式版本（`1`）、导出元数据（exported_at ISO-8601、来源产品名）、模板元数据（标题、描述、可见性、类型、标签、分类、语言），以及完整版本历史（按序排列的版本号、内容、变更说明（如有）、创建时间）。
- **FR-3**：导出必须在客户端完成：前端基于现有 `getTemplate` 和 `listTemplateVersions` 响应组装文件。无需新增后端接口。
- **FR-4**：下载文件名必须由模板标题（slug 化、ASCII 安全、最长 60 字符）加模板 id 前缀派生，例如 `my-prompt-template-a1b2c3d4.json`。
- **FR-5**：非所有者不得提供导出他人模板的入口；对用户不拥有的模板隐藏导出操作。
- **FR-6**：导出不得包含所有者身份信息（用户 id、邮箱、显示名），避免在共享文件中泄露个人数据。

### 5.2 导入

- **FR-7**：已登录用户可在模板首页通过"导入"操作打开模态框，通过文件选择器或拖放接受单个 `.json` 文件。
- **FR-8**：导入流程必须分两步：(1) 文件选择与解析并给出校验反馈；(2) 预填解析字段的审查表单（标题、描述、分类、标签、语言、可见性、最新版本内容），用户可在确认前编辑。
- **FR-9**：导入必须复用现有 `createTemplate` 接口。无需新增后端接口。多版本导入先以最新内容创建模板，再按顺序通过现有更新路径应用更早版本以保留历史（见开放问题）。
- **FR-10**：导入的模板必须默认 `visibility: private`，无论导出值为何；用户可在审查步骤修改。
- **FR-11**：校验必须拒绝：非 JSON 文件、大于 1 MB 的文件、缺少格式标识、未知格式版本、缺少标题或内容，以及违反现有约束的字段值（标题长度、标签数量/长度、内容大小）。每次拒绝必须产生指明问题字段的具体、可读错误。
- **FR-12**：若解析出的标题与该用户现有模板标题重复，审查表单必须给出（非阻断的）警告并建议加后缀的标题（`title (imported)`）；用户可保留或修改。
- **FR-13**：导入成功后，用户被导航到新模板的详情页并收到成功通知。
- **FR-14**：校验失败时，用户停留在第 1 步，错误已展示，可选择其他文件。

### 5.3 普通用户与管理员划分

- **普通用户**：导出自己的模板（FR-1–6）；导入文件（FR-7–14）。
- **管理控制台**（`/admin/templates/:id`）：管理员可对任意模板使用与 FR-2 输出格式完全相同的"导出"操作，支持支持/调试工作流。不提供管理员导入（管理员通过自己账号的普通导入处理用户上报的文件）。

## 6. 非功能需求

- **NFR-1（易用性）**：导入审查步骤复用现有 CreateTemplateModal 的字段布局与校验，学习成本为零。
- **NFR-2（性能）**：导出 ≤ 50 个版本的模板在客户端 1 秒内完成；数据拉取后立即开始文件下载。
- **NFR-3（安全）**：导出文件绝不包含凭据、令牌或所有者 PII。导入在 try/catch 中解析不可信 JSON 并设大小上限；畸形输入不能导致应用崩溃（错误边界安全）。
- **NFR-4（兼容性）**：格式版本 `1` 的文件在未来版本中保持可导入；未知的未来版本被明确拒绝并给出清晰提示，而非错误解析。
- **NFR-5（无障碍）**：导入模态框完全可键盘操作，通过现有 Field 错误模式播报校验错误；拖放区域有可见焦点态和可键盘访问的文件按钮。
- **NFR-6（国际化）**：所有 UI 文案、校验消息及错误码的可读部分均本地化（EN/ZH）。JSON 文件本身使用英文键名，不做本地化。

## 7. 验收标准

- **AC-1**：所有者打开模板详情页 → 可见"导出" → 点击下载符合 FR-2 结构的有效 JSON 文件；用文本编辑器打开可见缩进良好的可读 JSON。
- **AC-2**：非所有者（或未登录）查看公开模板时看不到"导出"操作。
- **AC-3**：导出文件按时间顺序包含 N 个版本，内容与变更说明完好。
- **AC-4**：用户将 AC-1 的文件导入另一账号 → 审查表单预填所有字段、可见性强制为私有 → 确认 → 模板创建 → 导航到详情页 → 版本历史显示同样的 N 个版本。
- **AC-5**：导入随机非 JSON 文件（如 `.png`）显示具体错误，而非崩溃。
- **AC-6**：导入 `"format": "unknown-thing"` 或 `"format_version": 99` 的 JSON 显示"不支持的格式"错误。
- **AC-7**：导入大于 1 MB 的文件在解析前显示大小错误。
- **AC-8**：标题冲突产生非阻断警告并建议加后缀的标题。
- **AC-9**：管理员从 `/admin/templates/:id` 导出用户模板 → 文件结构与普通导出一致。
- **AC-10**：所有导入/导出 UI 文案以相同键出现在 EN 和 ZH 语言包中。
- **AC-11**：导入模态框支持纯键盘操作：Tab 遍历所有控件、Enter 提交、Escape 关闭。
- **AC-12**：导出与导入在浅色和深色主题下均无视觉缺陷。

## 8. 范围外

- 批量导出（一次导出全部模板 / 账号归档）——未来迭代候选。
- 从第三方格式导入（AIPRM JSON、ChatGPT 文本）——仅支持 open-prompts 格式。
- 跨实例"链接分享"或服务端传输——仅限文件方式。
- 导出提示词（使用记录）或 API 密钥——仅限模板。
- 任何形式的市场上架或导出文件的商业化分发。

## 9. 依赖与假设

- **D-1**：`getTemplate` 返回完整元数据，`listTemplateVersions` 返回所有版本及内容；两者均已在 `services/api.js` 中提供。
- **D-2**：`createTemplate` 接受 title、description、visibility、type、tags、category、content、language（已在 proto `CreateTemplateRequest` 中验证）。
- **D-3**：模板更新路径在内容变化时创建新版本（现有行为），多版本导入依赖该行为。
- **D-4**：模板 `type`（system/user）属于导出内容；审查步骤将其作为只读或可编辑字段暴露，与 CreateTemplateModal 保持一致。
- **D-5**：预期无后端改动；若架构师为原子性倾向服务端导出接口，此处定义的文件格式不变。

## 10. 给架构师的开放问题

1. **多版本导入机制**：先以*最早*版本创建模板再依次更新到最新，历史顺序正确但需要 N+1 次接口调用。备选：仅以最新内容创建，接受单一版本。您倾向哪种取舍？（设计假设通过顺序更新保留完整历史，上限 50 个版本。）
2. **导入时的变更说明**：若版本管理功能引入 `change_note`，导入的版本是否应重放原始变更说明？（设计假设是。）
3. **文件大小上限**：考虑到内容列限制和典型版本数量，1 MB 的客户端上限是否合理？
4. **管理员导出**：请确认管理员可通过现有管理端接口获取任意模板的版本；若需要专门的管理端读取路径，请标记。
