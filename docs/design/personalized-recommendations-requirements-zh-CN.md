# 个性化推荐 — 需求分析

- **功能 ID：** personalized-recommendations
- **版本：** 1.0
- **状态：** 已提案（待架构评审）
- **作者：** ui-ux-agent
- **日期：** 2026-10-13

## 1. 竞品调研总结

| 平台 | 个性化方式 | 关键启示 |
|---|---|---|
| **YouTube** | 主页信息流由观看历史驱动；每张卡片有"不感兴趣"和"不看此频道"；"为什么推荐这个视频？"解释链接 | 带撤销的逐卡片关闭是信任机制；解释（"因为你看过 X"）让信息流显得公平 |
| **Reddit** | 注册时的兴趣选择器为信息流播种；历史不足时回退到"热门" | 冷启动用非个性化默认信息流解决，而不是空白页 |
| **FlowGPT** | 基于点赞/关注的"为你推荐"标签页；匿名用户默认"趋势" | 独立的标签页/横栏让个性化浏览与发现式浏览保持分离 |
| **AIPRM** | 库按安装时选择的分类排序；无逐用户学习 | 即使是静态的兴趣选择，也比通用列表显著提升相关性 |
| **Spotify** | "因为你喜欢 X"横栏；每首歌可"隐藏此歌曲"；用户因为可见的原因而信任系统 | 原因标签很便宜（一个字符串），却是最大的信任驱动因素 |
| **Medium** | "基于你的阅读"区块；可在设置中编辑显式关注的主题 | 让用户查看并编辑自己的兴趣画像，把黑盒变成可控功能 |

**综合分析：** 经过验证的 v1 形态是主页上的**基于内容的"为你推荐"横栏**，由用户自己的站内行为（收藏、点赞、使用、浏览）计算，带**可见的原因标签**（"因为你点赞过……"、"营销中的更多"）、**逐卡片"不感兴趣"关闭（带撤销）**，以及**可编辑的兴趣画像**，让用户看到并纠正系统对他们的了解。冷启动用户（尚无信号）看到明确标注的现有趋势/热门内容作为回退 —— 绝不出现空横栏。v1 无机器学习、无嵌入、无跨用户信号：推荐器是用户自身交互历史与模板元数据的透明函数。

## 2. 问题陈述

Open Prompts 的主页向每个登录用户展示相同的新品优先列表（加上 template-search-filtering 的搜索/过滤/排序和 related-templates 的元数据横栏）。仍有三个缺口：

1. **没有"为我"的界面。** 每周收藏并使用营销模板的用户看到的仍是无差别的广场。每个竞品上最强的参与度界面 —— 个性化横栏 —— 是缺失的。
2. **信号存在但未被使用。** 平台已经记录收藏、点赞、使用（`prompts`）以及（按 prompt-analytics）浏览事件。这些都没有反馈到用户接下来看到的内容。
3. **用户无法控制个性化。** 竞品做个性化时，用户要求（并得到了）"不感兴趣"控制和兴趣画像的可见性。设计没有控制的个性化将是信任倒退；本功能将两者一起交付。

本功能被两个已交付设计明确推迟：related-templates §8（"个性化推荐、浏览历史信号、共同交互矩阵；横栏卡片上的'不感兴趣'控制"）和 onboarding §8（"分类兴趣个性化选择器"）。现在将这些推迟项作为一个连贯的功能交付。

## 3. 目标用户

- **活跃普通用户（主要）：** 拥有 ≥3 个交互信号（收藏/点赞/使用/浏览）的用户，希望主页反映他们的实际兴趣。
- **新/冷启动用户：** 信号 <3 的用户；他们看到明确标注的"本周热门"回退横栏，绝不出现空白或损坏的区块。
- **注重隐私的用户：** 希望查看、编辑或重置平台对他们推断内容的用户。
- **管理员：** 本功能无管理员界面（见 FR-24）；推荐仅是普通用户体验。

## 4. 用户故事

### 4.1 接收推荐

- **US-R1：** 作为有交互历史的登录用户，我在主页顶部看到"为你推荐"横栏，匹配我兴趣的内容立即可见。
- **US-R2：** 作为用户，每张推荐卡片都显示推荐原因（"因为你点赞过 Cold Outreach"、"营销中的更多"），因此我信任这个横栏。
- **US-R3：** 作为用户，我的推荐中绝不出现我自己的模板、已收藏的模板或私有模板。
- **US-R4：** 作为用户，推荐随我的行为变化而刷新（收藏新分类 → 它会出现），横栏保持相关。
- **US-R5：** 作为冷启动用户（信号 <3），我看到"本周热门"横栏，主页绝不显得空白或损坏。

### 4.2 控制推荐

- **US-R6：** 作为用户，我可以用"不感兴趣"操作关闭任何推荐卡片，让它停止出现。
- **US-R7：** 作为用户，关闭后我获得撤销选项，错误可以逆转。
- **US-R8：** 作为用户，我可以打开"兴趣"页面，看到从我的活动推断出的分类和标签及权重条，理解是什么驱动我的横栏。
- **US-R9：** 作为用户，我可以从兴趣画像中移除主题或重置整个画像，从而控制我的个性化。
- **US-R10：** 作为用户，我可以完全关闭推荐，主页回到标准浏览体验。

### 4.3 系统故事

- **US-R11：** 作为系统，我只从用户自己的交互和公开模板元数据计算推荐，不存在跨用户画像。
- **US-R12：** 作为系统，我按用户缓存推荐结果（短 TTL），主页保持快速。
- **US-R13：** 作为系统，被关闭的模板不再出现，除非用户重置关闭记录。

## 5. 功能需求

### 5.1 信号模型

- **FR-1：** 系统应从四个信号源计算每用户的**兴趣画像**，权重为：收藏 = 5、使用 = 4、点赞 = 3、浏览 = 1。
- **FR-2：** 信号应在最近 90 天窗口内计数；更早的交互不参与计算。
- **FR-3：** 画像应为 `{type: category|tag, value, score}` 条目列表，按主题聚合：score = 用户与携带该主题模板交互的 Σ(信号权重)。
- **FR-4：** v1 信号源：`template_favorites`、`template_likes`、`prompts`（使用，web 来源）以及 prompt-analytics 事件表的浏览事件。若 prompt-analytics 尚未交付，浏览贡献为 0，功能优雅降级（仅收藏/点赞/使用）—— 见 D-3。
- **FR-5：** 画像最多保留 20 个主题（按分数排序）；并列时按字母序打破，保证确定性。

### 5.2 推荐计算

- **FR-6：** 系统应推荐公开模板（公开可见性、作者未被封禁，遵循现有列表规则），且用户尚未收藏、点赞或创作的模板。
- **FR-7：** 候选排序分数应为：`match_score × log10(1 + like_count)`，其中 `match_score` = 候选主题中出现在用户前 10 兴趣里的分数之和。并列时按 `created_at DESC` 保证新鲜度。
- **FR-8：** 每个推荐项应携带**原因**：当单一来源模板的主题占主导时为 `{type: "because_you_liked"|"because_you_used"|"because_you_favorited", template_title}`，否则为 `{type: "topic", topic_type, topic_value}`（"营销中的更多"）。原因由服务端派生并原样渲染。
- **FR-9：** 横栏最多返回 12 项；客户端请求 `limit=12` 并渲染收到的内容（少于 3 项时隐藏横栏，与 related-templates 惯例一致）。
- **FR-10：** 被关闭的模板（FR-16）应从结果中排除。
- **FR-11：** 结果应按用户缓存 10 分钟（服务端）；新交互在一个 TTL 窗口内反映。

### 5.3 主页横栏

- **FR-12：** 对启用推荐且计算得出 ≥1 项的登录用户，"为你推荐"横栏应渲染在主页顶部（模板网格上方、搜索栏下方）。
- **FR-13：** 对交互信号 <3 的登录用户，横栏应改为显示"本周热门"（最近 7 天 like_count + favorite_count 最高，复用 template-search-filtering FR-10 的趋势定义），并如此标注。
- **FR-14：** 匿名访客不看到横栏（标准浏览体验）；无匿名个性化或跟踪。
- **FR-15：** 横栏可通过其标题栏的"暂时隐藏"控件按会话关闭；下次页面加载时重新出现。

### 5.4 不感兴趣

- **FR-16：** 每张推荐卡片应提供"不感兴趣"操作（悬停/聚焦时可见，始终可键盘触达），为（用户, 模板）记录一次关闭。
- **FR-17：** 关闭应立即从横栏移除卡片（客户端），并显示带**撤销**操作的 toast，持续 8 秒。
- **FR-18：** 关闭无限期持久化；兴趣页面的"重置关闭记录"操作清除全部。
- **FR-19：** 关闭某个模板不影响其他任何内容（不影响点赞、收藏或其他界面）。

### 5.5 兴趣管理

- **FR-20：** **兴趣**页面应在 `/settings/interests` 提供（需登录），显示：带权重条的兴趣画像主题 chips（相对于最高主题）、推荐开/关切换、重置画像操作、重置关闭记录操作。
- **FR-21：** 移除主题会将其从兴趣画像（从而从未来推荐）中排除，直到新交互重新添加；被移除主题列为"已移除主题"并带恢复操作。
- **FR-22：** 重置画像清除所有分数和已移除主题记录；横栏回退到"本周热门"，直到信号重建。
- **FR-23：** 关闭推荐会完全隐藏横栏（FR-12/13 不渲染）；设置按用户持久化。

### 5.6 普通用户与管理员分离

- **FR-24：** 本功能的所有界面均为普通用户界面（`/`、`/settings/interests`、`/api/v1/recommendations*`、`/api/v1/me/interests*`）。不新增管理员控制台页面和 `/api/v1/admin` 端点；推荐表现的管理员分析不在范围内（§8）。

### 5.7 API

- **FR-25：** `GET /api/v1/recommendations?limit=12` → `{items: [{template_id, reason, …卡片字段}], fallback: bool}`。需认证；匿名返回 401。
- **FR-26：** `POST /api/v1/recommendations/{template_id}/dismiss` → 204；幂等。
- **FR-27：** `GET /api/v1/me/interests` → `{topics: [{type, value, score}], removed_topics: [{type, value}], recommendations_enabled, signal_summary: {favorites, likes, uses, views}}`。
- **FR-28：** `DELETE /api/v1/me/interests/topics/{type}/{value}` → 移除主题；`POST /api/v1/me/interests/topics/{type}/{value}/restore` → 恢复被移除主题。
- **FR-29：** `POST /api/v1/me/interests/reset` → 清空画像和已移除主题；`POST /api/v1/me/interests/dismissals/reset` → 清空关闭记录；`PUT /api/v1/me/interests/preferences` → `{recommendations_enabled: bool}`。

## 6. 非功能需求

- **NFR-1（性能）：** `GET /recommendations` p95 < 300ms（缓存命中）且 < 800ms（冷启动，≤90 天窗口的画像计算）；横栏在主网格查询之后非阻塞加载。
- **NFR-2（隐私）：** 推荐仅使用已存储的第一方交互数据（收藏、点赞、使用、浏览）。无新跟踪、无跨用户信号、无第三方数据。兴趣画像对用户完全可见且可编辑（FR-20–22）。
- **NFR-3（透明度）：** 每个推荐项携带原因（FR-8）；兴趣页面用通俗语言解释信号权重。
- **NFR-4（兼容性）：** 关闭推荐的用户或匿名访客看到与现在完全相同的主页；不改变现有端点。
- **NFR-5（无障碍）：** 横栏、关闭操作、撤销 toast 和兴趣页面完全可键盘操作并有屏幕阅读器播报（UI/UX 文档 §9）。
- **NFR-6（国际化）：** 所有新 UI 字符串以 EN 和 ZH 提供且键集一致；主题值（分类/标签名）为专有名词，不翻译。
- **NFR-7（确定性）：** 相同用户、相同画像状态、相同 TTL 窗口 → 相同结果顺序（按 FR-5/FR-7 的稳定并列打破规则）。
- **NFR-8（数据）：** 新表：`recommendation_dismissals (user_id, template_id, created_at)` 和 `user_interest_settings (user_id, recommendations_enabled, …)`；兴趣画像按需计算或缓存 —— v1 不需要画像表（架构师决策，见 OQ-2）。

## 7. 验收标准

- **AC-1：** 收藏了 3 个营销模板的用户看到"为你推荐"横栏，其中条目为公开营销模板（或携带营销主题原因），且都不是其自己的或已收藏的模板。
- **AC-2：** 每张横栏卡片显示原因标签；当存在主导来源模板时，至少一个条目显示"因为你{点赞|使用|收藏}过 {标题}"。
- **AC-3：** 点击"不感兴趣"立即移除卡片，显示撤销 toast，且刷新后该模板不再出现；点击撤销恢复它。
- **AC-4：** 全新账户看到"本周热门"（有标注），而不是空横栏或错误。
- **AC-5：** 匿名访客不看到横栏。
- **AC-6：** 兴趣页面列出带权重条的主题，与 API 分数一致；移除主题后，在一个缓存 TTL 内它从后续推荐中消失。
- **AC-7：** "重置画像"清空主题；横栏回退到"本周热门"。
- **AC-8：** 关闭推荐后该用户每次访问都不再看到横栏；重新开启后恢复。
- **AC-9：** `GET /api/v1/recommendations` 对匿名请求返回 401；所有 `/me/interests` 端点需要认证。
- **AC-10：** 私有模板和被封禁作者的模板绝不出现在推荐中。
- **AC-11：** 所有新 UI 字符串以 EN 和 ZH 存在于翻译文件中且键集一致。

## 8. 范围之外（v1）

- 协同过滤 / 共同交互信号（"喜欢此模板的用户也喜欢"）。
- 机器学习模型、嵌入、语义相似度。
- 主网格的个性化排序（横栏是附加的；网格保持用户可控）。
- "不感兴趣"原因或按主题反馈（"减少此类"）—— v1 仅关闭单个模板。
- 模板详情页上的推荐横栏（related-templates 拥有该界面，非个性化）。
- 匿名个性化（设备指纹、仅本地历史横栏）—— 永久超出范围。
- 推荐的管理员分析或调优 UI。
- 基于推荐的邮件摘要或推送通知。
- 任何形式的变现（横栏中的赞助位、推广卡片）—— 本产品永久超出范围。

## 9. 依赖与假设

- **D-1：** `template_favorites`、`template_likes` 和 `prompts` 表带 `user_id`/`created_at`，可查询 90 天窗口；`templates` 携带 `category`、`tags`、`like_count`、`visibility`、`owner_id`。
- **D-2：** 公开列表可见性规则（公开、作者未被封禁）是现有列表端点的可复用查询片段（与 related-templates D-2 相同假设）。
- **D-3：** 浏览事件依赖 prompt-analytics 功能的事件表（其 FR-5）。若尚未交付，本功能仅从收藏/点赞/使用计算；信号权重表和 UI 文案优雅降级（兴趣页面上浏览显示为 0）。
- **D-4：** 趋势定义（7 天点赞+收藏窗口）与 template-search-filtering FR-10 共享；回退横栏复用它而非重新定义。
- **D-5：** 主页（Home.js）在网格上方有容纳一个横栏的空间；横栏遵循 related-templates 建立的横向卡片惯例（复用 TemplateCard、移动端 scroll-snap）。
- **D-6：** Toast/撤销基础设施：notifications 设计提供 toast；若尚未实现，本功能内构建一个最小内联撤销 toast。
- **D-7：** `/settings` 路由前缀已存在或由其他在途功能引入（如 notification-preferences）；本功能在其下添加 `/settings/interests`，不主张对父路由的所有权。
- **D-8：** 认证中间件为主页数据获取区分匿名与已认证；未认证时客户端直接不发起横栏请求（客户端门控 + 服务端 401）。

## 10. 给架构师的开放问题

1. **画像计算时机：** 每次 `GET /recommendations` 时计算兴趣画像（简单、始终新鲜、成本 = 4 个聚合查询）vs. 按用户物化并用 TTL 刷新任务（更快、更多组件）？设计假设按需计算加 10 分钟结果缓存（FR-11）。
2. **已移除主题的存储：** 仅派生（重新计算减去移除项仍需要移除表）—— 确认 `user_interest_topics_removed (user_id, type, value)` 作为小型专用表 vs. `user_interest_settings` 上的 JSONB 列。
3. **浏览事件依赖顺序：** 若 prompt-analytics 后交付，本功能是否应先以 3 信号模型（收藏/点赞/使用）合并，之后再添加浏览？设计认为是 —— 信号表是数据驱动的。
4. **关闭范围：** v1 仅按模板（FR-19）；未来的按主题抑制是否值得现在预留 schema 占位？设计认为不需要 —— 需要时再加。
