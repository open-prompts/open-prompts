# 模板合集与分享 — 需求分析

- **功能标识:** template-collections
- **版本:** 1.0
- **状态:** 已提案（待架构评审）
- **作者:** ui-ux-agent
- **日期:** 2025-06-25

## 1. 竞品研究摘要

| 平台 | 合集/分享方式 | 关键启示 |
|---|---|---|
| **PromptBase** | 策展市场分类 + 卖家"店铺"；可分享的商品链接；无用户自定义合集 | 每个策展集合有稳定可分享的 URL 是核心原语；店铺聚合创作者的作品 |
| **FlowGPT** | 用户在主页创建提示词列表/合集；分享链接；合集有封面图与描述 | 合集是带元数据的一等对象；主页聚合驱动发现 |
| **Snack Prompt** | 社区"空间"/合集；用户把提示词组织成可分享的看板；可关注合集 | 关注合集带来持续参与；看板在某些情况下是协作的 |
| **AIPRM** | 个人库中的保存列表/文件夹；可分享的列表链接；公开列表参与排名 | 个人组织（私有）与公开分享（发布）是同一对象的两个状态 |
| **PromptHero** | 用户主页聚合作品；无任意合集 | 主页即合集是最小版本；任意合集增加灵活性 |
| **通用模式（Spotify 播放列表 / YouTube 播放列表）** | 创建 → 添加条目 → 可选发布 → 分享 URL → 他人可查看/关注 | 播放列表模式被普遍理解：私有工作集 → 一键发布 → 可分享链接 |

**综合结论:** 播放列表模式（Spotify/YouTube）是主流且被普遍理解的形态：合集是任何用户创建的、带名称的有序模板列表，附描述，默认私有，一键可发布，通过稳定 URL 分享。关注/订阅带来再参与但是 v2 的事。协作编辑很少见，不在范围内。

## 2. 问题陈述

Open Prompts 把每个模板当作孤立单元。找到 5 个好写作模板的用户无法把它们放在一起，发布 10 个相关模板的创作者也无法把它们作为一组呈现：

1. **没有分组。** 收藏和点赞是扁平、无组织的列表。有 40 个收藏模板的用户无法按项目或主题组织。
2. **没有可分享的集合。** 今天的分享意味着把单个模板公开。没有"这是我最好的 6 个邮件模板"的 URL。
3. **没有创作者橱窗。** 创作者的模板散落在广场各处；没有可以从简介、博客或社交帖子链接的"店铺"或策展集。
4. **集合没有发现界面。** 浏览仅按模板进行；合集作为浏览维度（像分类一样）不存在。
5. **上手缺口。** 新用户无法从其他用户的策展工作中受益 —— 这是低成本下最强的质量信号。

## 3. 目标用户

- **策展人（主要）:** 任何想把喜欢/使用的模板组织成命名集合（私有工作集）并可选发布的登录用户。
- **创作者:** 发布自己模板并想要可分享的"精选"或主题集来推广作品的用户。
- **浏览者:** 通过策展合集而非原始搜索发现优质模板的访客。
- **管理员:**（间接）合集是内容界面，管理员审核功能后续可以监管；v1 无管理员 UI。

## 4. 用户故事

### 4.1 创建与组织

- **US-C1:** 作为用户，我希望创建带名称和可选描述的合集，以便按项目或主题分组模板。
- **US-C2:** 作为用户，我希望从模板详情页或卡片把任何公开模板（或我自己的私有模板）加入合集，以便无论在哪里浏览都能一键收藏。
- **US-C3:** 作为用户，我希望从合集移除模板，以便合集保持最新。
- **US-C4:** 作为用户，我希望在合集中重排模板（拖拽或上移/下移），以便最重要的排在前面。
- **US-C5:** 作为用户，我希望我的合集默认私有，以便组织而不必发布。
- **US-C6:** 作为用户，我希望在一处看到我所有的合集，以便管理它们。

### 4.2 发布与分享

- **US-C7:** 作为策展人，我希望一键发布合集，以便它在稳定 URL 上公开可浏览。
- **US-C8:** 作为策展人，我希望取消发布（重新变为私有），以便不必删除即可下线一个集合。
- **US-C9:** 作为策展人，我希望通过复制链接按钮分享公开合集，以便随处张贴。
- **US-C10:** 作为访客，我希望打开分享的合集 URL 并看到合集名称、描述、策展人和模板网格，以便无需账号即可浏览使用。

### 4.3 发现

- **US-C11:** 作为访客，我希望在专属页面浏览公开合集，以便发现策展集合。
- **US-C12:** 作为访客，我希望看到合集计数（模板数、点赞数），以便判断受欢迎程度。

### 4.4 系统

- **US-C13:** 作为系统，我把私有模板排除在公开合集之外，以便发布合集绝不泄漏私有内容。
- **US-C14:** 作为系统，我限制每用户合集数（50）和每合集模板数（100），以便滥用与存储有界。

## 5. 功能需求

### 5.1 合集 CRUD

- **FR-1:** 登录用户应能创建合集：`name`（必填，1–80 字符）、`description`（可选，0–500 字符）、`visibility`（默认 `private` | `public`）。
- **FR-2:** 用户应能随时编辑自己合集的名称、描述和可见性。
- **FR-3:** 用户应能删除自己的合集（软删除；UI 需确认）。
- **FR-4:** 每用户最多 50 个合集；每合集最多 100 个模板（服务端强制，友好报错）。
- **FR-5:** 合集 URL 应稳定且不可猜测：`/collections/{id}`，id 为 UUID；重命名绝不改变 URL。

### 5.2 管理合集中的模板

- **FR-6:** 用户应能从以下位置把模板加入自己的一个或多个合集：(a) 模板详情页（"加入合集"按钮），(b) 首页网格卡片的悬停/溢出操作。
- **FR-7:** 用户可将任何公开模板或自己拥有的模板（含私有）加入合集。
- **FR-8:** 加入合集已含的模板是幂等无操作（不报错）。
- **FR-9:** 用户应能从合集移除模板（在合集页所有者视图中）。
- **FR-10:** 用户应能重排合集中的模板（上移/下移按钮；拖拽可选）。
- **FR-11:** 系统应为每个（合集, 模板）存储显式 `position`，以便排序在重新取数后保留。

### 5.3 可见性与分享规则

- **FR-12:** 私有合集仅对其所有者可见。
- **FR-13:** 公开合集对任何人在 `/collections/{id}` 可见（含匿名）。
- **FR-14:** 合集公开时，公开视图仅包含本身公开（或合集所有者拥有）的模板；所有者的私有视图显示全部成员，非公开的带"私有"徽章。
- **FR-15:** 若公开合集中的模板后来被其所有者（非策展人）设为私有，该模板从合集公开视图消失，但保留在策展人的私有视图中（带"不再公开"徽章）。
- **FR-16:** 删除模板自动将其从所有合集移除（级联）。
- **FR-17:** 合集页应提供"复制链接"操作（仅公开合集），将绝对 URL 复制到剪贴板。

### 5.4 发现

- **FR-18:** `/collections` 页面应列出公开合集：卡片网格含名称、描述摘录、策展人显示名、模板计数、封面拼贴（前 4 个模板卡片的颜色/首字母 —— v1 无图片上传）。
- **FR-19:** `/collections` 页面应支持按最新和最多模板排序（v1；复用 template-search-filtering 的搜索/排序是自然的后续）。
- **FR-20:** 侧栏应新增"合集"导航项（登录用户："我的合集"；所有用户："探索合集"），链接到各自视图。
- **FR-21:** 策展人的公开界面（v1：合集页头部）应链接到其其他公开合集（"来自 {策展人} 的更多"）。

### 5.5 API

- **FR-22:** 新 RPC（PromptService 或新 CollectionService —— 架构师决策）：`CreateCollection`、`UpdateCollection`、`DeleteCollection`、`GetCollection`（按 id；按可见性规则返回成员）、`ListMyCollections`、`ListPublicCollections`（分页、排序）、`AddTemplateToCollection`、`RemoveTemplateFromCollection`、`ReorderCollectionTemplates`、`ListCollectionsContainingTemplate`（用于"已在合集"指示）。
- **FR-23:** REST 端点位于 `/api/v1/collections`（列表/创建）、`/api/v1/collections/{id}`（获取/修改/删除）、`/api/v1/collections/{id}/templates`（添加/移除/重排）、`/api/v1/templates/{id}/collections`（我的哪些合集包含它）。公开合集允许匿名读；其余需认证。
- **FR-24:** `GetCollection` 响应应包含：id、name、description、visibility、所有者（id + display_name）、template_count、created_at、updated_at，以及成员（按 FR-14 规则的模板摘要）。
- **FR-25:** 所有变更操作强制所有权（非所有者 403）；私有合集的读返回 404（而非 403）以避免存在性泄漏。

### 5.6 普通用户与管理员划分

- **FR-26:** 合集是普通用户功能；v1 无管理员界面。合集的管理员审核（隐藏/封禁）是管理员功能的未来扩展；schema（D-1）包含 `status` 列以保持前向兼容。

## 6. 非功能需求

- **NFR-1（性能）:** ≤100 成员的合集页 p95 < 500ms；公开合集列表分页（20/页）。
- **NFR-2（一致性）:** 模板计数与成员列表在查询时从关联表读取（v1 无反规范化计数）；计数精确。
- **NFR-3（兼容性）:** 纯增量 schema/API；不改变既有端点；既有客户端不受影响。
- **NFR-4（隐私）:** 私有合集的存在不可发现（非所有者 404）；公开合集绝不包含他人的私有模板（FR-14/15）。
- **NFR-5（无障碍）:** 合集创建/编辑表单、加入合集菜单、重排控件和复制链接必须可键盘操作（见 UI/UX 文档 §10）。
- **NFR-6（国际化）:** 所有新增字符串 EN/ZH 同步；合集名称/描述是用户内容（不翻译）；UI 框架完全本地化。
- **NFR-7（安全）:** 每个变更操作服务端强制所有权；ID 是 UUID（不可猜测）；无注入面（参数化查询）。
- **NFR-8（规模）:** 关联表在 (collection_id, position) 与 (template_id) 上建索引；限制（FR-4）约束最坏情况规模。

## 7. 验收标准

- **AC-1:** 登录用户可创建私有合集，加入 3 个公开模板（其中一个自己的私有模板），并在所有者视图中看到全部 4 个，私有的带徽章。
- **AC-2:** 发布合集后，匿名浏览器可在 `/collections/{id}` 访问，仅显示公开模板（策展人自己的私有模板按 FR-14 包含）。
- **AC-3:** 加入公开合集的另一用户私有模板在其所有者设为私有后从公开视图消失，但保留在策展人的私有视图中并带徽章。
- **AC-4:** "复制链接"复制合集 URL；在全新匿名标签页打开显示该合集。
- **AC-5:** 重排（上移/下移）在刷新后保留。
- **AC-6:** 删除模板会将其从所有包含它的合集中移除。
- **AC-7:** 非所有者不能编辑、删除或变更合集（403），且不能读取私有合集（404）。
- **AC-8:** `/collections` 页面列出公开合集，含计数与策展人名，分页并按所选选项排序。
- **AC-9:** 模板详情页为登录用户显示"加入合集"操作，并标记我的哪些合集已包含它。
- **AC-10:** 限制被强制：创建第 51 个合集或添加第 101 个模板返回友好错误。
- **AC-11:** 所有新增 UI 字符串在 `en` 与 `zh` 翻译文件中存在且键集一致。
- **AC-12:** 既有模板浏览、点赞、收藏与 fork 流程不变（无回归）。

## 8. 范围外（v1）

- 关注/订阅合集（v2 参与功能）。
- 协作合集（多策展人）。
- 合集封面上传（v1 用生成的拼贴/首字母）。
- 合集点赞/评论。
- 合集搜索与完整筛选（后续从 template-search-filtering 复用）。
- 策展人主页（仅合集页上的"来自 {策展人} 的更多"链接）。
- 外部站点的可嵌入合集挂件。
- 合集导出（JSON/PDF）。
- 合集的管理员审核 UI（schema 通过 `status` 前向兼容）。
- 带预览卡的社交网络分享（og:image 生成）。
- 关注合集变更时的通知（尚无关注功能）。

## 9. 依赖与假设

- **D-1:** 新表：`collections`（id UUID PK, owner_id TEXT, name, description, visibility, status 默认 'active', created_at, updated_at）与 `collection_templates`（collection_id, template_id, position INT, added_at; PK (collection_id, template_id)）。索引：(collection_id, position)、(template_id)。按 deployment/init.sql 的幂等迁移模式。
- **D-2:** `users.display_name` 存在可用于策展人显示（schema 已确认）；若为空，回退到本地化的"匿名创作者"标签。
- **D-3:** 合集视图中的模板摘要复用既有 Template proto（title、description、tags、counts）—— 无需新投影。
- **D-4:** 加入合集选择器获取 `ListMyCollections`（≤50 行）—— 成本低；v1 选择器内无需搜索。
- **D-5:** `/collections` 与 `/collections/:id` 是新的前端路由；与既有路由无冲突。
- **D-6:** 复制到剪贴板使用 `navigator.clipboard` 并为旧浏览器提供回退（execCommand）；既有通知模式确认成功。
- **D-7:** 通过上移/下移按钮重排（FR-10）是可访问的基线；拖拽（HTML5 DnD）是可选润色 —— API 契约（position 列表）相同。
- **D-8:** 公开合集列表排序（FR-19）在服务端；分页遵循既有 page_token 模式。
