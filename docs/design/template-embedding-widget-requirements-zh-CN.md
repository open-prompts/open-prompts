# 模板嵌入挂件(Template Embedding Widget)— 需求分析

- **功能 ID:** template-embedding-widget
- **版本:** 1.0
- **状态:** 已提议(待架构评审)
- **作者:** ui-ux-agent
- **日期:** 2026-10-12

## 1. 竞品调研摘要

| 平台 | 嵌入方式 | 关键启示 |
|---|---|---|
| **GitHub Gist** | `<script src="...gist.js">` 内联渲染内容;每个 gist 都有嵌入代码 | 脚本嵌入是经典范式:宿主页面零依赖,内容始终最新 |
| **CodePen** | iframe 嵌入,支持主题/高度选项;每个作品都有 "Embed" 弹窗 | 带可复制代码 + 实时预览的嵌入弹窗是预期 UX;选项(主题、默认标签页)很重要 |
| **Stack Overflow** | "Share" 弹出层提供永久链接(Stack Snippet 可通过 iframe 嵌入) | 纯永久链接是分享的最小面;嵌入是升级 |
| **Hugging Face** | "Embed this model" 挂件:iframe 片段内含实时推理 UI | 嵌入*交互式*表面(而非仅静态文本)能带来最多回流流量 |
| **Reddit** | 通过 iframe 以挂件形式嵌入帖子 | 署名 + "查看原文" 回链是标准且被期待的 |
| **PromptBase** | 无嵌入(封闭市场) | 印证嵌入是社区/增长型功能,而非市场型功能 |

**综合结论:** 胜出范式是 GitHub Gist 式:为公开模板提供**只读可嵌入卡片**,由专用轻量嵌入路由提供服务,通过单个 `<script>` 标签注入(渲染 iframe 或直接渲染 shadow-DOM 卡片)。嵌入展示标题、描述、标签、内容预览、作者以及 "View on Open Prompts" 署名链接 —— 将每次外部提及转化为发现渠道。Open Prompts 已具备全部要素:公开模板数据、用于稳定版本固定的别名系统、REST 网关 —— 但除裸链接外没有任何对外分享面。

## 2. 问题陈述

1. **没有站外存在。** 模板完全活在站内。创作者在博客、文档或论坛回答中提及自己的提示词时,只能粘贴裸链接(或更糟:粘贴原始提示词文本,随后与源漂移)。
2. **内容漂移。** 用户在外部复制提示词文本后,模板的改进永远到不了这些副本。嵌入始终展示当前(或固定的)版本。
3. **没有增长回路。** 每个提供嵌入的竞品都将其视为首要获客渠道;Open Prompts 没有任何指向站内的外部表面。
4. **没有署名标准。** 外部副本不带作者署名、许可上下文或指向规范模板的链接。

## 3. 目标用户

- **创作者:** 希望在自己的网站/博客/文档中展示模板,且内容保持最新。
- **外部作者/博主:** 希望在文章中引用提示词,而不截图或粘贴会过时的文本。
- **宿主页面读者:** 看到干净、带品牌的卡片,并有通往完整模板的路径。
- **管理员:** 需要对滥用嵌入有可见性和开关(与其他公开表面的治理保持一致)。

## 4. 用户故事

### 4.1 创建嵌入

- **US-E1:** 作为创作者,我希望在公开模板详情页有 "Embed" 操作,以便获取可复制的嵌入代码。
- **US-E2:** 作为创作者,我希望将嵌入固定到特定版本(通过现有别名),以便在外部页面保持稳定的同时继续迭代。
- **US-E3:** 作为创作者,我希望嵌入弹窗中有主题(浅色/深色/自动)和布局(卡片/全文)选项,以便嵌入适配我的宿主页面。
- **US-E4:** 作为创作者,我希望弹窗中有嵌入的实时预览,以便确切知道将渲染什么。

### 4.2 宿主页面体验

- **US-E5:** 作为宿主页面访客,我希望嵌入快速渲染并展示标题、作者、描述、标签和内容预览,以便不离开页面就能理解模板。
- **US-E6:** 作为宿主页面访客,我希望有 "View on Open Prompts" 链接,以便打开完整模板。
- **US-E7:** 作为宿主页面所有者,我希望嵌入是单个无依赖的 script 标签,以便集成简单且安全。

### 4.3 治理

- **US-E8:** 作为管理员,我希望嵌入遵守模板可见性(私有模板永不可嵌入),以便隐私得到保障。
- **US-E9:** 作为管理员,我希望可以禁用特定模板的嵌入(治理),以便滥用内容无法在外部传播。
- **US-E10:** 作为系统,我永不为已删除或私有模板提供嵌入 —— 嵌入渲染 "模板不可用" 状态。

## 5. 功能需求

### 5.1 嵌入表面(公开、免登录)

- **FR-1:** 专用嵌入路由 `GET /embed/{templateId}`(常规前端,非 `/api`)应为**公开**模板渲染一个独立的、无应用外壳的页面:标题、作者(显示名 + 头像)、描述、标签、内容预览(前 ~500 字符,折叠并带 "展开更多")、以及指向 `/templates/{id}` 的 "View on Open Prompts" 链接。不出现主应用的页头/侧边栏/页脚。
- **FR-2:** 嵌入页面应接受查询参数:`theme`(`light`|`dark`|`auto`,默认 `auto` —— 跟随 `prefers-color-scheme`)、`layout`(`card`|`full`,默认 `card` —— `full` 渲染完整内容不做预览截断)、`version`(可选别名名 —— 渲染该别名固定的版本而非最新版)。
- **FR-3:** 嵌入页面应通过 CSP `frame-ancestors *` 实现 `X-Frame-Options: ALLOWALL` 语义(可被任意站点嵌入),而主应用保持现有框架策略。应发送 `Cache-Control: public, max-age=300` 以利于 CDN。
- **FR-4:** 非公开状态渲染友好的内联卡片:私有模板、已删除模板或嵌入被禁用 → "该模板不可用" 并附指向 Open Prompts 首页的链接。绝不在宿主 iframe 内渲染原始错误页。

### 5.2 嵌入代码生成(普通用户面)

- **FR-5:** 模板详情页应显示 `Embed` 操作(公开模板的所有者和任何查看者均可),打开嵌入弹窗:主题选择器、布局选择器、版本/别名选择器(默认 "最新")、实时预览 iframe(以当前选项指向嵌入路由)、以及生成的代码片段。
- **FR-6:** 生成的片段应为单个 script 标签:`<script async src="{origin}/embed.js/{templateId}?theme=…&layout=…&version=…"></script>`。加载脚本(`/embed.js/{id}`)注入响应式 iframe(以相同参数指向 FR-1 的路由),尺寸适配内容(card:固定最大宽度 480px;full:100% 宽度,高度通过 postMessage 自动调整)。
- **FR-7:** 弹窗应提供 "复制代码" 按钮(剪贴板 API 带降级方案)和一行纯永久链接备选("或使用链接")及模板 URL —— 供无法运行脚本的宿主使用。

### 5.3 加载脚本

- **FR-8:** `GET /embed.js/{templateId}` 应提供一个小的、可缓存的(max-age 3600)JavaScript 加载器:找到自身的 `<script>` 标签、创建 `loading="lazy"` 的 iframe、应用参数、监听嵌入页面通过 postMessage 发来的高度更新并相应调整 iframe 尺寸。无第三方依赖;压缩+gzip 后约 2 KB。
- **FR-9:** 嵌入页面应在加载时、"展开更多" 展开时、以及主题驱动的重排时,向其父窗口 postMessage 高度(对加载器来源做 origin 校验),以便 `full` 布局的 iframe 永不裁剪内容。

### 5.4 治理与管理

- **FR-10:** 嵌入对公开模板默认启用。`templates` 表新增 `embed_disabled`(BOOLEAN,NOT NULL,默认 false);所有者可在嵌入弹窗中切换("允许嵌入"),管理员可在 `/admin/templates/:id` 切换。
- **FR-11:** 当 `embed_disabled` 为 true 时,FR-1 渲染 "不可用" 卡片,FR-8 的加载器仍可工作(渲染同样的不可用状态)—— 宿主看到优雅降级,而非损坏的脚本。
- **FR-12:** 管理端模板详情页应显示嵌入状态(启用/禁用)及切换开关,管理控制台应将切换记录到审计日志(`action='toggle_embed'`,禁用时原因可选)。
- **FR-13:** 嵌入页面浏览量应与常规模板浏览量分开统计(独立计数器,或按 prompt-analytics 设计在现有浏览事件上增加来源维度),以便创作者衡量嵌入流量。

## 6. 非功能需求

- **NFR-1(安全):** 嵌入路由仅提供公开模板数据 —— 无邮箱、无除显示名/头像外的所有者 PII。加载脚本是静态、无依赖的,不能执行宿主页面代码。嵌入页面为自身内容设置严格 CSP;用户内容按现有规则以转义文本渲染。postMessage 目标做 origin 校验。
- **NFR-2(性能):** 嵌入页面是独立的轻量路由(不含主应用包):目标 < 50 KB JS(或服务端渲染 + 水合),冷 iframe 首次内容绘制 < 1 秒。加载器约 2 KB 且可缓存。
- **NFR-3(隐私):** 嵌入路由不要求认证 cookie(完全公开);可不设置任何 cookie。除聚合浏览计数(FR-13)外无追踪。
- **NFR-4(国际化):** 嵌入页面按模板语言上下文渲染;界面文案(View on Open Prompts、展开更多、不可用状态)提供 `en` 和 `zh`,由模板 `language` 字段决定并支持 `?lang=` 覆盖。
- **NFR-5(无障碍):** 嵌入页面是带 landmark 的真实文档,两种主题下均有可读对比度;加载器创建的 iframe 带有描述性 `title`。
- **NFR-6(韧性):** 嵌入 API 失败时,嵌入页面渲染不可用卡片(绝不空白 iframe)。加载器失败则静默降级(宿主页面不受影响)。
- **NFR-7(兼容性):** 嵌入可在任何允许 iframe/脚本的宿主(博客、文档站、类 Notion 工具)上工作。永久链接备选覆盖禁脚本的宿主。

## 7. 验收标准

- **AC-1:** 公开模板详情页显示 `Embed`;弹窗实时预览卡片,并生成反映所选主题/布局/版本选项的可用单脚本片段。
- **AC-2:** 将片段粘贴到纯 HTML 页面后渲染嵌入卡片:标题、作者、描述、标签、内容预览、以及可用的 "View on Open Prompts" 链接。
- **AC-3:** `full` 布局渲染完整内容,iframe 在加载和 "展开更多" 时自动调整尺寸(无裁剪、无内部滚动条)。
- **AC-4:** `theme=auto` 跟随宿主页面的 `prefers-color-scheme`;`light`/`dark` 强制主题;两者均满足对比度要求。
- **AC-5:** 以 `version={alias}` 嵌入时渲染该别名固定的版本;之后编辑模板不会改变嵌入内容。
- **AC-6:** 私有、已删除、嵌入被禁用的模板在 iframe 中渲染 "不可用" 卡片 —— 绝不渲染错误页,绝不渲染内容。
- **AC-7:** 所有者可在弹窗中切换 "允许嵌入";管理员可在 `/admin/templates/:id` 切换;禁用立即生效(嵌入路由 + 加载器均显示不可用)且管理操作被审计。
- **AC-8:** 嵌入页面浏览量与常规浏览量分开统计,并作为来源维度展示在分析仪表板(如已上线)中,或至少以独立方式记录。
- **AC-9:** 嵌入路由不提供 cookie 和 PII;响应携带 CSP `frame-ancestors *`,而主应用的框架策略保持不变。
- **AC-10:** 加载脚本 gzip 后 ≤ 5 KB、无依赖,并懒加载 iframe。
- **AC-11:** 嵌入界面文案在 `en` 和 `zh` 中正确渲染(由模板语言驱动并支持 `?lang=` 覆盖);两种主题均正确渲染。
- **AC-12:** 嵌入 API 宕机时,包含片段的宿主页面显示不可用卡片(而非空白框);宿主页面本身不受影响。

## 8. 不在范围内(v1)

- 交互式嵌入(在嵌入内运行提示词/填写变量)。
- 超出浅色/深色/自动主题的自定义品牌/配色。
- 超出浏览计数之外的宿主页面嵌入分析(来源细分)。
- oEmbed/OpenGraph 自动嵌入协议支持。
- 通过签名令牌嵌入私有模板。
- 合集/多模板嵌入。
- WordPress 插件/专用 SDK。
- 署名链接上的点击归因(UTM 参数)—— 可后续添加。
- 区别于公开模板端点的独立限流(嵌入共享公开读取路径)。
- 任何与变现相关的功能(按项目范围规则)。

## 9. 依赖与假设

- **D-1:** 公开模板读取 API 已存在(公开模板的 `GET /api/v1/templates/{id}` 可匿名访问);嵌入路由在服务端或客户端复用相同的服务调用。
- **D-2:** 别名系统(`template_aliases`、`GetPromptByAlias`)提供稳定的版本固定;FR-2 的 `version` 参数将别名名解析为其 `version_id`。
- **D-3:** prompt-analytics 设计(尚未上线)定义了带来源维度的浏览追踪;FR-13 与之对齐。若分析尚未上线,浏览以带来源字段的方式记录以便未来聚合。
- **D-4:** 前端是与 API 网关同源的 React SPA;嵌入路由是排除在主 Layout 之外的新 SPA 路由,或独立的轻量入口 —— 由架构师选择(见开放问题)。
- **D-5:** 管理控制台的模板详情页与审计日志模式(切换 + 原因 + 审计行)来自 admin-user-management/comments 功能;FR-12 复用它们。
- **D-6:** CSP/框架头可在网关/反向代理层(部署中的 nginx/ingress)配置;嵌入路由需要自己的响应头策略。

## 10. 给架构师的开放问题

1. **嵌入页面交付方式:** 独立轻量 SPA 入口(推荐 —— 包体小、响应头独立)vs. 主应用内排除外壳的条件路由 vs. Go 网关服务端渲染。哪种最契合部署?
2. **加载器托管:** 网关在 `/embed.js/{id}` 提供静态文件(推荐 —— 同源、按 id 传参)vs. 读取 `data-template` 属性的通用 `/embed.js`。倾向哪种?
3. **浏览计数:** 复用分析设计的浏览事件并加 `source=embed`(若分析先上线则推荐)vs. 独立 `embed_view_count` 列。请确认。
4. **`embed_disabled` 切换权限:** 所有者 + 管理员均可(我的提案)vs. 仅管理员。同时确认管理员禁用是否需要原因(与其他管理操作的审计保持一致)。
