# 模板变现 — 需求分析

- **功能标识:** template-monetization
- **版本:** 1.0
- **状态:** 已提案（待架构评审）
- **作者:** ui-ux-agent
- **日期:** 2025-06-25

## 1. 竞品研究摘要

| 平台 | 变现方式 | 关键启示 |
|---|---|---|
| **PromptBase** | 完整市场：卖家为提示词定价（典型 $0.99–$9.99），买家购买后获得内容；PromptBase 抽成（历史约 30%）；卖家收益看板；精选推荐位 | 固定价 listing 是被验证的核心；内容在购买前被门控；卖家收益看板是标配；策展/推荐位驱动销量 |
| **FlowGPT** | 免费 + 创作者变现实验（打赏、付费创作者等级）；大部分内容免费；变现次于社区增长 | 免费优先的平台难以按条收费；打赏在不门控内容的情况下回报创作者 |
| **Snack Prompt** | 免费社区；变现刚起步（创作者支持、徽章） | 基于参与度的奖励（徽章/打赏）适合没有支付通道的平台 |
| **AIPRM** | 订阅 SaaS：免费层 + 付费计划解锁高级提示词/功能；提示词本身是订阅的引流品 | 平台自身是产品时订阅制有效；创作者是产品时按条销售有效 |
| **PromptHero** | 免费浏览；通过课程/广告变现，不做按条销售 | 按条销售需要信任信号（评价、预览）和支付机制 |
| **通用（Gumroad / Etsy / 图库市场）** | 固定价数字商品：预览 → 购买 → 即时交付；平台抽成；卖家看板 | 通用模式：门控预览、一键购买、即时获得、卖家收益视图 |

**综合分析:** 存在两种可行模式：(a) 按 listing 固定价市场（PromptBase/Gumroad）和 (b) 平台订阅（AIPRM）。对于 Open Prompts —— 一个以个人创作者为主的社区提示词广场 —— 按 listing 的市场模式契合现有产品形态（模板是离散的、可拥有的、带版本的对象），且不需要订阅计费基础设施。v1 范围：创作者为自己的公开模板设定固定价格；买家用账户余额（钱包）购买；内容在购买前被门控。真实资金提现和外部支付服务商（Stripe 等）明确不在范围内 —— v1 使用模拟钱包，使完整产品面（定价、门控、购买、已购库、收益）可以端到端交付并测试，并为未来接入真实支付服务商留下清晰接缝。

## 2. 问题陈述

Open Prompts 完全没有变现能力：没有价格、没有购买、没有收益。发布高质量模板的创作者无法获得回报，平台也无法奖励或呈现优质内容：

1. **创作者无回报。** 点赞和收藏是仅有的反馈；没有经济激励去发布打磨过的、生产级的模板。
2. **没有优质内容层级。** 每个公开模板都是免费的；即使买家愿意，也无法为更高质量、持续维护、带版本的提示词付费。
3. **没有购买流程。** 没有结账、没有"我买过的提示词"库视图、没有许可/授权模型来门控内容。
4. **没有收益可见性。** 创作者看不到销量、收入、哪些模板在赚钱。
5. **没有市场发现维度。** 浏览时无法筛选"付费 vs 免费"，也无法呈现优质内容。

## 3. 目标用户

- **卖家（主要）:** 发布公开模板并希望对访问收取固定价格的创作者。
- **买家:** 发现优质模板值得用钱包余额购买、并希望即时永久访问的用户。
- **浏览者:** 需要在浏览时看到清晰价格信号（免费 vs 付费、价格），并在决策前看到门控预览的用户。
- **管理员:** 通过管理控制台监督市场健康度（listing、定价滥用、退款）—— v1 仅最小界面（见 FR 拆分）。

## 4. 用户故事

### 4.1 出售（创作者）

- **US-M1:** 作为创作者，我想为自己的公开模板设定价格，使买家必须付费才能访问内容。
- **US-M2:** 作为创作者，我想之后修改或取消价格，以便做促销或转为免费。
- **US-M3:** 作为创作者，我想看到每个模板和总计的收益，以便了解什么好卖。
- **US-M4:** 作为创作者，我想看到购买动态（谁买的、何时），以便了解我的受众。
- **US-M5:** 作为创作者，我希望调价前的购买者保留访问权，使购买是永久的。

### 4.2 购买

- **US-M6:** 作为买家，我想为钱包充值，以便购买模板。
- **US-M7:** 作为买家，我想在购买前看到价格和门控预览，以便知道自己在买什么。
- **US-M8:** 作为买家，我想一键购买，使访问是即时的。
- **US-M9:** 作为买家，我想把我购买的模板集中在一个库视图里，以便随时回来使用。
- **US-M10:** 作为买家，我想像使用自有模板一样使用已购模板（填变量、使用、fork），使购买解锁完整功能。

### 4.3 浏览与系统

- **US-M11:** 作为浏览者，我想在卡片和列表上看到免费/付费徽章和价格，以便分配注意力。
- **US-M12:** 作为系统，我必须绝不向未购买者暴露付费内容（列表端点、详情端点、别名、API key），使门控无懈可击。
- **US-M13:** 作为系统，我希望购买是幂等且原子的，使双击和重试绝不会重复扣款或授予部分访问权。

## 5. 功能需求

### 5.1 定价（创作者）

- **FR-1:** 模板所有者可为自己的模板设定价格：`price_cents`（整数，0 = 免费，允许范围 99–9900 即 $0.99–$99.00），v1 货币固定为 USD。
- **FR-2:** 只有公开模板可以定价；为私有模板定价返回错误（私有模板没有可门控的内容）。
- **FR-3:** 所有者可随时改价；已有购买不受后续调价或转免费影响，保留访问权（FR-4）。
- **FR-4:** 所有者可随时把价格设回 0（免费）；模板对所有人自由开放。
- **FR-5:** 调价立即生效；v1 无审批流程。

### 5.2 钱包与充值

- **FR-6:** 每个用户有一个钱包：`balance_cents`（整数，≥ 0），单一货币（USD），首次访问时懒创建。
- **FR-7:** 用户通过模拟充值流程为钱包充值：选择预设金额（$5 / $10 / $20）或输入自定义金额（$1–$500），确认后即时到账。v1 记录一条类型为 `topup` 的 `wallet_transactions`（source 为 `simulated`）；不接入真实支付服务商。
- **FR-8:** 钱包余额显示在头部（已登录用户）和钱包页，钱包页含交易历史（充值、购买、收益、退款）分页展示。
- **FR-9:** 钱包交易只追加；余额由交易账本（贷方合计减借方）推导并缓存在钱包行上以便快速读取。

### 5.3 购买

- **FR-10:** 已登录用户可购买自己未拥有的定价模板：系统检查余额 ≥ 价格，扣减买家、贷记卖家（扣除平台佣金，FR-14）、创建 `purchases` 授权行、记录两条 `wallet_transactions`（买家借记、卖家贷记）—— 在一个数据库事务中原子完成。
- **FR-11:** 购买幂等：购买已拥有的模板是无操作并返回成功（不重复扣款）；并发重复购买由 (buyer_id, template_id) 唯一约束防止。
- **FR-12:** 所有者自动"拥有"自己的模板（不能自购）；fork 副本是新模板，不继承价格（fork 者可自行定价）。
- **FR-13:** 购买授予永久访问：查看完整内容、带变量使用、fork、加入合集、API key 实例化 —— 与拥有完全一致，除了买家不能编辑原模板、也看不到最新发布版本之外的版本历史（v1 简化；见 D-6）。

### 5.4 收益与佣金

- **FR-14:** 平台对每笔购买收取可配置佣金（默认 20%，环境变量 `MARKETPLACE_COMMISSION_BPS`，如 2000）；卖家获得剩余部分。佣金记录在购买行上。
- **FR-15:** 卖家可查看收益：总收益、每个模板的收益（销量、毛收入、净收入）和最近销售动态 —— 在工作区的"收益"标签页。
- **FR-16:** 收益贷记卖家钱包余额，可用于购买其他模板（v1 无提现 —— D-3）。

### 5.5 门控（内容保护）

- **FR-17:** 对定价模板，未购买者（含匿名用户）可见：标题、描述、标签、分类、语言、点赞/收藏数，以及最新版本内容前 200 字符的预览（服务端截断，带 `preview_truncated: true`）。
- **FR-18:** 定价模板的完整内容只返回给：所有者、购买者和管理员。这适用于所有读取路径：`GetTemplate`、`ListTemplates`（内嵌的 `latest_version.content` 必须对未购买者脱敏）、`GetPromptByAlias`（API key 路径）和版本历史（未购买者只看到最新版本的门控预览，看不到历史版本）。
- **FR-19:** 定价模板的 fork 仅允许所有者/购买者（fork 需要看到内容）；fork 产物是全新的私有模板，价格为 0。
- **FR-19a（管理员拆分）:** 管理员为审核可查看任何模板的完整内容（管理 API 在 admin-user-management 功能中定义；本功能只要求管理员角色检查存在 —— D-7）。

### 5.6 发现与 UI 界面

- **FR-20:** PromptCard 和列表行为定价模板显示价格徽章（如 "$4.99"），为免费模板显示 "Free" 徽章；首页网格筛选栏增加"价格"筛选（全部 / 免费 / 付费）。
- **FR-21:** 对定价模板的未购买者，模板详情页显示：带模糊/锁定遮罩的门控预览、价格、"购买"按钮（余额不足时禁用并显示原因）、充值入口。
- **FR-22:** 购买者（和所有者）看到正常详情页（完整内容、变量表单、使用/fork 操作）。
- **FR-23:** "已购"库视图位于 `/dashboard/purchased`，列出用户购买的模板（卡片网格、购买日期、支付价格），链接到详情页。

### 5.7 API

- **FR-24:** 新 RPC：`SetTemplatePrice`、`GetWallet`、`TopUpWallet`、`ListWalletTransactions`、`PurchaseTemplate`、`ListPurchasedTemplates`、`GetEarnings`（卖家总计 + 按模板 + 最近销售）。REST 端点：`PATCH /api/v1/templates/{id}/price`、`GET /api/v1/wallet`、`POST /api/v1/wallet/topup`、`GET /api/v1/wallet/transactions`、`POST /api/v1/templates/{id}/purchase`、`GET /api/v1/templates/purchased`（或 `/api/v1/purchases`）、`GET /api/v1/earnings`。
- **FR-25:** `GetTemplate`/`ListTemplates` 响应增加 `price_cents`、`is_purchased`（对当前调用者）、`preview_truncated` 字段；`latest_version.content` 按 FR-18 脱敏。忽略新字段的既有客户端不受影响。
- **FR-26:** 所有资金操作（充值、购买）是原子数据库事务，对钱包行加行级锁（SELECT ... FOR UPDATE）以防止并发下的丢失更新。
- **FR-27:** 购买退款（管理员发起）反转账本条目并撤销授权 —— 管理界面推迟到管理功能；schema 已支持（D-4）。

### 5.8 普通用户 vs 管理员拆分

- **FR-28:** 普通用户：定价、钱包、购买、已购库、收益（本功能）。管理员：市场监督（按 FR-19 查看任何 listing 的完整内容、按 FR-27 退款、强制冻结 listing）—— 这些的管理 UI 属于 admin-user-management 功能的控制台；本功能只提供使退款成为可能的底层授权/账本设计。本功能不构建任何管理页面。

## 6. 非功能需求

- **NFR-1（性能）:** 购买 p95 < 300ms；钱包/收益页 p95 < 500ms；带价格徽章的卡片网格不增加额外往返（价格随既有列表响应返回）。
- **NFR-2（完整性）:** 所有余额变动通过只追加账本 + 数据库事务；余额始终可由账本重算并对账（对账作业是后续工作，不在 v1）。
- **NFR-3（安全）:** 门控在每条读取路径上由服务端强制执行（FR-18）；客户端绝不会收到未购买者的完整内容；不存在仅客户端的门控。
- **NFR-4（兼容性）:** 仅增量 schema/API；既有端点增加可选字段；既有客户端不受影响。免费模板行为与今天完全一致（价格 0 = 不门控、除 "Free" 外无徽章）。
- **NFR-5（无障碍）:** 购买/充值流程、价格徽章、锁定遮罩可键盘操作且对屏幕阅读器友好（见 UI/UX 文档 §10）。
- **NFR-6（国际化）:** 所有新字符串 EN/ZH 同步；价格按 locale 格式化（如 $4.99 / 4.99 美元）；UI 框架完全本地化。
- **NFR-7（规模）:** `purchases` 在 (buyer_id, purchased_at) 和 (template_id) 上建索引；`wallet_transactions` 在 (wallet_id, created_at) 上建索引；账本只追加增长（分区是未来课题）。
- **NFR-8（可审计）:** 每笔资金流动都有账本行，含类型、金额、对手方和引用（购买 id / 充值 id）；管理员退款操作可追溯。

## 7. 验收标准

- **AC-1:** 创作者为公开模板设定 $4.99；卡片显示 "$4.99" 徽章；免费模板显示 "Free"。
- **AC-2:** 匿名用户打开定价模板详情页，只看到 200 字符预览和锁定遮罩；任何路径（详情、列表、别名）的 API 响应都不含完整内容。
- **AC-3:** 余额 $10 的已登录买家一键购买 $4.99 模板；余额变为 $5.01；详情页显示完整内容；模板出现在 `/dashboard/purchased`。
- **AC-4:** 卖家余额增加 $3.99（20% 佣金）；其收益标签页显示 1 笔销售、毛收入 $4.99、净收入 $3.99。
- **AC-5:** 再次购买同一模板是无操作（不扣款、返回成功）。
- **AC-6:** 创作者把价格改为 $9.99 再改为免费；早先的买家保留访问权；免费后所有人可查看内容。
- **AC-7:** 余额不足的买家看到禁用的购买按钮及差额和充值链接；充值 $5 后购买成功。
- **AC-8:** 首页网格"价格"筛选（全部/免费/付费）只返回匹配的模板。
- **AC-9:** 未购买者对定价模板的 fork 尝试被拒绝；购买者的 fork 创建一个私有的免费副本。
- **AC-10:** 钱包页按时间倒序分页列出交易（充值、购买借记、销售贷记），头部显示可用余额。
- **AC-11:** 同一用户并发购买同一模板只产生一笔扣款（唯一约束 + 幂等）。
- **AC-12:** 所有新 UI 字符串在 `en` 和 `zh` 翻译文件中存在且键集一致；价格在两个 locale 下正确渲染。
- **AC-13:** 既有免费模板流程（浏览、点赞、收藏、使用、fork、别名、API key）不变（无回归）。

## 8. 不在范围内（v1）

- 真实支付服务商（Stripe/支付宝/微信支付）和真实资金提现 —— 钱包是模拟的（充值 source 为 `simulated`）；账本设计是未来接入服务商的接缝。
- 订阅层级 / 平台计划（AIPRM 模式）—— 待按条销售验证后再考虑。
- 随心付 / 打赏（FlowGPT 式）。
- 购买发票/收据（PDF）和税务处理。
- 已购模板的评价/评分（信任面留给后续迭代）。
- 精选/推广 listing 和市场策展页。
- 管理控制台中的退款 UI（schema 支持；UI 随管理功能推迟）。
- 多货币支持（仅 USD）。
- 销量/毛收入/净收入之外的卖家分析（漏斗、转化）。

## 9. 依赖与假设

- **D-1:** 新表：`wallets`（id UUID PK，user_id UNIQUE，balance_cents INT 默认 0，currency 'USD'，created_at，updated_at）、`wallet_transactions`（id UUID PK，wallet_id，type 类枚举 TEXT ['topup','purchase_debit','sale_credit','refund']，amount_cents INT 有符号，balance_after INT，counterparty_user_id 可空，reference_id 可空（购买/充值 id），source TEXT 可空，created_at）、`purchases`（id UUID PK，buyer_id，template_id，price_cents，commission_bps，seller_net_cents，status 'active'|'refunded'，created_at；在 status='active' 上对 (buyer_id, template_id) 建部分唯一索引）、不使用 `template_prices` 表：价格作为 `templates.price_cents INT 默认 0` 列（单一事实来源，一列即可，既有查询不受影响）。
- **D-2:** 钱包懒创建（首次 GET /wallet 或首次购买/充值时创建）；无需迁移回填。
- **D-3:** 收益是可消费余额（v1 无提现）；带类型 `refund` 和引用 id 的 `wallet_transactions` 账本使未来的提现/退款可反转。
- **D-4:** 退款（管理员）用补偿行反转账本条目并将购买状态置为 'refunded' —— 授权撤销；买家不再保留访问权。UI 推迟到管理功能。
- **D-5:** 预览截断（FR-17）在服务端对最新版本内容截 200 字符；`preview_truncated: true` 通知客户端渲染锁定遮罩。
- **D-6:** v1 中购买者只看到定价模板的最新版本（不是完整历史）—— 简化门控逻辑；购买者的版本历史是后续工作。
- **D-7:** 管理员角色检查按 admin-user-management 功能存在（users 上的角色）；本功能的门控在需要处检查 `role == 'admin'`（FR-19）。若管理功能后落地，在此之前门控把所有人视为非管理员（优雅降级）。
- **D-8:** 佣金默认 20%，通过 `MARKETPLACE_COMMISSION_BPS` 环境变量（2000 bps）；按购买记录，使历史销售不随环境变量变化而漂移。
- **D-9:** 首页网格"价格"筛选（FR-20）映射为 ListTemplates 的新 `pricing` 筛选参数（`all`|`free`|`paid`）—— 与 template-search-filtering 功能的参数模式一致。
- **D-10:** `/dashboard/purchased` 扩展 user-dashboard 功能的工作区；若该功能未落地，此路由独立可用（只需要 ListPurchasedTemplates）。
