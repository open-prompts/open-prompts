# 键盘快捷键与命令面板 — 需求分析

- **功能 ID：** keyboard-shortcuts
- **版本：** 1.0
- **状态：** 已提案（待架构评审）
- **作者：** ui-ux-agent
- **日期：** 2026-10-12

## 1. 竞品调研总结

| 平台 | 快捷键 / 命令方式 | 关键启示 |
|---|---|---|
| **GitHub** | `s` 聚焦搜索、`/` 搜索、`g`+`d` 跳转仪表盘序列、`?` 快捷键速查表 | 最高频动作用单键；可发现的 `?` 浮层是参考模式 |
| **Notion** | cmdk 命令面板（`Cmd/Ctrl+K`）：搜索页面、执行操作、插入块；完整快捷键映射 | 面板是万能出口 —— 每个操作都能从一个输入框到达；比记忆按键更具扩展性 |
| **Slack** | `Cmd/Ctrl+K` 跳转会话；`?` 浮层；导航序列 | 面板用于*导航*，单键用于*操作* —— 清晰的分工 |
| **Gmail** | `c` 写信、`j/k` 列表导航、`x` 选择、`Enter` 打开 | `j/k` 列表导航是任何列表界面的高级用户预期 |
| **Linear** | cmdk 面板作为主界面；每个路由和操作都可用命令寻址 | 面板优先的产品证明命令可以承载整个应用；我们仅将其用于导航 + 顶级操作 |
| **PromptBase / FlowGPT / Snack Prompt** | 无键盘快捷键或面板 | 提示词平台在此落后 —— 面向高级用户的差异化机会 |

**综合分析：** 两个互补层次，均已被验证：(1) **命令面板**（`Cmd/Ctrl+K`）用于导航和顶级操作 —— 搜索模板、跳转页面、创建模板、切换主题/语言；(2) 特定界面上的一小组**单键快捷键** —— `s`/`/` 聚焦搜索、`j/k` 在模板网格中移动、`?` 打开快捷键速查表。无障碍设计（已提交）使每个控件*可键盘操作*（Tab/Enter/方向键）；本功能在可操作性之上增加*速度*。一切都是可选且不阻塞的：输入时任何快捷键不触发，且所有快捷键都有可见的 UI 等价物。

## 2. 问题陈述

1. **每个操作都是一次鼠标往返。** 到达搜索、创建模板或切换页面需要指针导航；高级用户每次访问都能感受到摩擦。
2. **速度特性不可发现。** 即使存在键盘可操作性（按无障碍设计），也没有速查表，没有提示存在快速路径。
3. **界面规模增长需要通用跳转框。** 随着 17+ 个已设计功能（合集、链、团队、试验场、用量、仪表盘、通知），通过侧边栏跳页不可扩展；面板是标准答案。
4. **竞品忽视键盘用户。** 提示词平台今天全是鼠标操作；服务键盘优先用户（开发者、重度提示词用户）是差异化点。

## 3. 目标用户

- **高级用户 / 重度提示词用户：** 每天浏览和打开数十个模板；从 `j/k` + 面板获益最多。
- **使用 API 工作流的开发者：** 在试验场、用量、API 密钥、模板详情之间跳转。
- **键盘优先和辅助技术用户：** 无障碍设计已提供*可操作性*；本功能增加效率。
- **管理员：** 管理控制台内的快速跳转（面板限定在管理路由内）。

## 4. 用户故事

- **US-K1：** 作为高级用户，我可以在任何地方按 `Cmd/Ctrl+K` 打开命令面板，无需鼠标即可搜索模板并跳转到任何页面。
- **US-K2：** 作为用户，我可以按 `?` 查看所有快捷键的速查表，不用离开页面就能学习它们。
- **US-K3：** 作为用户，我可以按 `s` 或 `/` 聚焦搜索框，让搜索只需一次按键。
- **US-K4：** 作为浏览用户，我可以按 `j`/`k` 在模板网格中移动选择并按 `Enter` 打开选中的卡片，无需鼠标即可浏览。
- **US-K5：** 作为用户，我可以在主页按 `c` 打开创建模板弹窗，让创建瞬间完成。
- **US-K6：** 作为用户，我可以按 `t` 切换主题（非输入状态），让明暗切换立即完成。
- **US-K7：** 作为用户，我可以按 `Esc` 关闭任何面板/浮层，随时可以退出。
- **US-K8：** 作为用户，我可以在快捷键触发的 UI 元素上看到提示（tooltip），让快捷键在上下文中可发现。
- **US-K9：** 作为管理员，我可以在 `/admin` 内打开面板并获得管理范围的命令（跳转用户/模板/审计日志），让控制台也快起来。
- **US-K10：** 作为不喜欢快捷键的用户，我可以忽略这一切并像以前一样使用产品，没有任何东西强加于我。

## 5. 功能需求

### 5.1 命令面板

- **FR-1：** 全局面板通过 `Cmd/Ctrl+K` 打开（以及头部搜索框的入口：点击搜索框的 `⌘K` 标签打开面板）。渲染为居中弹窗，含单个文本输入框。
- **FR-2：** 面板命令来源（合并、排序）：
  - **导航：** 当前用户可访问的所有顶级路由（主页、个人资料、API 密钥、通知、我的团队、合集、链、试验场、用量、仪表盘、管理员控制台（仅管理员）；未登录时为登录/注册）。
  - **模板搜索：** 防抖（250 毫秒）查询既有模板搜索 API；结果显示名称 + 分类，Enter 打开模板。
  - **操作：** 创建模板（`c`）、切换主题、切换语言（EN/中文）、创建团队、创建合集（按上下文）。
- **FR-3：** 面板交互：方向键移动活动行，`Enter` 执行，`Esc` 关闭，`Tab` 被捕获在内部，关闭时焦点返回打开者。鼠标点击同样执行。空查询显示"快速链接"（前 5 个导航项 + 最近模板）。
- **FR-4：** 面板结果分组（导航 / 模板 / 操作）并带组标题；活动行滚动到可见区域；最多 12 行可见，内部滚动。
- **FR-5：** 在 `/admin/*` 内，面板限定范围：导航命令列出管理页面（仪表盘、用户、模板、团队、审计日志）加"返回应用"；模板搜索替换为管理端模板搜索；包含用户搜索（按 ID/邮箱，仅管理员）。

### 5.2 单键快捷键

- **FR-6：** `s` 和 `/` 聚焦页面的主搜索输入框（主页搜索、管理端列表搜索）。若页面没有搜索输入框，该键无效。
- **FR-7：** `j`/`k` 在当前模板网格（主页、合集、团队、链模板、搜索结果）中移动可视选择光标：`j` 下一个、`k` 上一个、`Enter` 打开、`o` 也可打开（Gmail 惯例）。选择用既有的焦点环样式指示；选中卡片滚动到可见区域。光标在第一次按 `j`/`k` 前隐藏。
- **FR-8：** `c` 在有创建模板弹窗的界面（主页、团队主页）打开该弹窗；其他界面无效。
- **FR-9：** `t` 切换明暗主题；`?`（Shift+/）打开快捷键速查表弹窗。两者均为全局。
- **FR-10：** **防护规则：** 当焦点在文本输入框、textarea 或 contenteditable 元素中，或弹窗打开时（`Esc` 和面板内部按键除外），任何单键快捷键不触发。`Esc` 关闭最顶层浮层（面板、速查表、创建弹窗、任何既有弹窗）—— 一个一致的行为。

### 5.3 可发现性

- **FR-11：** `?` 速查表弹窗以两列表格（按键 — 操作）列出所有快捷键，分组（全局 / 浏览 / 面板），底部链接到文档页面。可从头部用户下拉（"键盘快捷键"）和面板（"帮助：键盘快捷键"）到达。
- **FR-12：** 头部搜索框（`s`）、主题切换（`t`）、创建按钮（`c`）的 tooltip 以标准 `key` 标签样式显示其快捷键。
- **FR-13：** 首次提示：用户第 3 次会话后，主页显示一次性可关闭 toast"按 `?` 查看键盘快捷键"（按用户偏好存储，`localStorage`）。

### 5.4 API

- **FR-14：** 无新增后端端点。面板复用既有模板搜索 API 和当前用户/会话状态。（管理端用户搜索复用既有管理用户 API。）

### 5.5 管理端

- **FR-15：** 所有快捷键在管理控制台中生效并带范围限定行为（FR-5、FR-6）；`j`/`k` 适用于管理端列表表格（用户、模板、团队），`Enter` 打开该行的详情视图。速查表反映当前范围。

## 6. 非功能需求

- **NFR-1（性能）：** 面板打开 < 100 毫秒（打开时不拉取数据；快速链接是静态的）；模板搜索结果在防抖后 < 300 毫秒渲染。
- **NFR-2（不干扰）：** 从不按键的用户零行为变化；所有快捷键是增量的，且每个快捷键都有可见的 UI 等价物。
- **NFR-3（无障碍）：** 面板遵循 ARIA 1.2 combobox/listbox 模式（role=dialog、aria-activedescendant）；速查表是标准弹窗；快捷键绝不覆盖浏览器或屏幕阅读器保留键；所有新 UI 按无障碍设计完全可键盘操作。
- **NFR-4（国际化）：** 所有面板标签、组标题、速查表文案、tooltip 通过 i18next（`shortcuts.*`、`palette.*` 命名空间）提供 EN/ZH；快捷键*按键*与语言无关。
- **NFR-5（可测试性）：** 快捷键映射是单一声明式配置（键 → 处理器，按路由限定范围），单元测试覆盖每个绑定；手动冒烟脚本扩展无障碍键盘测试。
- **NFR-6（一致性）：** 视觉语言（弹窗、焦点环、按键标签）复用 Aurora 设计系统；不引入新视觉习惯。

## 7. 验收标准

- **AC-1：** `Cmd/Ctrl+K` 在每个页面（登录和未登录）打开面板；输入 "prof" 显示个人资料导航项；Enter 导航。
- **AC-2：** 在面板中输入模板名称，300 毫秒内（防抖后）返回匹配模板；Enter 打开模板详情页。
- **AC-3：** 方向键移动面板活动行；`Esc` 关闭并将焦点返回打开者；Tab 保持在内部。
- **AC-4：** 在 `/admin` 中，面板列出管理页面和管理端用户搜索；除"返回应用"外不列出面向用户的页面。
- **AC-5：** `s` 聚焦主页搜索框；随后输入正常工作（输入时不触发快捷键）。
- **AC-6：** `j`/`k` 在主页网格中移动可见选择；`Enter` 打开选中的模板；选择滚动到可见区域。
- **AC-7：** `?` 打开列出所有快捷键的速查表；`Esc` 关闭；也可从用户下拉和面板到达。
- **AC-8：** `t` 切换主题；`c` 在主页打开创建弹窗；输入框聚焦或弹窗打开时两者均无效。
- **AC-9：** `Esc` 关闭最顶层浮层，无论类型（面板、速查表、创建弹窗）。
- **AC-10：** 首次提示 toast 只出现一次（第 3 次会话），可关闭，关闭后不再出现。
- **AC-11：** 所有文案 EN/ZH 翻译；快捷键按键在两种语言下完全一致。
- **AC-12：** 从不使用键盘的用户体验零差异（无布局偏移、无点击行为变化）。

## 8. 范围之外

- 用户自定义或可重映射的快捷键。
- 超出 `g` 式跳转前缀的快捷键序列/组合键（v1 保持单键 + 面板）。
- 面板命令扩展性（插件、自定义命令）。
- 录制/宏功能。
- 移动端专属手势（移动端使用既有触控 UI；面板以桌面为主但响应式）。
- 任何形式的变现 —— 本产品永久排除。

## 9. 依赖与假设

- **D-1：** 无障碍设计的键盘可操作性（可聚焦卡片、焦点捕获弹窗、菜单方向键模式）是基础；本功能在其上构建，不得重复或冲突。
- **D-2：** 既有模板搜索 API（来自 template-search-filtering）为面板模板结果提供支持；无新搜索端点。
- **D-3：** 头部搜索框、主题切换、创建按钮作为 `s`、`t`、`c` 的可见等价物存在。
- **D-4：** 路由列表派生自应用的路由配置加上当前用户权限（管理员可见管理路由）。
- **D-5：** `localStorage` 可用于首次提示偏好（与 advanced-editor 草稿相同的机制）。
- **D-6：** 通知、团队、合集、链、试验场、用量、仪表盘功能将其路由自动加入面板的导航来源（单一注册表）。

## 10. 给架构师的开放问题

1. **快捷键注册表形态：** 一个全局声明式配置（键、范围、处理器、描述 i18n 键），同时被按键监听器和速查表消费 —— 请确认这是纯前端模块，无后端参与。
2. **面板搜索 API：** 原样复用公开模板搜索端点（含分页），还是新增轻量 `?limit=5` 变体以优化面板查询？建议：若支持 limit 参数则复用。
3. **面板中的管理端用户搜索：** 管理用户 API 需要管理员权限 —— 请确认面板在会话为管理员时直接调用（无新权限面）。
4. **虚拟化网格上的 `j`/`k`：** 若任何网格虚拟化行（大量搜索结果），选择光标是否需要特殊处理，还是 v1 限于第一页结果？
5. **首次提示 toast 触发：** "第 3 次会话"需要 `localStorage` 中的会话计数器 —— 可接受，还是偏好功能上线后首次访问主页时显示 toast？
