# 高级模板编辑器 — 需求分析

- **Feature ID:** advanced-editor
- **Version:** 1.0
- **Status:** Proposed（待架构评审）
- **Author:** ui-ux-agent
- **Date:** 2026-10-12

## 1. 竞品调研总结

| 平台 | 编辑器做法 | 关键启示 |
|---|---|---|
| **PromptBase** | 简单 textarea + 实时预览面板；预览中高亮变量语法 | 实时预览是价值最高的编辑器特性；输入区本身可以保持朴素 |
| **FlowGPT** | 裸 textarea；变量手动输入；无校验 | 没有校验意味着变量名静默拼错 —— 这是我们必须防止的头号创作者错误 |
| **Snack Prompt** | textarea + 字符计数 + 基础 markdown 格式工具栏 | 轻量工具栏（描述字段的加粗/斜体）是预期配置但属次要 |
| **AIPRM** | 富提示词组合器：变量插入按钮、模板分类/标签选择器、发布前"测试"步骤 | 插入按钮优于手打 `$$` 语法；发布前的健全性检查能拦住坏模板 |
| **PromptHero** | 极简文本输入；提示词是静态文本 | 静态文本平台展示了下限；我们的模板是参数化的，编辑器必须把变量当作一等公民 |
| **Notion** | 块编辑器：斜杠命令、内联提及、撤销历史 | 斜杠命令插入与可靠的撤销是高级用户最称道的模式；完整块编辑对提示词文本而言过重 |
| **Stack Overflow / GitHub 评论框** | Markdown 工具栏 + 实时预览切换 + 草稿丢失警告 | 防草稿丢失（beforeunload 警告、本地草稿）是任何长文本 Web 编辑器的基本要求 |

**综合结论：** v1 的制胜模式是"增强型 textarea"：保持纯文本内容模型（提示词文本是带 `$$variable$$` 占位符的纯文本 —— 无富文本），加上创作者真正需要的四件事：(1) **变量工具栏**，在光标处插入 `$$name$$` 并列出已检测变量及其出现次数；(2) **实时预览**，高亮变量并提供示例解析切换；(3) **校验** —— 未闭合的 `$$`、空变量名、仅大小写/空白不同的重复名、超长内容在保存前被标记；(4) **草稿安全** —— 按模板自动保存到 localStorage、刷新后恢复提示、编辑期间 beforeunload 守卫。这升级了模板详情页现有的编辑模式（目前是裸 `<textarea>`），不引入重型依赖，也不新增路由。

## 2. 问题陈述

1. **变量极易出错。** 创作者在裸 textarea 里手打 `$$varname$$`。少一个闭合 `$$`、名字内带尾随空格（`$$name $$`）、大小写不一致（`$$Name$$` 与 `$$name$$`）都会静默产生一个生成器渲染错误或空值的模板。目前没有任何校验。
2. **编辑时没有实时反馈。** 现有编辑器只显示原始文本；创作者必须保存新版本、退出编辑模式、滚动到生成器才能看到模板如何解析。拼写错误由最终用户而非创作者发现。
3. **草稿极易丢失。** 编辑状态只存在于 React state。刷新、误导航或会话过期都会无声丢弃任意时长的工作成果。
4. **没有编辑器辅助。** 没有字符/行数计数、没有变量清单、没有插入变量按钮、没有保存快捷键。这个 textarea 和单行备注用的是同一个控件。
5. **编辑体验不一致。** 模板创建（Home 页弹窗）与模板编辑（详情页）使用不同且极简的控件；创作者无法建立可迁移的肌肉记忆。

## 3. 目标用户

- **模板创作者（主要）：** 编写或修订模板内容的用户 —— 需要正确性反馈与草稿安全。
- **高级创作者：** 维护大量多变量模板 —— 需要变量清单与快速插入。
- **普通用户：** v1 不受影响（详情页的生成器不是编辑器）；他们从更少的坏模板中受益。
- **管理员：** v1 无管理界面 —— 管理员以所有者身份编辑模板时走与现有行为相同的普通编辑器；审核仍在管理控制台。

## 4. 用户故事

- **US-E1:** 作为创作者，当我输入 `$$` 时编辑器帮我补全变量，或让我点击按钮在光标处插入格式正确的 `$$name$$`，以便绝不产生畸形占位符。
- **US-E2:** 作为创作者，我希望看到内容中变量的实时清单及出现次数，以便一眼发现拼写错误和重复。
- **US-E3:** 作为创作者，我希望校验错误（未闭合 `$$`、空名、近似重复名、超长）在保存前内联展示，以便坏模板无法被发布。
- **US-E4:** 作为创作者，我希望看到用示例值或自定义值解析后的实时预览，以便无需先保存版本就能验证模板可用。
- **US-E5:** 作为创作者，如果编辑中途刷新或离开页面，我希望草稿被恢复（或至少有警告），以便绝不丢失工作成果。
- **US-E6:** 作为创作者，我希望有字符数、行数和最大长度指示，以便写作时掌握边界。
- **US-E7:** 作为创作者，我希望在编辑器中 `Cmd/Ctrl+S` 保存、`Esc` 取消，以便高频编辑更快捷。
- **US-E8:** 作为创建新模板的创作者，我希望创建表单也有同样的变量工具栏和校验，以便在任何写模板内容的地方体验一致。

## 5. 功能需求

### 5.1 编辑器界面（升级现有编辑模式）

- **FR-1:** 高级编辑器替换模板详情编辑模式与模板创建弹窗内容字段中的裸 `<textarea>`。它仍是纯文本控件（无富文本）；内容模型与 `$$variable$$` 语法不变。
- **FR-2:** **变量工具栏：** "插入变量"按钮打开小浮层，含名称输入（校验：字母、数字、下划线，1–30 字符）并在光标位置插入 `$$name$$`。内容中已有的变量以一键 chip 形式出现在同一浮层中便于再次插入。
- **FR-3:** **变量清单：** 编辑器下方面板列出每个唯一变量及其出现次数；点击次数在编辑器中高亮所有出现位置（v1：聚焦编辑器并选中第一处；完整的文内高亮是加分项，不是要求）。
- **FR-4:** **校验（客户端，保存前）：** 编辑器在固定的校验摘要区标记：(a) 未闭合或不配对的 `$$` 定界符；(b) 空变量名（`$$$$`）；(c) 名称含首尾空白；(d) 仅大小写或空白不同的近似重复名；(e) 内容超过最大长度（与今日保存路径相同的上限）。存在阻断性错误（a–d）时 Save 按钮禁用；超长始终阻断。
- **FR-5:** **实时预览：** 可切换的预览面板渲染内容并高亮变量；"示例值"模式为每个变量填入占位值（`<name>`），"自定义值"模式复用现有生成器输入。预览随输入防抖 300 ms 更新。
- **FR-6:** **草稿安全：** 编辑期间，内容最多每 5 秒（有变更时）自动保存到 localStorage，键按模板区分（编辑用 `draft:template:{id}`，创建用 `draft:new-template`）。进入编辑模式时，若存在与已加载版本不同的草稿，恢复提示提供"恢复草稿"/"丢弃"选项。有未保存变更时启用 `beforeunload` 守卫。保存成功或明确丢弃后删除草稿。
- **FR-7:** **计数：** 编辑器底部实时显示字符数、行数、变量数；字符数在距上限 10% 内变琥珀色，达到上限变红色。
- **FR-8:** **键盘：** `Cmd/Ctrl+S` 保存（校验通过时），`Esc` 取消（有变更时弹确认框），`Cmd/Ctrl+Enter` 作为插入按钮的别名打开变量插入浮层。
- **FR-9:** 编辑器同时用于详情页编辑模式与创建弹窗；创建弹窗的标题/描述/分类/标签字段保持不变。

### 5.2 保存路径（语义不变，反馈更好）

- **FR-10:** 保存使用现有的更新/创建端点与版本创建语义（内容变更创建新版本，遵循 template-versioning 功能）。编辑器不新增端点；只是让现有 Save 按钮受校验门控。
- **FR-11:** 保存成功后清除草稿、显示成功通知并如常退出编辑模式。保存失败则保留草稿并内联展示错误与重试。

### 5.3 管理端界面

- **FR-12:** v1 无。管理控制台的模板审核保持只读（现有行为）。管理员作为所有者编辑模板时，通过 FR-1 获得同样的高级编辑器。

### 5.4 数据模型

- **FR-13:** 不新增数据库表，无后端变更。草稿仅存于 localStorage；校验在客户端。`$$variable$$` 内容格式、模板长度上限、版本语义均不变。

## 6. 非功能需求

- **NFR-1（性能）：** 100 KB 以内的模板输入延迟 < 50 ms；校验与清单重算防抖（300 ms）且不得阻塞输入。
- **NFR-2（兼容性）：** 在与应用相同的浏览器矩阵中工作；优雅降级 —— localStorage 不可用时无草稿也能编辑（不报错）。
- **NFR-3（安全）：** localStorage 中的草稿内容尽可能按用户账号隔离（键含用户 id）；登出时清除。无 HTML 注入：预览将变量作为文本渲染，绝不作为标记。
- **NFR-4（国际化）：** 所有编辑器文案通过 i18next 提供 EN/ZH（`editor.*` 命名空间）；变量名本身不翻译。
- **NFR-5（无障碍）：** 编辑器全键盘可操作；校验错误通过 `aria-live` 播报并经 `aria-describedby` 关联到编辑器；预览面板是带标签的区域；工具栏按钮有可聚焦标签。
- **NFR-6（可维护性）：** 变量解析/校验逻辑是单一共享工具（纯函数），供编辑器、创建弹窗使用，并可在未来被导入校验复用。

## 7. 验收标准

- **AC-1:** 输入 `$$na` 后点击插入变量并命名 `na`，在光标处插入格式正确的 `$$na$$`；清单立即显示 `na ×1`。
- **AC-2:** 含 `$$unclosed` 的内容显示阻断性校验错误；修复前 Save 禁用。
- **AC-3:** 同时含 `$$Name$$` 与 `$$name$$` 的内容显示列出两者的近似重复警告；解决前 Save 阻断。
- **AC-4:** 以示例值开启预览时，内容 `My name is $$name$$` 渲染为 `My name is <name>`。
- **AC-5:** 编辑模板后刷新页面再进入编辑模式，出现草稿恢复提示；恢复后得到与草稿完全一致的内容。
- **AC-6:** 字符计数以 `1234 / 10000` 样式展示，达到上限变红且 Save 阻断。
- **AC-7:** 校验通过时 `Cmd/Ctrl+S` 保存；有变更的编辑器上按 `Esc` 打开取消确认框。
- **AC-8:** 创建弹窗使用同一编辑器；不可能创建含未闭合 `$$` 的模板（Save 被阻断并显示错误）。
- **AC-9:** 所有文案 EN/ZH 已翻译；无硬编码文案。
- **AC-10:** 功能中没有任何变现相关内容。

## 8. 不做范围

- 模板内容的富文本 / markdown 渲染（内容保持纯文本）。
- 协同编辑（多用户光标、在线状态）。
- AI 辅助写作（提示词文本的建议、自动补全）。
- 服务端校验端点或服务端存储草稿。
- 完整的文内出现位置高亮（v1 从清单选中第一处）。
- CodeMirror/Monaco 式的 textarea 内语法高亮。
- 任何形式的变现（支付、定价、购买、收益）—— 本产品永久不做。

## 9. 依赖与假设

- **D-1:** `$$variable$$` 占位符语法与客户端提取正则（镜像后端 `\$\$(.*?)\$\$`）仍是模板变量契约。
- **D-2:** template-versioning 功能的保存语义（内容变更 → 新版本）已设计完成；本功能只对同一保存路径做门控与增强。
- **D-3:** 现有创建弹窗（Home 页）与详情页编辑模式是待升级的两个界面；不新增路由。
- **D-4:** 模板内容最大长度遵循现有后端上限；编辑器从共享常量读取。
- **D-5:** 遵循 accessibility 功能的焦点管理与 live-region 模式用于校验摘要。

## 10. 给架构师的开放问题

1. **最大长度来源：** 内容最大长度是否应由后端暴露（如配置/限额端点）而非前端硬编码常量，以免编辑器与后端漂移？
2. **草稿键隔离：** localStorage 草稿键包含用户 id 是否足够，还是你倾向于仅按模板 id 加用户前缀命名空间（同一件事）—— 登出后共享机器上残留草稿是否有安全顾虑（我们在登出时清除，但令牌过期时不清除）？
3. **校验一致性：** 后端目前用 `\$\$(.*?)\$\$`（非贪婪、无名称校验）提取变量。后端是否应在保存时加入相同的名称校验规则（FR-4）作为纵深防御，还是 v1 客户端门控即可？
4. **创建弹窗范围：** 创建弹窗还有标题/描述/分类/标签。变量校验是否应扩展到描述字段（描述中的变量今日不做替换），还是仅限内容字段（推荐）？
