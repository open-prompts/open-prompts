# 变量预设 — 需求分析

- **功能 ID：** variable-presets
- **版本：** 1.0
- **状态：** 已提案（待架构评审）
- **作者：** ui-ux-agent
- **日期：** 2026-10-13

## 1. 竞品调研总结

| 平台 | 已保存输入方式 | 关键启示 |
|---|---|---|
| **浏览器自动填充** | 按站点保存的值；显式保存提示；按字段下拉 | 用户期望保存的值按上下文区分而非全局；显式保存优于静默捕获 |
| **Postman** | 环境（命名的变量集）可按请求切换；全局 vs. 环境作用域 | 带作用域选择器的命名集是高级用户模式；一键切换是核心 UX |
| **Stripe 控制台** | 在 API 演练场中保存测试卡/客户作为可复用夹具 | 可复用夹具显著减少测试/迭代循环中的重复输入 |
| **ChatGPT（自定义指令）** | 持久的"关于我"画像注入每次对话 | 小型常开画像覆盖最重复的字段（语气、语言、人设） |
| **Zapier** | 按连接账户保存字段映射；"复用之前的值" | 按账户上下文优于重新输入；"最近"列表覆盖一次性复用 |
| **VS Code snippets** | 带占位符的命名代码片段；片段选择器 | 命名和快速选择让复用快速而无需搜索 UI |

**综合分析：** 重复表单输入的成熟模式是**带快速切换器的命名、按上下文的值集**：Postman 环境证明了命名集模型；浏览器自动填充证明了显式保存 + 按字段回填；ChatGPT 自定义指令证明小型常开画像处理最重复的字段。对 Open Prompts 而言，生成器表单（模板详情页上的变量输入）每次使用都要重新输入；**按模板的命名预设**系统加可选的**全局默认画像**（"我的默认值"，用于语气/语言/名称字段）消除大部分输入，同时保持完全的用户控制。

## 2. 问题陈述

详情页上的模板生成器为每个 `$$variable$$` 渲染一个输入。每次使用都要重新输入相同的值：

1. **每次使用都重复输入。** 每天运行"冷邮件"的用户每次重新输入 `tone=professional`、`language=English`、`company=Acme`。什么都不被记住。
2. **无跨模板连续性。** 许多模板共享变量（`tone`、`language`、`audience`）；为一个模板输入的值不会带到另一个。
3. **无已保存上下文。** 对不同客户/项目（Acme vs. Beta）使用同一模板的用户无法保留两套值集；他们重新输入或在产品外记笔记。
4. **复制粘贴变通。** 今天唯一的"预设"是从个人笔记文件粘贴 —— 易错且对产品不可见。

## 3. 目标用户

- **高频用户（主要）：** 定期实例化相同或相似模板并重复输入相同变量值的用户。
- **多上下文用户：** 对不同客户、项目或人设使用同一模板的用户。
- **创作者（间接）：** 在生成器中测试自己的模板时受益于更低摩擦（与 advanced-editor 预览的内食循环）。
- **管理员：** v1 无管理员界面（§8）；预设是按用户的私有数据。

## 4. 用户故事

### 4.1 保存与应用预设

- **US-V1：** 作为用户，填写生成器表单后我可以将当前值保存为该模板的命名预设，下次可以复用。
- **US-V2：** 作为用户，打开生成器时我可以从下拉中选择已保存的预设，所有字段立即填充，复用只需一键。
- **US-V3：** 作为用户，我可以用当前表单值更新现有预设，预设保持最新。
- **US-V4：** 作为用户，我可以删除不再需要的预设，列表保持干净。
- **US-V5：** 作为用户，我仅在保存过预设的模板上看到预设选择器，加上始终可用的"保存为预设"操作，一次性使用的 UI 保持安静。

### 4.2 全局默认值

- **US-V6：** 作为用户，我可以维护常见变量值的"我的默认值"画像（如 `tone`、`language`、`name`），跨模板的共享变量自动预填。
- **US-V7：** 作为用户，全局默认值仅应用于我未在所选预设中显式设置或未输入的字段，具体选择始终优先。
- **US-V8：** 作为用户，我可以在设置页管理默认值，控制常开画像。

### 4.3 系统故事

- **US-V9：** 作为系统，我按用户私有存储预设，任何用户都看不到他人的预设。
- **US-V10：** 作为系统，当模板的变量在版本间变化时，我按变量名应用预设并静默跳过缺失项，过期预设绝不破坏表单。

## 5. 功能需求

### 5.1 按模板预设

- **FR-1：** 在生成器表单上（模板详情页，仅登录用户），"预设"下拉应列出该模板已保存的预设（名称 + 最后使用时间），以及操作："将当前保存为预设…"、"管理预设"。
- **FR-2：** 选择预设应填充预设中存在对应变量名的每个表单字段；预设中没有的字段保持当前值（合并而非替换）。
- **FR-3：** 保存预设需要名称（1–50 字符）；同一模板重名提示覆盖（确认对话框）。
- **FR-4：** 预设应存储 `{template_id, name, values: {var_name: value}, created_at, updated_at, last_used_at}`；值为纯字符串，受现有变量值长度限制约束。
- **FR-5：** 每用户每模板限 20 个预设；超出提示删除一个（服务端以 400 强制执行）。
- **FR-6：** "更新预设"应用当前表单值覆盖存储值（确认对话框；名称不变）。
- **FR-7：** 删除预设需要确认并立即生效（v1 无回收站/撤销）。
- **FR-8：** 应用预设应更新 `last_used_at`；下拉按最近使用排序。

### 5.2 变量名漂移

- **FR-9：** 预设应按变量名应用。若模板当前版本缺少预设中的变量，该值被静默跳过（无错误）；预设保持可用。
- **FR-10：** 若预设的值不覆盖任何当前变量（完全过期），应用时显示通知（"此预设与当前变量不匹配"）且不填充。

### 5.3 全局默认画像

- **FR-11：** 每用户应有"我的默认值"画像：`{var_name: value}` 对，最多 30 条，在 `/settings/defaults` 管理。
- **FR-12：** 生成器表单首次渲染时（未应用预设），变量名匹配默认值的字段应预填；预填有一次性视觉提示（首个字段上的细微提示）且完全可编辑。
- **FR-13：** 优先级：用户显式输入 > 应用预设 > 全局默认值。应用预设覆盖其包含变量的默认填充值。
- **FR-14：** 生成器中的"保存到我的默认值"操作应支持将单个字段值（或所有字段）保存到默认画像，对已存在键显示覆盖确认。
- **FR-15：** 默认画像可整体清空（确认对话框）或在设置页逐键编辑。

### 5.4 访问与可见性

- **FR-16：** 预设和默认值仅对登录用户可用；匿名访客看到纯生成器（无预设 UI、无默认值预填）。
- **FR-17：** 预设对其所有者私有；v1 不共享、不导出，对模板作者不可见。
- **FR-18：** 预设适用于用户可查看的任何模板（公开或自己的私有）；预设数据绝不授予模板访问权。

### 5.5 普通用户与管理员分离

- **FR-19：** 所有界面均为普通用户界面（`/templates/{id}` 上的生成器、`/settings/defaults`、`/api/v1/me/*`）。无管理员控制台页面；无 `/api/v1/admin` 端点。

### 5.6 API

- **FR-20：** `GET /api/v1/templates/{id}/presets` → `{presets: [{id, name, values, updated_at, last_used_at}]}`（限定为请求用户自己的）。
- **FR-21：** `POST /api/v1/templates/{id}/presets` 体 `{name, values}` → 201；`PUT /api/v1/templates/{id}/presets/{preset_id}` 体 `{values}`（及可选 `name`）→ 200；`DELETE /api/v1/templates/{id}/presets/{preset_id}` → 204。
- **FR-22：** `POST /api/v1/templates/{id}/presets/{preset_id}/use` → 更新 `last_used_at` → 204（应用时调用）。
- **FR-23：** `GET /api/v1/me/defaults` → `{values: {var: value}}`；`PUT /api/v1/me/defaults` 体 `{values}`（全量替换）→ 200；`DELETE /api/v1/me/defaults` → 204。

## 6. 非功能需求

- **NFR-1（性能）：** 预设列表获取并行且非阻塞；应用预设是客户端操作（除 `use` 信标外无往返）；表单填充 < 50ms。
- **NFR-2（隐私）：** 预设值可能包含个人上下文（姓名、公司）；它们按用户私有，绝不渲染给其他用户或模板作者，并排除在分析负载之外。
- **NFR-3（兼容性）：** 匿名和无预设用户看到不变的生成器；不改变现有端点。
- **NFR-4（无障碍）：** 下拉、保存/更新/删除对话框和默认值设置页完全可键盘操作（UI/UX 文档 §9）。
- **NFR-5（国际化）：** 所有新 UI 字符串以 EN 和 ZH 提供且键集一致。
- **NFR-6（数据）：** 新表：`template_variable_presets (id, user_id, template_id, name, values JSONB, created_at, updated_at, last_used_at)`，`UNIQUE(user_id, template_id, name)`；`user_default_variables (user_id, values JSONB, updated_at)`，`UNIQUE(user_id)`。
- **NFR-7（限制）：** 预设名 ≤ 50 字符；值 ≤ 现有变量值限制；每模板 20 个预设；30 条默认条目 —— 服务端强制执行并给出清晰的 400 消息。

## 7. 验收标准

- **AC-1：** 填写生成器并保存为"Acme campaign"后，它出现在预设下拉中；重新打开模板并选择它重新填充所有匹配字段。
- **AC-2：** 编辑某些字段后应用预设，除非预设包含那些变量，否则保留已编辑字段（合并语义，FR-2）。
- **AC-3：** 新版本去掉 `$$tone$$` 的模板仍可应用含 `tone` 的预设 —— 静默跳过；完全过期的预设显示通知且不填充。
- **AC-4：** 我的默认值中有 `language=English` 时，打开任何带 `language` 变量的模板都会预填；输入覆盖优先；应用含 `language` 的预设覆盖它。
- **AC-5：** 对同一模板第 21 次保存预设返回 400，UI 提示删除一个。
- **AC-6：** 匿名访客看不到预设 UI 和默认值预填。
- **AC-7：** 用户 A 的预绝不会出现在用户 B 的同一模板上。
- **AC-8：** 删除预设立即从下拉中移除；删除前有确认对话框。
- **AC-9：** `/settings/defaults` 列出所有条目并可编辑/删除；清空全部需要确认。
- **AC-10：** 所有新 UI 字符串以 EN 和 ZH 存在于翻译文件中且键集一致。

## 8. 范围之外（v1）

- 与团队共享预设（team-collaboration 可以后续采用）。
- 导出/导入预设（import-export 仅覆盖模板）。
- API key 使用的预设（基于别名的消费无表单；未来 API 可接受预设 id）。
- 无显式保存的自动捕获值（无静默历史）。
- 预设版本化或 diff。
- 管理员查看用户预设（隐私立场，FR-17）。
- 任何形式的变现 —— 本产品永久超出范围。

## 9. 依赖与假设

- **D-1：** 模板详情页上的生成器表单为每个 `$$variable$$` 渲染一个输入（现有行为）；表单状态是本功能接入的客户端 React 状态。
- **D-2：** 变量提取使用共享的 `$$var$$` 正则工具（advanced-editor D-1、template-compare D-2 —— 相同契约）。
- **D-3：** 认证中间件在 `/api/v1/me/*` 和模板作用域路由上识别登录用户（现有模式）。
- **D-4：** `/settings` 路由前缀已存在或随其他在途功能到来（与 personalized-recommendations D-7 相同假设）；本功能添加 `/settings/defaults`。
- **D-5：** 变量值长度限制是提示词变量值的现有后端限制；预设原样复用。
- **D-6：** `values` 映射的 JSONB 存储可接受（Postgres）；无需按变量分行。

## 10. 给架构师的开放问题

1. **`use` 信标必要性：** `last_used_at` 是否值得专用端点（FR-22），还是应在下一次 `PUT` 中机会性更新应用时间？设计保留信标（便宜，保持 MRU 排序真实）。
2. **默认值预填时机：** 客户端在生成器挂载时获取 `/me/defaults`（每次详情视图多一个请求）vs. 打包进模板详情响应。设计假设带会话级客户端缓存的轻量并行获取。
3. **预设上限执行：** 每用户每模板 20 个（FR-5）—— 确认该限制以及是否还需要全局每用户上限（如 200）以约束存储。
