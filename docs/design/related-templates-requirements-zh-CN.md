# 相关模板与发现 — 需求分析

- **功能 ID：** related-templates
- **版本：** 1.0
- **状态：** 已提案（待架构评审）
- **作者：** ui-ux-agent
- **日期：** 2026-10-12

## 1. 竞品调研总结

| 平台 | 相关内容方式 | 关键启示 |
|---|---|---|
| **YouTube** | 由共同观看信号驱动的"接下来"推荐；强个性化 | 相关内容是会话时长的第一驱动力；即使简单的分类/作者回退也有效 |
| **PromptHero** | 详情页上按标签/模型的关联提示词；主页分类横栏 | 基于标签的关联是提示词平台的标准 —— 廉价且可解释 |
| **FlowGPT** | 提示词页上的"相似提示词"区块；主页分类横栏 | 相同标签 + 相同分类横栏；v1 无需个性化 |
| **Amazon** | "买了此商品的顾客还买了"（共同购买）；"更多类似"（内容相似） | 一旦有量，共同交互信号（收藏/点赞）优于元数据 |
| **Spotify** | 主页"因为你喜欢 X"横栏；艺人页上的相关艺人 | 解释*为什么*相关（"同分类"）能建立信任 |
| **PromptBase** | 极少相关内容；仅市场分类 | 即使市场领导者也跳过这一点 —— 容易的差异化 |

**综合分析：** 模板详情页今天是死胡同：用户读完提示词后唯一的路径是返回或离开。v1 模式（PromptHero/FlowGPT）：每个模板详情页上的**"相关提示词"横栏**，由可解释的元数据信号计算 —— 先同分类，再共享标签，再同作者（"来自 {作者} 的更多"）—— 按简单评分（共享标签数，再点赞数）排序，上限 8 项，排除当前模板和非公开内容。v1 无个性化、无机器学习、无跟踪：关联性是模板自身元数据的纯函数，这让它快速、可缓存且诚实（"相关 · 客服支持"）。第二个较小的界面：详情页上的**"来自此作者的更多"**（最多 4 个，同作者，点赞最多优先）—— 这也服务于 follow-creators 功能将读者转化为关注者的目标。主页个性化横栏明确排除（v1 没有"为你推荐"）。

## 2. 问题陈述

1. **详情页是死胡同。** 读完模板后除了返回/离开没有下一步；会话深度受损，同分类的优秀模板永远看不到。
2. **发现只有搜索。** 用户必须已经知道要找什么；没有"更多类似"的相邻浏览流程。
3. **作者没有光环效应。** 喜欢 alice 某个模板的用户没有路径看到她的其他作品 —— follow-creators 功能需要这座桥。
4. **竞品大多跳过这一点。** PromptBase 没有相关内容；加上它是廉价且显眼的产品胜利。

## 3. 目标用户

- **浏览用户：** 读完一个模板后想要更多类似的，无需构造新搜索。
- **作者：** 其作品目录获得交叉可见性（"来自 {作者} 的更多"）。
- **follow-creators 用户：** 在关注前发现作者的广度。
- **平台：** 更长的会话、更多模板浏览、更好的内容流转。

## 4. 用户故事

- **US-D1：** 作为浏览用户，我在每个公开模板详情页看到"相关提示词"横栏，无需新搜索即可继续探索。
- **US-D2：** 作为用户，相关提示词与我当前模板的分类或标签相同，建议真正相关。
- **US-D3：** 作为用户，我理解为什么展示某个提示词（"相关 · 客服支持"），横栏值得信任。
- **US-D4：** 作为用户，我看到"来自 {作者} 的更多"及其其他公开模板，可以探索其作品目录。
- **US-D5：** 作为用户，我在相关横栏中绝不会看到私有、未发布或被封禁作者的内容，横栏始终安全。
- **US-D6：** 作为作者，我的其他模板出现在我的模板详情页上，读者可以发现我更多的作品。
- **US-D7：** 作为查看无相关匹配模板的用户，该区块干净地隐藏，没有空洞的杂乱。

## 5. 功能需求

### 5.1 相关提示词横栏（模板详情）

- **FR-1：** 每个公开模板详情页在提示词内容下方渲染**"相关提示词"**横栏：最多 8 张模板卡片，移动端横向滚动，桌面端网格换行。
- **FR-2：** 候选池：非封禁作者的公开模板（visibility public），排除当前模板。信号按优先级：
  1. 同分类（最强信号）；
  2. 共享标签（每个共享标签增加权重）；
  3. 同语言（平局裁决）；
  4. 同作者（小权重 —— 作者自己的作品可以出现但不应主导）。
- **FR-3：** 排序评分：`3 × 同分类 + 2 × 共享标签数 + 1 × 同语言 + 0.5 × 同作者`，再按点赞数降序，最后按 updated_at 降序。对给定模板是确定性的（v1 无随机化）。
- **FR-4：** 横栏标题解释关联：顶部候选共享分类时显示"相关 · {分类}"；标签驱动时显示"相关 · {标签}"（顶部项的第一个共享标签）；回退为"相关提示词"。
- **FR-5：** 若排除后存活候选少于 3 个，整个区块隐藏（没有 1–2 项的残桩）。

### 5.2 来自此作者的更多

- **FR-6：** 在作者有其他公开模板的公开模板详情页上，"相关"下方渲染**"来自 {作者} 的更多"**行：最多 4 张卡片，点赞最多优先，排除当前模板。作者无其他公开模板时隐藏。
- **FR-7：** 行标题链接到作者的公开资料（follow-creators 界面，若可用）；否则为纯文本。

### 5.3 API

- **FR-8：** `GET /api/v1/templates/{id}/related?limit=8` 返回相关横栏：`{ items: [TemplateCard…], basis: "category" | "tag" | "generic" }`。仅公开；不存在/私有模板 id 返回 404（与模板详情端点相同的可见性规则）。
- **FR-9：** `GET /api/v1/templates/{id}/more-from-author?limit=4` 返回作者行：`{ items: [TemplateCard…] }`，无则空 items。相同可见性规则。
- **FR-10：** 两个端点均可缓存（短 TTL，5 分钟），从既有模板元数据（分类、标签、语言、所有者、点赞）计算 —— 无新表、无后台任务。

### 5.4 位置与集成

- **FR-11：** 横栏渲染在模板详情页提示词/版本内容之下、评论之上；移动端出现在操作按钮之后。私有模板（仅所有者视图）或管理端视图上不渲染。
- **FR-12：** 横栏中的卡片复用既有 TemplateCard 组件（名称、分类、点赞、所有者），点击行为一致（导航到详情）。
- **FR-13：** 横栏排除在 SEO/SSR 爬虫渲染之外（它们是交互式发现，非核心内容）—— 爬虫页面只渲染内容 + CTA（按 seo-landing 设计）。

### 5.5 管理端

- **FR-14：** 无管理端界面。横栏通过与公开列表端点相同的过滤器（既有行为）自动排除未发布模板和被封禁作者。

## 6. 非功能需求

- **NFR-1（性能）：** 相关端点响应 < 200 毫秒（p95），5 分钟缓存；横栏渲染不阻塞详情页（主内容之后懒加载）。
- **NFR-2（正确性）：** 横栏绝不包含私有/未发布模板或被封禁作者的内容；当前模板绝不出现在自己的横栏中。
- **NFR-3（确定性）：** 缓存窗口内同一模板 id 产生相同横栏（加载之间无闪烁）。
- **NFR-4（国际化）：** 横栏标题和空状态通过 i18next（`related.*` 命名空间）提供 EN/ZH；基础标签插值分类/标签名（专有名词不翻译）。
- **NFR-5（无障碍）：** 横栏是可键盘访问的横向滚动区域（卡片按无障碍设计是可聚焦链接）；节标题为 `h2`；无自动播放/轮播计时器。
- **NFR-6（无跟踪）：** v1 关联性仅使用模板元数据 —— 无用户行为、无 cookie、无画像；没有任何个性化。

## 7. 验收标准

- **AC-1：** 公开模板详情页显示含最多 8 张共享其分类/标签卡片的相关横栏；点击卡片导航到该模板。
- **AC-2：** 横栏标题显示关联基础（"相关 · 客服支持"或"相关 · writing"）。
- **AC-3：** 相关候选少于 3 个的模板不显示横栏。
- **AC-4：** 当前模板绝不出现在自己的横栏中；私有和未发布模板绝不出现；被封禁作者的模板绝不出现。
- **AC-5：** "来自 {作者} 的更多"显示该作者最多 4 个其他公开模板，点赞最多优先；没有时隐藏。
- **AC-6：** 未认证调用时，两个端点对私有/不存在的模板 id 返回 404。
- **AC-7：** 横栏在主内容之后懒加载；详情页的 LCP 不受影响（横栏请求不阻塞渲染）。
- **AC-8：** 横栏可键盘导航（Tab 遍历卡片），并被屏幕阅读器标记为补充节。
- **AC-9：** 所有横栏文案 EN/ZH 翻译；分类/标签名按原样渲染。
- **AC-10：** 缓存窗口内重复加载返回相同横栏（确定性）。

## 8. 范围之外

- 个性化推荐（"为你推荐"、浏览历史信号、共同交互矩阵）。
- 主页推荐横栏或"因为你喜欢"界面。
- 机器学习/嵌入相似度或语义搜索。
- 相关合集/链/团队（在这些界面上线时增加）。
- 横栏卡片上的"不感兴趣"控件。
- 任何形式的变现（赞助横栏、推广位）—— 本产品永久排除。

## 9. 依赖与假设

- **D-1：** 模板带有分类、标签、语言、owner_id、点赞、可见性、updated_at —— 全部是既有列；关联性无需模式变更。
- **D-2：** 公开模板列表过滤器（visibility public、非封禁作者）是既有列表端点可复用的查询片段。
- **D-3：** TemplateCard 组件及其无障碍点击行为存在（无障碍设计使其可键盘操作）。
- **D-4：** 模板详情页布局（内容 → 操作 → 评论）在内容下方有容纳两个横栏的空间（按 template-versioning/comments 设计的页面结构）。
- **D-5：** follow-creators 设计的公开资料路由存在或将要存在；"来自 {作者} 的更多"在存在时链接到它。
- **D-6：** 存在短 TTL 响应缓存机制（或可轻易添加）用于两个新端点。

## 10. 给架构师的开放问题

1. **查询形态：** 带评分表达式的单条 SQL（基于 CASE，ORDER BY score DESC, likes DESC, updated_at DESC, LIMIT 8）vs 取候选（同分类 + 共享标签，池上限约 200）后应用侧评分？建议：单条 SQL —— 数据量小且表达式简单。
2. **缓存层：** 进程内 TTL 缓存（5 分钟）vs redis（栈中有 redis）vs 带 CDN 的 HTTP Cache-Control？建议：redis 或进程内 —— v1 不依赖 CDN。
3. **端点粒度：** 两个端点（related + more-from-author）vs 详情响应上的一个组合 `?include=related,author`？建议：两个端点 —— 并行懒加载、独立缓存。
4. **同作者权重：** FR-3 给同作者小权重（0.5），作者自己的作品可以出现但不淹没横栏 —— 请确认，还是把自有作品完全排除出 Related（它已有自己的行）？
5. **基础标签：** FR-4 从顶部项的主导信号派生标签 —— 请确认这个简单规则 vs 返回每张卡片的关系原因（载荷更重、UI 更丰富）。
6. **限制默认值：** 8 相关 / 4 作者 —— 请确认或调整（如移动端通过响应式 CSS 显示 6/3，载荷相同）。
