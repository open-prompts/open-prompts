# 管理员模板审核 — 需求分析

- **功能 ID：** admin-template-moderation
- **版本：** 1.0
- **状态：** Proposed（待架构评审）
- **作者：** ui-ux-agent
- **日期：** 2026-10-13
- **配套文档：** `admin-template-moderation-ui-ux-design-zh-CN.md`

## 1. 竞品调研摘要

| 产品 | 模板/内容审核模式 | 启示 |
|---|---|---|
| **Reddit（版主工具）** | 移除帖子（带原因）、锁定、剧透标记；版主日志记录每个操作；被移除内容对公众隐藏但对版主可见 | 可逆移除（而非删除）是默认；版主日志不可或缺 |
| **YouTube Studio** | 视频状态：公开 / 不列出 / 私密 / 已移除；年龄限制；"有限广告"；创作者申诉路径 | 状态机胜过二元删除；创作者得到解释 |
| **Discord** | 删除消息（记录）、用户禁言、慢速模式；审计日志含操作者 + 目标 + 原因 | 每个破坏性操作都伴随操作者 + 原因 + 时间戳 |
| **WordPress** | 回收站（30 天软删除）→ 永久删除；批量回收；从回收站恢复 | 带恢复窗口的软删除是普适安全网 |
| **GitHub（仓库下架）** | 管理员可将仓库设为私有/因 ToS 违规移除；透明度报告 | 平台级下架罕见、有原因记录、可申诉 |
| **FlowGPT / Snack Prompt** | 审核极简；内容无解释消失 | 反面教材：无解释的移除摧毁创作者信任 |

**综合结论：** v1 的制胜模式是 **Reddit/WordPress 混合**：管理员对模板的操作是**状态变更而非删除** —— (1) **取消发布**（公开 → 私有，可逆，必填原因，通知创作者）、(2) **锁定**（冻结编辑 + 新评论/fork，内容保持公开 —— 用于审核中的争议内容）、(3) **软删除**（处处隐藏，30 天恢复窗口，之后永久删除）。三者均写入现有 `admin_audit_logs`（操作者、目标、原因）。管理员模板详情页（`/admin/templates/:id`，admin-user-management 已设计为只读）新增**审核操作面板**；管理员模板列表新增**状态筛选**（公开 / 私有 / 已锁定 / 已软删除）。content-reporting 的"处理：取消发布模板"流程调用本功能的取消发布端点 —— 补上 content-reporting 假设存在实则缺失的"现有审核操作"缺口。创作者通知复用现有通知系统，新增 `moderation` 事件类型（数据驱动注册，沿用 mention-notifications 模式）。

## 2. 问题陈述

1. **管理员只能看不能动。** 管理控制台的模板页面按设计只读（admin-user-management FR-24/27 明确将"管理员编辑或删除模板"推迟为后续功能）。发现违规模板的管理员只能联系所有者请求删除 —— 没有执行路径。
2. **content-reporting 依赖缺失的操作。** 举报队列的"处理"流程假设存在"取消发布模板（现有审核操作）"—— 但后端没有该管理员端点（`admin.proto` 只有 ListTemplates/GetTemplate/DeleteAdminComment）。审核闭环在最后一步断裂。
3. **没有分级响应。** 今天唯一的手段是封禁用户（核弹级）或无所作为。审核需要渐进响应：取消发布（可逆）、锁定（原地冻结）、删除（最后手段）。
4. **内容操作没有问责轨迹。** 用户操作（封禁/解封）有审计日志，但模板级审核没有操作词汇、必填原因或通知机制。

## 3. 目标用户

- **管理员（主要）：** 需要对举报或巡查发现的模板进行分级、可审计的处置。
- **创作者（次要）：** 需要知道自己的内容何时被处置、为什么、如何修复或申诉。
- **社区（隐含）：** 有害内容快速移除，同时边缘案例不伤及无辜（封禁）。

## 4. 用户故事

- **US-M1:** 作为管理员，我可以取消发布任何公开模板（公开 → 私有）并必填原因，以便违规内容立即、可逆地离开公开界面。
- **US-M2:** 作为管理员，我可以锁定模板（冻结编辑、评论、fork、新点赞）并保持公开可见，以便争议内容在审核期间冻结而不消失。
- **US-M3:** 作为管理员，我可以软删除模板（处处隐藏，30 天恢复窗口），以便最严重的内容被移除且留有纠错安全网。
- **US-M4:** 作为管理员，我可以从管理员详情页恢复已取消发布或已软删除的模板，以便失误与申诉成功可逆。
- **US-M5:** 作为管理员，我看到每个可选操作及其后果说明（什么保留、什么消失、谁被通知），以便选择相称的响应。
- **US-M6:** 作为管理员，我可以按审核状态（公开 / 私有 / 已锁定 / 已软删除）筛选模板列表，以便复查已处置内容与待恢复项。
- **US-M7:** 作为创作者，我的模板被取消发布/锁定/删除时收到带原因的通知，以便理解发生了什么并应对（修复后重新发布，或申诉）。
- **US-M8:** 作为创作者，修复后可以重新发布被管理员取消发布的模板，以便审核是纠正性而非惩罚性 —— 除非模板被锁定（重新发布被阻断并说明）。
- **US-M9:** 作为管理员，我的每个审核操作都写入审计日志（操作者、目标、原因、时间戳），以便监督与申诉有据可查。
- **US-M10:** 作为管理员，我可以从 content-reporting 队列条目直接跳到审核操作，以便"举报 → 处置"是一个流程。

## 5. 功能需求

### 5.1 审核状态

- **FR-1:** 新列 `templates.moderation_status VARCHAR(12) NOT NULL DEFAULT 'normal'`，取值：`normal`、`locked`、`unpublished_by_admin`、`soft_deleted`。现有 `visibility` 列不变（公开/私有）；审核状态与之正交，并在访问检查中优先。
- **FR-2:** **取消发布**（`unpublished_by_admin`）：模板在所有公开界面（首页、搜索、分类、相关推荐、嵌入、二维码目标、Following 流、API `GetPromptByAlias` 对非所有者返回 404）表现为私有，无论 `visibility` 如何。所有者仍可查看和编辑。所有者**可以**重新发布（`moderation_status` 回到 `normal` 且 `visibility` 置为公开）—— 审核是纠正性的。重新发布不通知管理员（v1）。
- **FR-3:** **锁定**（`locked`）：模板保持公开可见（只读），但除管理员外所有人的变更被阻断：不能编辑、不能新评论、不能 fork、不能点赞/收藏/评分、不能关注、不能保存预设。现有评论保持可见。详情页显示锁定横幅（"该模板已被管理员锁定"）。
- **FR-4:** **软删除**（`soft_deleted`）：模板对除管理员外的所有人隐藏（所有者直接访问时看到"该模板已被管理员移除"及原因；其他路径 404）。`deleted_at` 时间戳启动 **30 天恢复窗口**；期满后 ticker 任务（webhooks/scheduler 的到期扫描模式）按与所有者删除相同的级联语义硬删除（account-deletion FR-8/9：版本、别名、其下评论删除；他人的 fork 保留并显示"源已删除"谱系）。
- **FR-5:** **恢复**：管理员可恢复 `unpublished_by_admin`（→ `normal`，visibility 保持私有 —— 由所有者重新发布）、`locked`（→ `normal`）、窗口期内的 `soft_deleted`（→ `normal`，恢复先前 visibility）。恢复需填原因并写审计条目。

### 5.2 管理员 API 与 UI

- **FR-6:** 新管理员 RPC（REST 位于 `/api/v1/admin`）：`POST /api/v1/admin/templates/{id}/unpublish`（原因必填）、`POST /api/v1/admin/templates/{id}/lock`（原因必填）、`POST /api/v1/admin/templates/{id}/delete`（原因必填；软删除）、`POST /api/v1/admin/templates/{id}/restore`（原因必填）。均需管理员会话；均以新动作码 `template.unpublish`、`template.lock`、`template.delete`、`template.restore` 写入 `admin_audit_logs`（操作者、目标模板 id、原因、时间戳）。
- **FR-7:** `GET /api/v1/admin/templates` 新增 `moderation_status` 筛选，响应项包含 `moderation_status`、`moderated_at`、`moderated_by`、`moderation_reason`（仅管理员可见字段）。
- **FR-8:** 管理员模板详情页（`/admin/templates/:id`）新增**审核操作面板**：当前状态 chip、三个操作及后果摘要、恢复（适用时）、审核历史（按目标过滤审计日志）。
- **FR-9:** 三个操作均使用**原因弹窗**（3–500 字符，与封禁相同的校验），内含后果清单（"公开界面：移除 / 评论：冻结 / 创作者：收到通知"）。删除还需输入模板标题确认（type-to-confirm，沿用 account-deletion 模式）。
- **FR-10:** content-reporting 队列的"处理 → 取消发布模板"调用 FR-6 的取消发布端点（补上 content-reporting FR-15 假设的闭环）；成功后举报组按现有 content-reporting FR-11/12 语义自动解决为 `actioned`。

### 5.3 创作者体验

- **FR-11:** 新通知事件类型 `moderation`（数据驱动注册进通知系统与 notification-preferences 面板，默认**开**、可抑制）：在取消发布/锁定/删除/恢复时发给模板所有者，载荷含操作、模板标题、原因、以及（取消发布时）"修复并重新发布"深链。
- **FR-12:** 所有者界面：已取消发布 → 模板详情页（所有者视图）显示管理员通告横幅（"管理员已取消发布该模板：{原因}。你可以编辑后再次分享。"）；已锁定 → 带原因的锁定横幅；已软删除 → 带原因的移除通告页与申诉提示（v1 申诉为带外联系 —— 横幅链接到现有支持/联系入口或提示"通过你的通知回复"）。
- **FR-13:** 管理员取消发布后的重新发布走正常分享流程（现有 `UpdateTemplate` visibility 变更）—— 无专用端点；横幅 CTA 深链到该流程。锁定模板阻断分享开关并给出解释性提示。

### 5.4 防护栏

- **FR-14:** 管理员不能审核自己的模板（403 及提示）—— 与封禁相同的自我操作防护。一个管理员的操作可被另一个管理员恢复（restore）—— v1 无超级锁。
- **FR-15:** 每管理员的审核操作有速率限制（复用 rate-limit-dashboard 的写入档），防止误操作批量处置；批量审核明确不在范围内。
- **FR-16:** 30 天硬删除 ticker 幂等且支持宕机补跑（scheduler-sharing/webhooks 到期扫描模式）；窗口期内恢复会取消计划删除。

## 6. 非功能需求

- **NFR-1（性能）：** 取消发布/锁定在读路径立即生效（状态在现有模板访问层检查 —— WHERE 子句/响应整形多一列）；除现有 TTL 外无需缓存失效。
- **NFR-2（可审计）：** 每个操作、恢复及计划硬删除都写审计条目；详情页的审核历史完整且不可变（现有审计日志语义）。
- **NFR-3（隐私）：** 审核原因仅展示给模板所有者（透明度）与管理员 —— 绝不给其他用户。锁定横幅对公众显示通用文案（"已被管理员锁定"），不显示原因。
- **NFR-4（国际化）：** 所有管理员与创作者文案 EN/ZH 双语；通知内容按现有渲染机制本地化。
- **NFR-5（兼容性）：** 不改变所有者发起的删除、归档、可见性语义；审核状态与之组合（如被管理员取消发布的模板仍可被所有者归档）。

## 7. 验收标准

- **AC-1:** 管理员打开公开模板的管理详情 → 审核操作面板可见 → 填原因取消发布 → 模板从首页/搜索/嵌入/API 对非所有者消失；所有者看到带原因的管理员通告横幅；审计日志有 `template.unpublish`。
- **AC-2:** 所有者收到含操作、标题、原因的 `moderation` 通知；点击打开模板（所有者视图）并显示横幅。
- **AC-3:** 所有者编辑模板并重新分享 → `moderation_status` 回到 `normal`，模板重新公开；无管理员通知。
- **AC-4:** 管理员锁定模板 → 公众看到锁定横幅；评论/fork/点赞/评分/关注被阻断并给出解释性错误；现有评论保持可见；所有者不能编辑（保存被阻断并显示锁定原因）。
- **AC-5:** 管理员软删除模板（输入标题确认）→ 非所有者 404；所有者看到带原因的移除通告；管理员列表在 `soft_deleted` 下显示该模板及恢复倒计时。
- **AC-6:** 管理员在第 12 天恢复软删除模板 → 模板回到先前 visibility；审计日志有 `template.restore`；计划的硬删除被取消。
- **AC-7:** 软删除模板超过 30 天后被 ticker 硬删除，级联语义同 account-deletion；他人 fork 该模板的副本保留并显示"源已删除"谱系。
- **AC-8:** 管理员按 `moderation_status=locked` 筛选 `/admin/templates` → 仅列出已锁定模板，各带 moderated_at/by/reason。
- **AC-9:** 从 content-reporting 队列组，处理 → 取消发布 → 举报组自动解决为 `actioned`；审核审计条目携带相同原因。
- **AC-10:** 管理员尝试取消发布自己的模板 → 403 及提示；审计日志不变。

## 8. 不在范围内（v1）

- 批量审核操作（多模板取消发布/删除）。
- 发布前审核队列（提交 → 批准）—— 未来功能（见 admin-user-management）。
- 创作者申诉工作流（应用内申诉表单、案件状态）—— v1 为通知 + 带外联系。
- 管理员编辑模板内容（仅状态变更；内容编辑归所有者）。
- 年龄限制 / 内容警告遮罩（YouTube 式）—— 未来。
- 影子封禁或分级可见性（仅搜索除名）。
- 任何形式的变现 —— 本产品永久不做。

## 9. 依赖与假设

- **D-1:** admin-user-management 提供管理控制台外壳、`/admin/templates` 列表 + 详情页（当前只读）、原因弹窗模式与 `admin_audit_logs`。
- **D-2:** content-reporting 的队列"处理"流程与 FR-6/FR-10 集成；其自动解决语义（FR-11/12）适用。
- **D-3:** 通知系统 + notification-preferences 为 `moderation` 类型提供数据驱动的事件类型注册（mention-notifications 模式）。
- **D-4:** scheduler-sharing/webhooks 的 DB 驱动到期扫描 ticker 模式承载 30 天硬删除扫描。
- **D-5:** account-deletion 定义了过期软删除复用的硬删除级联语义（FR-8/9）；template-remix-forks-tree 提供"源已删除"谱系渲染。
- **D-6:** template-embedding-widget 与 template-qr-share 界面必须尊重 `moderation_status`（已取消发布/软删除模板的嵌入渲染"已移除"状态，而非内容）。
- **D-7:** rate-limit-dashboard 提供被 FR-15 复用的写入档限流器。
- **D-8:** 假设：`templates.visibility` 仍为所有者控制字段；`moderation_status` 为管理员控制并优先 —— 访问检查合并二者。

## 10. 给架构师的开放问题

1. **访问检查组合：** `moderation_status` 应在哪里强制 —— 单一仓储/服务层守卫（推荐：所有读路径共用的 `checkTemplateAccess(template, viewer)`），还是逐端点检查（嵌入/API 路径有泄漏风险）？
2. **列 vs. 独立表：** `templates.moderation_status` 列（推荐 —— 热路径读取）vs. 通过当前状态推导的 `template_moderation_events` 表（历史更多、join 更多）。无论哪种，历史都可来自审计日志。
3. **锁定与所有者编辑的交互：** FR-3 阻止锁定模板的所有者编辑。备选：允许编辑但仅阻止重新发布（所有者可在审核期间准备修复）。推荐双阻断（真冻结）；请确认。
4. **硬删除复用：** 30 天到期是否应调用为 account-deletion 设计的同一删除例程（共享级联代码），该例程是可复用服务还是账号专用？推荐抽取共享的模板级联服务。
5. **无管理员复审的重新发布（FR-2）：** 所有者可在取消发布后立即重新发布 —— 恶意所有者可能原样重发。缓解选项：(a) 接受（v1 简单，管理员可再取消；屡犯 → 封禁）、(b) 审核后重新发布限速、(c) 要求管理员重新批准。推荐 (a)，并在被审核模板重新发布时记录审计事件 `template.republished_after_moderation` 使模式可见。请确认。
