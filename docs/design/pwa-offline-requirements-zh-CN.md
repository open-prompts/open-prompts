# PWA 与离线支持 — 需求分析

- **功能 ID：** pwa-offline
- **版本：** 1.0
- **状态：** 已提案（待架构评审）
- **作者：** ui-ux-agent
- **日期：** 2026-10-12

## 1. 竞品调研总结

| 平台 | PWA / 离线方式 | 关键启示 |
|---|---|---|
| **Notion** | 可安装 PWA；离线页面缓存，重连后同步 | 以读为主的离线效果很好；离线写需要显式同步状态 |
| **Google Docs** | 离线模式（用户主动开启）；本地编辑排队并合并 | 离线*编辑*是巨大的工程投入 —— 需主动开启并明确标识 |
| **Twitter/X Lite** | Service worker 应用外壳缓存；骨架优先加载；省流量 | 应用外壳缓存是价值最高、风险最低的 PWA 举措 |
| **AIPRM** | 浏览器扩展（非 PWA）；提示词库本地缓存 | 提示词*内容*小而静态 —— 理想的缓存对象 |
| **PromptBase / FlowGPT / Snack Prompt** | 普通网页；无离线、无安装 | 目前没有提示词平台可安装 —— 差异化机会 |
| **VS Code web / StackBlitz** | 可安装、激进缓存、离线横幅 | 带排队操作感知的显式离线横幅能建立信任 |

**综合分析：** 价值最高的 v1 是**以读为先的 PWA**：让应用可安装（manifest + 图标 + service worker），缓存应用外壳实现秒开，并缓存最近查看的模板详情以供离线阅读。提示词文本小而静态 —— 完美的离线内容。离线*编辑*明确排除在 v1 之外（冲突解决本身就是一个大项目）；离线用户会看到清晰的离线横幅、缓存内容和带说明的禁用写操作。v1 不需要"保存供离线使用"功能 —— 最近 N 次查看的自动缓存覆盖了自然场景（在飞机/火车上查阅提示词）。

## 2. 问题陈述

1. **没有安装存在感。** 应用只是一个普通标签页；每天使用的用户没有 dock/桌面图标，移动用户看到的是浏览器 UI 而非类应用体验。
2. **每次访问都依赖网络。** 没有任何缓存；连接不稳定意味着白屏或转圈，即使是刚看过的内容。
3. **提示词在离开工位时才最需要。** 核心产物（提示词文本）极小且静态，却无法离线阅读模板 —— 而这恰是用户最需要已保存提示词的时刻（在别的工具中工作、通勤时）。
4. **竞品全是普通网页。** 可安装 + 离线阅读对提示词平台是廉价且显眼的差异化。

## 3. 目标用户

- **每日活跃用户：** 希望产品一键可达（安装的应用图标）并秒启动。
- **通勤/出行用户：** 离线阅读和复制自己的模板。
- **移动用户：** 无需应用商店即可获得类应用体验（独立窗口、无浏览器边框）。
- **弱网用户：** 网络不稳定时应优雅降级而非页面崩溃。

## 4. 用户故事

- **US-P1：** 作为每日活跃用户，我可以安装应用（桌面图标 / 移动主屏），让它像原生应用一样在自己的窗口中打开。
- **US-P2：** 作为用户，重复访问时应用外壳秒开，启动不等待网络。
- **US-P3：** 作为出行用户，我可以在离线时打开最近查看过的模板，在没有网络的情况下阅读和复制提示词文本。
- **US-P4：** 作为离线用户，我看到清晰的"您已离线"横幅和禁用的写操作，不会对能做什么感到困惑。
- **US-P5：** 作为用户，网络恢复时应用自动检测并清除离线状态，无需手动刷新即可恢复正常使用。
- **US-P6：** 作为移动用户，安装后的应用使用全屏（无浏览器边框）并跟随我的主题，感觉像原生应用。
- **US-P7：** 作为注重隐私的用户，我缓存的离线数据保留在设备上，登出时被清除，公用电脑是安全的。
- **US-P8：** 作为持有过期外壳的用户，我在下次启动时获得新版本（而非会话中途），更新绝不破坏正在运行的会话。

## 5. 功能需求

### 5.1 可安装性

- **FR-1：** Web 应用 manifest（`manifest.webmanifest`）：名称、短名称、图标（192/512 px，maskable）、`start_url: "/"`、`display: standalone`、`theme_color`/`background_color` 匹配 Aurora 亮色主题（暗色主题在运行时应用），两种语言由既有 i18n 运行时处理（manifest 本身与语言无关）。
- **FR-2：** 应用注册 service worker（仅生产构建；开发环境禁用），提供：应用外壳预缓存（HTML、JS、CSS 包、图标、字体）、模板详情数据的运行时缓存（最近 20 次查看）、离线路由加载时回退到缓存外壳的导航回退。
- **FR-3：** 不强制自定义安装提示：使用浏览器原生安装入口；应用额外在主页显示一次性可关闭的"安装应用"提示卡片（桌面：第 3 次会话后；移动：第 5 次后），文案按平台适配，状态存 `localStorage`。

### 5.2 离线阅读

- **FR-4：** 模板详情响应（`/templates/{id}` 的 API 载荷）在用户可见的已认证视图中运行时缓存；缓存持有最近 20 个模板（LRU 淘汰），总量上限 5 MB。
- **FR-5：** 离线时导航到已缓存模板可完整渲染（名称、分类、标签、提示词文本、版本列表），带"已缓存 — {时间}查看"徽章；复制提示词操作离线可用（剪贴板是本地能力）。
- **FR-6：** 离线时，未缓存的模板页显示友好的离线空状态（"该模板离线不可用"）并带重试按钮；列表/搜索页显示离线横幅和仅缓存外壳的内容。

### 5.3 离线状态处理

- **FR-7：** 全局连接状态指示：online 事件移除；offline 事件显示顶部细横幅"您已离线 —— 正在显示缓存内容"（头部之下、内容之上；出现时不引起布局偏移 —— 预留空间）。
- **FR-8：** 离线时所有写操作（创建/编辑模板、点赞、收藏、评论、API 密钥操作、资料修改）禁用并带 tooltip"离线不可用"；任何操作不静默排队或假装成功。
- **FR-9：** 重连时横幅清除、禁用操作自动恢复（无需刷新）；离线加载失败的页面提供"重试"按钮重新拉取。

### 5.4 更新流程

- **FR-10：** Service worker 更新采用"等待 + 下次加载激活"策略：新外壳在后台下载；运行中的会话保持旧外壳；出现小 toast"有可用更新 —— 重启以应用"，带"重启"按钮（刷新）和关闭。不会话中途切换。

### 5.5 缓存卫生与隐私

- **FR-11：** 登出清除所有缓存的模板数据（外壳除外）；缓存按浏览器配置隔离，绝不同步。
- **FR-12：** 仅缓存*用户有权查看的模板内容*（他人的私有模板因从未渲染而绝不缓存）；管理控制台页面绝不缓存（SW 缓存中无管理数据落盘）。

### 5.6 API

- **FR-13：** 无新增后端端点。Service worker 消费既有 API；缓存是客户端事务。（可选：收紧静态资产的 `Cache-Control` 响应头以支持长生命周期外壳缓存 —— 见开放问题。）

### 5.7 管理端

- **FR-14：** 管理控制台完全排除在离线缓存之外（FR-12）；离线使用 `/admin` 的管理员看到标准离线空状态。无管理端专属 PWA 行为。

## 6. 非功能需求

- **NFR-1（性能）：** 缓存外壳下重复访问外壳加载 < 1 秒（无网络）；通过 Lighthouse PWA 可安装性标准。
- **NFR-2（正确性）：** 离线体验绝不把过期数据当新鲜数据展示 —— 缓存视图带徽章（FR-5）；写操作离线时绝不显得成功。
- **NFR-3（隐私）：** 除已查看的模板详情外，无其他用户内容存储在客户端；登出清除（FR-11）；无管理数据缓存（FR-12）。
- **NFR-4（兼容性）：** 不支持 service worker 的浏览器降级为今天的行为且零报错；整个功能是渐进增强。
- **NFR-5（国际化）：** 所有横幅/提示/空状态文案通过 i18next（`offline.*`、`pwa.*` 命名空间）提供 EN/ZH。
- **NFR-6（无障碍）：** 离线横幅为 `role="status"`（礼貌播报一次，不刷屏）；禁用操作保持可聚焦并带说明 tooltip（不用 `display:none`）。
- **NFR-7（构建）：** Service worker 生成与既有 react-scripts 构建集成（CRA 内置 SW 支持的 Workbox 或等价插件 —— 见开放问题），开发与生产之间零配置漂移。

## 7. 验收标准

- **AC-1：** Lighthouse（或等价工具）报告应用可安装：manifest + 图标 + 已注册 SW + HTTPS（生产已满足）。
- **AC-2：** 在线访问一次后，断网并刷新应用，显示外壳（头部、导航、主页骨架）和离线横幅 —— 而非浏览器错误页。
- **AC-3：** 在线查看过的模板离线可打开，完整提示词文本和"已缓存"徽章；复制按钮离线可用。
- **AC-4：** 从未查看过（或超出 20 项 LRU）的模板显示离线空状态并带重试。
- **AC-5：** 离线时点赞/收藏/编辑/创建按钮禁用并带"离线不可用"tooltip；无一静默成功。
- **AC-6：** 重连后横幅消失、禁用按钮恢复，无需手动刷新。
- **AC-7：** 部署新版本后，下次访问显示"有可用更新"toast；运行中的会话在重启前不受影响。
- **AC-8：** 登出清除缓存的模板数据；随后的离线访问不显示任何用户内容。
- **AC-9：** 安装提示卡片按阈值（桌面第 3 次/移动第 5 次会话）出现一次，可关闭，关闭后不再出现。
- **AC-10：** `/admin` 页面离线绝不提供缓存数据；显示离线空状态。
- **AC-11：** 所有新文案 EN/ZH 翻译；离线横幅被屏幕阅读器礼貌播报。
- **AC-12：** 开发环境（`npm start`）无 service worker；行为与今天完全一致。

## 8. 范围之外

- 离线编辑或写排队/同步（冲突解决是独立的未来功能）。
- 推送通知（通知功能是应用内的；推送是未来扩展）。
- 显式"保存供离线使用"固定（自动最近 20 个缓存覆盖 v1）。
- 任何形式的后台同步。
- 原生应用商店打包（TWA/包装商店）。
- 任何形式的变现 —— 本产品永久排除。

## 9. 依赖与假设

- **D-1：** 生产环境通过 HTTPS 提供服务（已满足）—— service worker 需要安全上下文。
- **D-2：** 前端构建是 react-scripts 5（CRA），自带 Workbox service worker 支持（`serviceWorker.js` 注册模式）—— 实现可使用它或等价的 Workbox 配置；本设计与工具无关。
- **D-3：** 模板详情 API 响应是 JSON 且自包含，足以渲染详情页（当前行为）。
- **D-4：** i18n 运行时预先加载所有语言包（当前行为），因此缓存外壳可离线以任一语言渲染。
- **D-5：** 剪贴板 API 离线可用（浏览器能力）。
- **D-6：** 无障碍设计的焦点和 live-region 模式适用于新的横幅和禁用状态。

## 10. 给架构师的开放问题

1. **SW 工具：** 使用 CRA 内置 `serviceWorker.js`（Workbox 预缓存，不使用 `workbox-background-sync`），还是免 eject 的自定义 Workbox 配置在构建时注入？建议：若 CRA 内置支持模板详情 LRU 的运行时缓存则用之；否则用约 100 行的极简自定义 SW 配显式缓存策略。
2. **缓存版本化：** 外壳缓存按构建哈希版本化（自动）—— 请确认更新 toast 挂接 SW 的 `waiting` 事件，"重启"应在 `skipWaiting()` 后调用 `window.location.reload()` 还是直接刷新。
3. **感知认证的缓存：** 模板详情缓存仅按 URL 键控，还是加上用户 ID（同一浏览器配置上的两个用户）？建议：用户 ID + URL 键控；登出清除（FR-11）已基本解决，但键控更安全。
4. **API 缓存头：** 后端是否应为已认证 API 响应加 `Cache-Control: no-store`（使 SW 成为唯一缓存层），并为带哈希的静态资产加长生命周期不可变头？建议：是 —— 显式优于偶然。
5. **LRU 大小：** 20 个模板 / 5 MB —— 合理默认，还是架构师希望 v1 更小（如 10 个模板）？
6. **安装提示阈值：** 第 3 次会话（桌面）/ 第 5 次（移动）—— 请确认或简化为统一的第 3 次会话规则。
