# 用户仪表盘 — 需求分析

- **功能标识:** user-dashboard
- **版本:** 1.0
- **状态:** 已提案（待架构评审）
- **作者:** ui-ux-agent
- **日期:** 2025-06-25

## 1. 竞品研究摘要

| 平台 | 个人仪表盘方式 | 关键启示 |
|---|---|---|
| **PromptBase** | 卖家仪表盘：商品、销量、浏览、收入；账户设置独立 | 单一"我的内容"中心，分区块清晰；指标内联到每个条目 |
| **FlowGPT** | 主页兼作仪表盘：我的提示词、点赞、合集；内联编辑 | 主页即仪表盘，融合身份与内容管理 |
| **Snack Prompt** | 个人库：保存的提示词、创建的提示词、合集；标签页 | 标签式个人库是标准形态 |
| **AIPRM** | 按文件夹组织的个人列表库；每条提示词的使用统计 | 组织（文件夹）+ 单条统计 |
| **GitHub** | 仪表盘：总览卡片、活动流、仓库列表、快捷入口 | 总览优先加快捷操作；活动流驱动再参与 |
| **通用 SaaS（Vercel/Stripe）** | 左侧导航分区：总览、[实体] 列表、设置；最近活动面板 | 总览 + 实体列表 + 设置是经典信息架构 |

**综合结论:** 胜出模式是带以下要素的个人中心：(1) 总览区（计数 + 最近活动 + 快捷操作），(2) 标签页或路由式实体列表（我的模板、我的提示词、我的合集、我的点赞/收藏），(3) 设置独立。Open Prompts 的实体列表已散落各处（我的提示词 = 过滤后的首页视图；实例化提示词埋在模板详情里；API keys 在独立页面）；缺口是统一中心与总览。

## 2. 问题陈述

1. **没有个人主页。** 登录后用户落在公开广场。没有能回答"我最近做了/用了/存了什么？"的"我的工作区"。
2. **我的提示词是过滤器而非界面。** 侧栏的"我的提示词"是带 owner 过滤的首页网格 —— 没有所有者专属操作（内联编辑/删除）、没有模板类型区分（系统/用户）、没有统计。
3. **实例化提示词被埋没。** 提示词（填好变量的模板实例）只能在各模板详情页内看到。用户无法在一处看到"我创建的所有提示词"。
4. **没有总览。** 我的模板/提示词/合集/密钥计数与最近活动需要访问四个不同页面。
5. **缺少快捷操作。** 创建模板需要导航到广场的创建按钮；没有仪表盘级"新建模板" CTA。

## 3. 目标用户

- **普通用户（主要）:** 任何想要个人工作区总览与内容快速访问的登录用户。
- **创作者:** 管理大量模板、希望一目了然看到表现与管理入口的重度用户。
- **管理员:** 不受影响（管理员控制台独立；这是普通用户界面）。

## 4. 用户故事

### 4.1 总览

- **US-D1:** 作为用户，我希望在 `/dashboard` 有一个个人仪表盘，显示我的模板、提示词、合集和 API keys 计数，以便一目了然了解我的足迹。
- **US-D2:** 作为用户，我希望有最近活动列表（最新创建的模板、使用的提示词、点赞/收藏的模板），以便从上次中断处继续。
- **US-D3:** 作为用户，我希望有快捷操作（新建模板、新建 API key），以便常见任务一键可达。
- **US-D4:** 作为用户，我希望登录后落在仪表盘，以便从我的工作区开始，而不是公开广场。

### 4.2 我的内容管理

- **US-D5:** 作为创作者，我希望"我的模板"视图带所有者专属操作（编辑、删除、切换可见性），以便无需访问每个详情页即可管理模板。
- **US-D6:** 作为用户，我希望"我的提示词"视图列出我实例化的所有提示词（跨模板），以便 revisit/复用过去的工作。
- **US-D7:** 作为用户，我希望看到我的每个提示词来自哪个模板（带链接），以便导航到来源。
- **US-D8:** 作为用户，我希望从列表删除提示词，以便清理。
- **US-D9:** 作为用户，我希望仪表盘展示我的合集并带链接，以便所有内容从一处可达。

### 4.3 系统

- **US-D10:** 作为系统，我保持仪表盘完全限定所有者范围，以便绝不出现其他用户的数据。
- **US-D11:** 作为系统，我让仪表盘快速（并行聚合查询），以便感觉即时。

## 5. 功能需求

### 5.1 仪表盘总览（`/dashboard`）

- **FR-1:** 仪表盘应位于 `/dashboard`（需认证；匿名 → 登录重定向）。
- **FR-2:** 总览应显示四个统计卡片：我的模板（计数）、我的提示词（计数）、我的合集（计数）、API Keys（活跃计数）。
- **FR-3:** 总览应显示最近活动流（最多 10 条，最新在前），合并：我创建/更新的模板、我创建的提示词、我点赞/收藏的模板。每条：图标、文本、时间戳、实体链接。
- **FR-4:** 总览应显示快捷操作："新建模板"（打开既有创建流程）、"新建 API key"（链接到 /api-keys）。
- **FR-5:** 登录后重定向应落在 `/dashboard` 而非 `/`（既有会话不受影响；广场仍可从侧栏到达）。
- **FR-6:** 仪表盘应是侧栏的"我的工作区"导航项（顶部位置，登录用户在 Prompt Square 之上）。

### 5.2 我的模板标签页（`/dashboard/templates`）

- **FR-7:** 列出用户拥有的所有模板（公开 + 私有、所有类型），分页（20/页），按 updated_at 降序；列/卡片显示：标题、可见性徽章、类型徽章（系统/用户）、分类、标签（前 3）、点赞/收藏计数、更新日期。
- **FR-8:** 行/卡片操作：编辑（跳转模板详情编辑模式）、删除（确认弹窗；既有删除 API）、切换可见性（既有更新 API）。
- **FR-9:** 筛选 chips：全部 / 公开 / 私有 / 系统 / 用户类型；v1 客户端筛选可接受（页大小有界）。
- **FR-10:** 空状态："你还没有创建任何模板" + 创建 CTA。

### 5.3 我的提示词标签页（`/dashboard/prompts`）

- **FR-11:** 列出用户跨所有模板拥有的所有提示词（实例化），分页（20/页），按 created_at 降序；每行：变量摘要（前 2 个 key=value 对，截断）、来源模板标题（链接）、创建日期。
- **FR-12:** 行操作：查看（在弹窗中打开提示词内容 —— 变量渲染进模板内容）、删除（确认；既有删除 API）。
- **FR-13:** 按来源模板筛选（我使用过的模板下拉；v1 客户端可接受）。
- **FR-14:** 空状态："还没有提示词 —— 使用模板创建一个" + 广场 CTA。

### 5.4 我的合集与 API keys 入口

- **FR-15:** 仪表盘导航包含"我的合集"（链接到合集功能的 /collections/mine；若该功能未上线则隐藏入口）与"API Keys"（链接到既有 /api-keys）。
- **FR-16:** 总览统计卡片链接到各自的标签页/页面。

### 5.5 API

- **FR-17:** 新 RPC `GetDashboardOverview()` → `{template_count, prompt_count, collection_count, api_key_count, recent_activity: [{type, entity_id, entity_title, timestamp}]}`。REST：`GET /api/v1/dashboard/overview`。需认证。
- **FR-18:** 最近活动从既有表派生（templates.updated_at、prompts.created_at、template_likes/template_favorites.created_at）—— 无新事件表；UNION 查询 LIMIT 10。
- **FR-19:** 我的模板标签页复用 `ListTemplates`（`owner_id=me`，既有能力）；我的提示词标签页复用 `ListPrompts`（`owner_id=me`，既有能力）。
- **FR-20:** 提示词"查看"弹窗内容在客户端组装：获取模板最新版本内容（既有 GetTemplate）并替换变量（既有占位符逻辑）—— 无新 API。

### 5.6 普通用户与管理员划分

- **FR-21:** 仪表盘完全是普通用户界面。管理员用户同样看到自己的个人仪表盘（管理员控制台仍在 /admin 下独立）。
- **FR-22:** 本功能不涉及管理员 API 或页面。

## 6. 非功能需求

- **NFR-1（性能）:** 总览端点 p95 < 400ms（四个 COUNT 查询 + 一个 UNION LIMIT 10，全部有索引）。
- **NFR-2（兼容性）:** 无破坏性变更；新路由 + 一个新的只读端点；既有页面不变。
- **NFR-3（隐私）:** 所有仪表盘数据限定所有者；无跨用户数据；无新 PII。
- **NFR-4（无障碍）:** 统计卡片、标签页、表格与弹窗可键盘操作；活动流是语义列表（见 UI/UX 文档 §10）。
- **NFR-5（国际化）:** 所有新增字符串 EN/ZH 同步；时间戳 locale 格式化；相对时间（"2小时前"）通过共享工具。
- **NFR-6（弹性）:** 若合集功能缺失，仪表盘优雅降级（隐藏合集卡片/导航；总览端点返回 collection_count: 0 或省略）。
- **NFR-7（安全）:** 总览端点需要认证；所有查询按 token 中的认证用户 id 限定（绝不来自客户端参数）。

## 7. 验收标准

- **AC-1:** 登录后用户落在 `/dashboard` 并看到四个计数正确的统计卡片。
- **AC-2:** 最近活动流显示最多 10 条，图标、链接与相对时间戳正确。
- **AC-3:** 快捷操作可用："新建模板"打开创建流程；"新建 API key"导航到 /api-keys。
- **AC-4:** 我的模板列出所有拥有的模板，编辑/删除/切换可见性操作与筛选可用。
- **AC-5:** 我的提示词列出实例化提示词并带来源模板链接；查看弹窗渲染替换后的内容；删除可用。
- **AC-6:** 匿名访问任何 /dashboard/* 路由重定向到登录。
- **AC-7:** 仪表盘不显示任何其他用户的数据。
- **AC-8:** 合集功能未上线时，仪表盘隐藏合集 UI 且无错误。
- **AC-9:** 统计卡片导航到各自标签页/页面。
- **AC-10:** 所有新增 UI 字符串在 `en` 与 `zh` 翻译文件中存在且键集一致。
- **AC-11:** 既有首页/广场、模板详情、个人资料与 API keys 页面行为不变（无回归）。
- **AC-12:** 1k 模板/提示词规模下总览端点 p95 < 400ms（有索引查询）。

## 8. 范围外（v1）

- 仪表盘自定义/重排。
- 通知中心（尚无通知系统）。
- 仪表盘上的创作者分析（属于 prompt-analytics 功能；上线后可加链接）。
- 批量操作（多选删除）。
- 仪表盘列表内搜索。
- 活动流分页（仅前 10 条）。
- 上手清单（"完善你的资料"）—— 未来参与功能。
- 邮件摘要。
- 移动应用专属布局（仅响应式 Web）。

## 9. 依赖与假设

- **D-1:** 带 `owner_id` 过滤的 `ListTemplates` 与 `ListPrompts` 已存在且返回足够字段（proto/service 已确认）；标签页无需后端列表变更。
- **D-2:** 最近活动 UNION（FR-18）要求 `template_likes`/`template_favorites` 有 `created_at`（schema 已确认）；模板活动用 `updated_at` 作为"创建/更新"的代理（v1 不区分）。
- **D-3:** 合集功能（template-collections）可能尚未上线；仪表盘必须做特性检测（NFR-6）。检测方式：合集 API 的存在性（端点 404 则隐藏 UI）或构建时开关 —— 架构师/开发者选择。
- **D-4:** 登录后重定向（FR-5）将登录成功处理器的目标从 `/` 改为 `/dashboard`；匿名访客仍默认到广场。
- **D-5:** 提示词查看弹窗（FR-20）复用模板使用流程中既有的占位符替换逻辑（frontend/src/pages/TemplateDetails.js）—— 若尚未抽取则提取为共享工具。
- **D-6:** 相对时间格式化工具是新增但很简单（分钟/小时/天）；在仪表盘与未来功能间共享。
- **D-7:** 侧栏新增"我的工作区"入口；既有入口（Prompt Square、我的提示词、我的点赞、我的收藏）保留 —— "我的提示词"侧栏入口后续可指向仪表盘标签页（v1 两者都保留；去重是后续工作）。
- **D-8:** 统计卡片计数用精确 COUNT 查询；当前规模无需缓存。
