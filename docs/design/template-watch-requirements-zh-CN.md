# 模板关注（Watch）— 需求分析

- **功能 ID：** template-watch
- **版本：** 1.0
- **状态：** Proposed（待架构评审）
- **作者：** ui-ux-agent
- **日期：** 2026-10-13
- **配套文档：** `template-watch-ui-ux-design-zh-CN.md`

## 1. 竞品调研摘要

| 产品 | 关注/订阅模式 | 启示 |
|---|---|---|
| **GitHub** | 仓库上的 "Watch"：全部活动 / 仅发布 / 忽略；关注者收到 issue/PR/release 通知；关注数仅仓库所有者可见 | Watch 是"关注人"在制品层面的补充；粒度分级可控制噪音 |
| **YouTube** | 订阅频道；每个视频的铃铛（全部 / 个性化 / 无） | 铃铛的按条目粒度是解决"过度订阅"的答案 |
| **Medium** | 关注作者；对单篇文章订阅评论邮件 | 订阅单篇文章以跟进后续讨论是独立且常见的需求 |
| **Reddit** | "Follow post" 将帖子收进个人流并显示新评论徽标 | 关注帖子 ≠ 收藏：用户要的是*未来变化*，不只是一个链接 |
| **npm** | "Watch package" 获取新版本通知；每个包有 RSS | 发布关注是与"模板版本更新"最贴切的类比 |
| **PromptBase / FlowGPT / Snack Prompt** | 均无制品级订阅 | 差异化机会；也说明该模式并非用户预期基线 |

**综合结论：** v1 的制胜模式是 **npm/GitHub 混合**：公开模板详情页上的单一 **Watch（关注）** 开关（v1 不做粒度分级 —— 只有一档，"有新版本就通知我"）、一张 `template_watchers` 表、被关注模板发布新版本时触发的 `template_version_published` 通知事件、用户仪表盘中的 **Watched（已关注）** 列表（带未读更新徽标）、以及详情页上给回访关注者的 **"N 个更新"** 横幅。关注与收藏（bookmark/点赞性质）和 follow（人层面）刻意分离：用户关注一个模板，是因为*这个具体的提示词*对他们的工作重要，他们想知道它何时变化。follow-creators 设计明确将 "Watch template" 推迟为未来功能 —— 本功能即那个功能。

## 2. 问题陈述

1. **模板静默变化。** 创作者发布了消费者每天依赖的提示词的 v5；消费者永远不会知道上周复制走的提示词被修复或改进了。没有制品级订阅。
2. **收藏是错误的工具。** 用户收藏模板是为了 bookmark；收藏在模板更新时不产生任何信号。没有办法表达"*这个*变了就告诉我"。
3. **Follow 太宽。** 关注创作者会通知其*所有*新模板（通过 Following 流）；只关心某一个提示词的用户得到的是噪音。
4. **回访关注者什么也看不到。** 即使用户手动重访模板，也得不到"自上次查看以来已更新"的任何提示 —— 没有更新徽标，没有版本差异提示。

## 3. 目标用户

- **依赖特定提示词的消费者：** 某个模板的日常使用者，想知道它何时改进或失效。
- **Fork 用户：** fork 过模板、想跟踪上游变化以择优合并改进的用户。
- **创作者（次要）：** 通过关注数（仅所有者可见）了解自己哪些作品最受重视。

## 4. 用户故事

- **US-W1:** 作为消费者，我可以在公开模板上点击"关注"，以便在新版本发布时收到通知。
- **US-W2:** 作为消费者，我可以随时在详情页或已关注列表中取消关注，以便控制噪音。
- **US-W3:** 作为消费者，被关注模板发布版本时，我在现有通知中心看到"新版本"通知，以便在我常看的地方获知更新。
- **US-W4:** 作为消费者，我在仪表盘中有"已关注"列表，展示所有被关注模板及未读更新徽标，以便在一处分流更新。
- **US-W5:** 作为回访关注者，我在模板详情页看到"自你上次查看已更新 —— v4 → v6"横幅，以便立即知道发生了什么变化。
- **US-W6:** 作为关注者，我可以从通知/横幅跳转到版本对比，以便几秒内评估变化。
- **US-W7:** 作为创作者，我可以看到有多少用户关注我的模板（仅所有者），以便了解哪些作品对人最重要。
- **US-W8:** 作为用户，自己的模板不可关注（我自己写的，我知道它何时变），以便绝不自我通知。
- **US-W9:** 作为用户，只能关注公开模板，以便关注行为不会泄露私有内容的存在。

## 5. 功能需求

### 5.1 关注动作

- **FR-1:** 任何已认证用户可通过模板详情页的 Watch 开关关注任何**非自己所有的公开**模板。关注私有模板、他人的私有模板或已归档模板，按现有可见性语义返回 404/403；关注自己的模板返回 400 及明确提示。
- **FR-2:** 新表 `template_watchers`：`id UUID PK`、`user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE`、`template_id UUID NOT NULL REFERENCES templates(id) ON DELETE CASCADE`、`created_at TIMESTAMPTZ NOT NULL DEFAULT now()`、`last_viewed_version INT NOT NULL DEFAULT <关注时的当前版本>`、`last_notified_version INT NOT NULL DEFAULT <关注时的当前版本>`、`UNIQUE(user_id, template_id)`。取消关注后再次关注会重新插入并重置默认值。
- **FR-3:** `POST /api/v1/templates/{id}/watch`（关注）与 `DELETE /api/v1/templates/{id}/watch`（取消关注）。二者幂等（重复关注返回 200 无操作；未关注时取消返回 200 无操作）。需认证；匿名 401。
- **FR-4:** 模板被归档、硬删除或被所有者设为私有时，现有关注记录**保留但休眠**：模板非公开可见期间不发出通知。模板重新公开后，关注自动恢复。（记录仅在显式取消关注或用户/模板删除时移除。）

### 5.2 版本更新事件

- **FR-5:** 当 `UpdateTemplate` 为模板创建新版本（内容变化，现有行为）时，系统应向该模板的每个活跃关注者发出 `template_version_published` 通知，但以下除外：模板所有者（自己的模板永不通知）、被封禁用户（按现有语义不通知）、以及 `last_notified_version >= 新版本` 的关注者（去重）。
- **FR-6:** 通知载荷应包含：模板 id、模板标题、前一版本号、新版本号、变更说明（若 template-versioning 的 `change_note` 存在；否则为空字符串）。通知链接到模板详情页并预开版本对比（`/templates/{id}?diff={prev}..{new}`）。
- **FR-7:** 发出为尽力而为，条件允许时与版本插入同事务；失败时版本仍创建（漏一条通知可接受，丢一个版本不可接受）。每次发布优先单条批量插入而非 N 条单独插入。
- **FR-8:** 该事件类型以数据驱动方式接入现有通知系统与 notification-preferences 面板（`template_version_published`），默认**开启**，可按现有偏好机制在发出时抑制。mention-notifications 设计已确立此数据驱动模式；偏好 schema 无需变更。
- **FR-9:** 频率安全：模板在短窗口内发布多个版本（如连续编辑会话）时，每个模板每关注者每 **1 小时**最多发出一条通知（最新版本胜出，中间版本折叠 —— 一条通知显示 "v3 → v7"）。防止快速保存工作流造成通知风暴。

### 5.3 已关注列表（仪表盘）

- **FR-10:** 用户仪表盘新增 **Watched（已关注）** 标签页（`/dashboard/watched`），列出被关注模板（复用现有模板列表项结构，`PromptCard` 无需改动），排序为**最近更新优先**（当前版本 > `last_viewed_version` 的模板置顶并带未读徽标），其次按关注时间倒序。
- **FR-11:** 每行/卡片展示：现有模板卡片内容、当 `current_version > last_viewed_version` 时的**未读徽标**（"2 个新版本"）、**Watch 开关**（快速取消）、关注日期。
- **FR-12:** 打开被关注模板的详情页时，`last_viewed_version` 更新为当前版本（页面加载时通过现有 `GET /api/v1/templates/{id}` 响应处理在服务端完成 —— 一个轻量 `PUT /api/v1/templates/{id}/watch/viewed` 信标，fire-and-forget），清除未读徽标。
- **FR-13:** `GET /api/v1/users/me/watched?page=&page_size=` → `{templates: [<现有列表项结构> + `new_versions: int`、`watched_at`>], total, page, page_size}`。仅限本人；分页（默认 20，最大 50）。

### 5.4 回访关注者横幅

- **FR-14:** 已登录关注者查看当前版本 > 其 `last_viewed_version` 的模板时，详情页显示可关闭横幅："自你上次查看已更新 —— v4 → v6 · [查看变化]"。点击"查看变化"打开 template-versioning 的 DiffModal（v4→v6）。横幅出现同时触发 FR-12 的已查看信标。
- **FR-15:** 横幅对非关注者、匿名用户、所有者、无新版本的关注者隐藏。

### 5.5 所有者指标

- **FR-16:** 模板详情响应（`GET /api/v1/templates/{id}`）仅在**所有者视角响应**中包含 `watcher_count`（沿用 template-health-hints FR-15 的所有者视图增强模式）；公开响应绝不包含。所有者仪表盘"我的模板"可将该数作为一列展示（v1 可选，UI 层面）。

## 6. 非功能需求

- **NFR-1（性能）：** 关注/取消关注为单行 upsert/delete（典型 < 10ms）。发布时扇出为每次发布一条批量插入；关注者超过 10,000 的模板按 `created_at` 取前 10,000 封顶（已文档化；提示词平台极少接近此量级）。
- **NFR-2（隐私）：** 关注者列表绝不公开（v1 无"谁在关注此模板"界面）；仅展示聚合数，且仅所有者可见。关注行为不出现在个人主页。
- **NFR-3（一致性）：** 发布竞态期间取消关注可能产生一条过期通知；可接受（已文档化）。恢复（restore）不单独发通知 —— template-versioning 的恢复会创建新版本，它本身就是一次版本发布，正常通知。
- **NFR-4（国际化）：** 所有 UI 文案 EN/ZH 双语；通知标题/正文按现有通知渲染机制本地化。
- **NFR-5（兼容性）：** 不改变收藏、follow、点赞语义；Watch 按钮是独立控件，使用自己的图标（眼睛），避免与星星（收藏）混淆。

## 7. 验收标准

- **AC-1:** 已认证用户打开非自己的公开模板 → Watch 按钮可见 → 点击 → 按钮变为"已关注"（实心眼睛）；notification-preferences 出现新的 `template_version_published` 开关（默认开）。
- **AC-2:** 所有者发布新版本（内容变化）→ 每个合格关注者收到恰好一条 `template_version_published` 通知，含前后版本号与变更说明；所有者本人不收到任何通知。
- **AC-3:** 关注者打开模板详情页 → 显示"自你上次查看已更新 —— v4 → v6"横幅 → 点击"查看变化"打开 v4→v6 对比 → 下次访问仪表盘时横幅与未读徽标清除。
- **AC-4:** 快速发布（10 分钟内 5 个版本）→ 关注者每模板每小时最多收到一条通知，显示折叠区间（v3 → v8）。
- **AC-5:** Watched 标签页列出被关注模板，未读徽标按最近更新优先排序；从列表取消关注后该行移除且无需刷新页面。
- **AC-6:** 关注私有模板（非所有者）→ 404；关注自己的模板 → 400 及提示；未关注时取消关注 → 200 无操作。
- **AC-7:** 所有者将模板设为私有 → 关注者不再收到通知；所有者重新公开 → 下一个版本再次通知关注者。
- **AC-8:** 模板所有者在详情页看到 `watcher_count`；非所有者视角的响应不含该字段。
- **AC-9:** 在通知偏好中关闭 `template_version_published` → 后续发布不创建通知行（发出时抑制，与 notification-preferences 一致）。
- **AC-10:** 硬删除被关注模板 → 关注记录级联移除，Watched 标签页不再列出。

## 8. 不在范围内（v1）

- 关注粒度分级（GitHub 式"仅发布 / 全部活动 / 忽略"）—— 只有一档。
- 关注者列表（谁在关注此模板）—— 仅聚合数，仅所有者可见。
- 邮件/推送渠道 —— 仅应用内（与产品通知基础设施一致）。
- 关注模板的评论或 fork —— 仅版本更新。
- "关注合集"/"关注链" —— 仅模板；其他实体类型视需求再议。
- 任何形式的变现 —— 本产品永久不做。

## 9. 依赖与假设

- **D-1:** 通知系统（已上线）与 notification-preferences（已设计）提供事件类型注册、未读徽标、历史页与发出时抑制；本功能只新增一个类型。
- **D-2:** template-versioning 提供版本号、DiffModal 与 `change_note`；横幅深链到该弹窗。
- **D-3:** `UpdateTemplate` 在内容变化时创建新版本是现有后端行为；发出钩子挂在该代码路径（与 webhooks 处理生命周期事件的模式相同）。
- **D-4:** 用户仪表盘（已设计）提供标签式中心；Watched 是与"我的模板 / 我的提示词 / 我的合集"并列的新标签页。
- **D-5:** follow-creators 的"不在范围内"一节明确将 "Watch template" 留给本功能；与 Following 流（人层面、最新模板）无重叠。
- **D-6:** 假设：`PromptCard` 与模板列表项结构足够稳定，可扩展两个可选字段（`new_versions`、`watched_at`）。

## 10. 给架构师的开放问题

1. **扇出机制：** 发布时批量插入 `notifications`（对 `template_watchers` 做一条 INSERT ... SELECT）vs. 在 goroutine 中逐关注者插入 —— 哪种更契合现有 `createEngagementNotification` 模式？推荐批量。
2. **折叠窗口实现：** 1 小时折叠（FR-9）需要按（关注者, 模板）记录"上次发出时间" —— 复用 `last_notified_version` 加一列 `last_notified_at`，还是发出时查询近期通知？推荐加列（多一列，免发出时查询）。
3. **已查看信标：** fire-and-forget 的 `PUT .../watch/viewed` 是否可接受，还是让 `GET /api/v1/templates/{id}` 在调用者是关注者时服务端顺带更新（少一次请求，但读路径中含写）？推荐信标（保持 GET 纯净）。
4. **关注者上限：** 10,000 关注者上限（NFR-1）是否值得 v1 实现，还是等数据说话再议？推荐推迟并留 TODO 文档。
5. **恢复语义确认：** template-versioning 的恢复会创建新版本 —— 请确认它流经同一发布钩子（假设是，D-3）。
